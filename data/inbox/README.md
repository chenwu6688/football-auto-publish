# data/inbox —— 导出文件投递箱

把头条后台下载的文件**直接丢进这个目录**，`scripts/ingest_exports.py` 会自动识别并入库
（R11 建议7：绩效回填自动化）。处理完文件会被移到 `data/processed/<日期>/`。

支持的文件（`.xlsx / .csv / .tsv`）：

| 后台位置 | 用来做什么 | 去向 |
| --- | --- | --- |
| 数据 → 作品数据 → 单篇 → 右上角「⬇ 下载Excel」 | 单篇阅读/点赞/点击率/完读率/涨粉（若导出含该列） | `output/performance_log.json` + 回写各日 `metadata.json` |
| 数据 → 粉丝数据 → 页面导出按钮 | 日涨粉 / 粉丝总数（转粉通道，唯一来源） | `data/growth/fans_daily.json` |

> 2026-10-14 实测备注：作品数据页**没有**时间范围选择器，「下载Excel」导的是全量作品
> 快照（按篇目逐行），投进来即可；粉丝数据页主内容区加载较慢，导出前多等几秒。
> 作品数据页注明「每日 14:00 更新前一日数据」——collector 06:00 导到的前一天是未结算
> 值，次日 06:00 的导出会自动覆盖为结算值（按日 upsert 自愈）。
>
> 2026-10-14 四次实测（collector 自动投递）：点「开始下载」后仍 120s 等不到下载事件，
> 脚本已改为在确认框里**显式填写日期范围**（近 7 天，三级手段 fill→JS 注入→日历点选，
> 读回值留证）并采集点击后现场证据（新标签页/导出类响应/toast）——手动投递时若确认框
> 日期是空的，也请先把起止日期填上再点「开始下载」。

## 多久投递一次：默认全自动，手动是兜底

**collector 每天 06:00 CST 自动投递**（`scripts/collect_toutiao_exports.py` +
`.github/workflows/toutiao-collector.yml`）：自动登录头条后台，把「作品数据」「粉丝分析」
两页各导出**前一天**一整天落进本目录，每次运行都发 WxPusher 回执。之后 09:10 的
perf-ingest 自动识别/幂等/入库。**你不需要做任何操作。**

手动投递通道**永远保留**（自动化是增量不是替换）：收到 collector 失败告警
（登录过期/页面改版）时，登录后台 → 导这两个文件 → 丢进本目录即可，CI 每天 09:10
照样消费。手动导出时的两个实操点（2026-10-14 实测）：

- **作品数据**：进「数据 → 作品数据 → 单篇」页，点右上角「**下载Excel**」会弹确认框
  （发布时间范围 + 作品总数），**必须再点「开始下载」**才真正出文件；范围用默认的
  近 7 天即可（必含前一天），不必改日期（collector 现在会显式填上这 7 天）；
- **粉丝数据**：从左侧导航点「粉丝数据」进去（直接输网址会白屏），页面加载较慢，
  等图表出来再找导出按钮。

## 用法

```bash
# 手动兜底：一条命令跑完（收文件 → 入库 → 滞后监控 → 看板 → 调参建议 → 汇总报告）
python3 scripts/weekly_review.py --from ~/下载 --commit

# 只想消费箱里已有的文件
python3 scripts/weekly_review.py

# 本机手动跑一次（只入库，不做后面几步）
python3 scripts/ingest_exports.py

# 定时任务（CI）：collector 每天 06:00 投递 + perf-ingest 每天 09:10 消费
```

## 纪律

- 识别不出类型 → **原样留在 inbox** 并报 `unknown`，不猜、不导入；
- 导入失败 → 留在 inbox 并记 `failed`，下次投递自动重试；
- 同一文件（按 sha256）重复投递 → 跳过（幂等），不会重复回填；
- collector 落盘文件名带统计日期（如 `作品数据_2026-10-13.xlsx`），箱内一眼可辨；
- 绩效台账按 (date, slug) upsert——每天导入前一天快照不重复计数；
- 幂等台账：`data/ingest_state.json`（含最近 60 次投递历史）。

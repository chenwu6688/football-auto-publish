## 0. 一页结论

**筛选了 13 个项目，只有 5 个真正值得接。** 其余 8 个要么热度高但解决的不是我们的问题
（`awesome-chatgpt-prompts-zh` 64k star，是提示词大杂烩），要么已经停更到不能依赖
（`DailyHotApi` 8 个月无提交、`icrawler` 11 个月无提交）。

| 类别 | 主推 | 星数 | 最后提交 | 许可证 | 解决的缺口 |
|---|---|---|---|---|---|
| 选题 | **RSSHub** | 46.8k | 2026-11-04 | AGPL-3.0 | 被 EdgeOne 拦 → 改订阅 RSS |
| 选题 | TrendRadar | 63.4k | 2026-10-29 | GPL-3.0 | 社媒讨论量恒为 0 |
| 配图 | **satori** | 14.2k | 2026-10-23 | MPL-2.0 | 35% 无封面 → 用数据卡兜底 |
| 写作 | **Humanizer-zh** | 21.9k | 2026-09-23 | MIT | 兜底话术 / AI 味 |
| 写作 | **中文文案排版指北** | 15.8k | 2026-10-12 | MIT | `0-1` vs `0比1` 口径 |

**最重要的一条判断**：这三类项目里，**没有一个是「提高阅读量」的**。它们分别解决
「不漏题」「有图」「不像 AI 写的」。真正决定阅读量的还是那个 0.89% 的 CTR——
这些工具最多把**执行成本**降下来，把**质量下限**抬上去。

## 1. 头部账号的三类共性（先有靶子再筛项目）

### 1.1 选题：全部是「已发生 + 可量化 + 有专名」

五个号里没有一篇是「前瞻型空谈」。`英超那些事` 14 条样本 **100% 带数字**，
`我爱英超` 84 条 **96% 带数字**。金球奖那一夜 `我爱英超` 发了 15 条，是同一事实的 15 个切面
（得票数/历届对比/年龄纪录/队友反应/落选者），不是 15 个不同事件。

> 对我们的含义：选题能力 = **事实的密度 × 切面的数量**，不是「想到一个好点子」。
> 我们现在有 `season_calendar`（节点）+ `event_cluster`（六角度），缺的是**当天到底发生了什么**
> 的一手密度——而这恰好是热榜/订阅源能补的。

### 1.2 视觉：头部图文是「一图一短标题」的信息流单位

必须诚实说明：**对标抓的是主页文本，没有封面字段，所以我拿不到头部账号的封面率**。
能确认的只有我们自己的分层实测——无封面 n=50 聚合 CTR **0.52%**、有封面 n=26 **2.07%**，
差 4 倍；12 篇零阅读里 11 篇无封面。

在这条上，头部账号的共同点是**没有一个靠「纯文字卡片」在信息流里竞争**：
`英超那些事` 标题平均 12 字，图承担了几乎全部视觉识别。这反过来解释了为什么它能用
12 字标题还拿到中位 5,526——**短标题的前提是有图**，没图还写 12 字等于放弃信息流。

### 1.3 写作：短段落流 + 感叹号收束 + 零 CTA

`英超那些事` 实测：正文 **312 字 / 4.6 段 / 段均 70 字**，**0 个列表、0 处引语、0 个小标题**，
段与段之间纯靠空行。**96% 的文章没有任何关注/点赞引导**，100% 结尾挂话题标签（平均 2.2 个）。

| 指标 | 头部（英超那些事 / 我爱英超） | 我方 88 篇 |
|---|---|---|
| 标题感叹号 | 95% / 82% | **1.2%（1 篇）** |
| 标题问号 | 5% / 20% | **81%** |
| 标题均长 | 12 字 / 33 字 | 25 字 |
| 正文字数 | 312 字 | 规格 600-800 字（`prompts/rewrite_article.txt:32`） |
| 列表 / 引语 / 小标题 | 0 / 0 / 0 | **无法复算**（见下） |
| 话题标签 | 100%，均 2.2 个 | **0** |
| 关注引导 | **96% 不做** | 近乎 100%（兜底话术累计强插 249 次） |

> **顺带发现一个可观测性缺口**：我方正文 .md 只存在于 CI 临时目录
> （`/home/runner/work/_temp/...`），仓库里只有 `metadata.json`。所以上表右侧
> 「正文字数/段落/列表/引语」这四行**算不出来**——不是没改，是没留证。
> 这和「37% 无封面黑了很久」同源：**只有结论落库，过程没落库**。
> 若要评估「压字数到 300-500」这条建议，第一步是把正文摘要指标写进 metadata，
> 而不是先改 prompt。

## 2. 筛选维度与打分规则

### 2.1 检索方式

按三类各定义检索词，用 GitHub Search API 按 star 排序取前 3-4，再逐个读 README 核实：

| 类别 | 检索词 |
|---|---|
| 选题 | `TrendRadar` `newsnow` `DailyHotApi` `RSSHub` `hot search` `热榜` |
| 配图 | `satori` `og-image` `html2image` `Pillow` `rembg` `icrawler` `gallery-dl` |
| 写作 | `humanizer` `chinese-copywriting-guidelines` `LangGPT` `awesome-chatgpt-prompts` |

### 2.2 五个维度与权重

| 维度 | 权重 | 判据 |
|---|---|---|
| **功能适配度** | 40 | 是否直接解决本文第 1 节列出的**已量化缺口**，而不是泛泛「可能有帮助」 |
| **维护活跃度** | 25 | 90 天内有提交=活跃（可依赖）；90-180 天=观察（可借鉴）；>180 天=只用思路不引依赖 |
| **项目热度** | 20 | stars ≥400 为入围门槛，≥5k 加分（热度只代表「被验证过」，不代表适配） |
| **接入成本** | 10 | 纯 Python/Node 可跑、无 GPU、不需要登录态/浏览器指纹 |
| **许可证** | 5 | **本仓库是 public 且无 LICENSE**，因此 GPL/AGPL 代码不能 vendor（见 §6.1） |

### 2.3 明确排除的三类

- **需要逆向签名或登录态**（会重蹈 MediaCrawler 的评估结论：绕过技术保护措施，法律定性不同）
- **需要 GPU / 大模型本地推理**（我们没有算力预算）
- **纯提示词清单**（不可验收，无法进闸门）

## 3. 选题技巧类

### 3.1 RSSHub —— ⭐46,803 / 2026-11-04 / AGPL-3.0 / TypeScript · **评分 92**

**简介**：`Everything is RSSible`。把没有 RSS 的站点（含头条号、微博、公众号、B 站、
YouTube 等数千条路由）转成标准 RSS 输出，可自建、可 Docker 部署。

**核心功能**
- 数千条「路由」把站点页面转成统一 XML（标题/时间/正文摘要/封面链接）
- 支持参数化过滤（关键词、条数、全文输出）
- 自建实例可绕开公共实例的限流；输出是纯 XML，**不执行平台 JS、不需要登录态**

**对应头部哪个特点**：头部账号的选题密度来自「知道当天发生了什么」（`我爱英超` 金球奖 15 条）。
我们现在的 `media_scraper.py` 直连站点，被懂球帝的 EdgeOne 返 HTTP 567 挑战页拦掉，
只能 `return ""`（11-03 才改成显式分类）。**RSS 拿的是 XML，不经过反爬挑战层**，
这是绕开「渲染+风控」两件事的最低成本方式。

**接入点**：`source_watch.py` 增加 rss 源类型；`media_scraper` 新增 `_fetch_rss()`，
复用已落地的 `scraper_diagnostics` 七类分类（RSS 也要区分「源没更新」和「源挂了」）。

**适用条件与风险**：只消费 XML 输出，**不把路由代码复制进本仓库**（AGPL-3.0）。
公共实例有速率限制，产量大要自建；头条号路由依赖平台页面结构，平台改版会短暂失效。

### 3.2 TrendRadar —— ⭐63,405 / 2026-10-29 / GPL-3.0 / Python · **评分 90**

**简介**：30 秒部署的多平台热点聚合 + AI 筛选推送工具，当前 v6.11.0，另有 MCP 服务（v4.1.1）。

**核心功能**
- 聚合 35+ 平台热榜（今日头条、百度、微博、抖音、知乎、B 站等），记录**排名随时间的变化**
- 关键词/正则筛选 + 静默时段 + 增量推送（飞书/钉钉/企微/个人微信/TG/Bark/邮件/Webhook）
- AI 筛选与多语言翻译；支持 GitHub Actions / Docker / Cloudflare Pages 部署
- RSS 订阅源支持

**对应头部哪个特点**：它解决的是「**不漏**」。我们 `data/signals/external_signals.json` 里
71 个实体的「社媒讨论量」**全部为 0**、「搜索指数」71 个有值但 **69 个都是 100**（完全饱和），
等于信号层是死的。`ranker._SOCIAL_FAME_BANDS` 给社媒热度只加 **+1 分（满分 25）**，
本来就没权重——若接入，要先决定「值不值得给权重」，而不是先接。

**接入点**：**只读它输出的 JSON/网页**，写进 `signal_sources` 的「社媒讨论量」字段；
不改 `ranker` 权重（当前 +1 分封顶，接了也不会改变排序）。

**适用条件与风险**：GPL-3.0，同样不 vendor。最大风险不是技术，是**同质化**——
所有自媒体都在看同一个热榜，热榜选题恰恰是竞争最激烈的那批。
头部账号的差异不在「知道金球奖」，在「金球奖当天给出 15 个切面」。
所以它和 `event_cluster` 是**互补**：热榜管「不漏」，切面池管「不同」。

### 3.3 newsnow —— ⭐22,278 / 2026-10-13 / MIT / TypeScript · **评分 78**

**简介**：`Elegant reading of real-time and hottest news`。实时热榜阅读器，
默认 30 分钟缓存、自适应抓取间隔（最小 2 分钟），支持 GitHub OAuth 同步与 MCP。

**核心功能**：多平台热榜聚合 Web UI；可 Fork 后免费部署到 Cloudflare Pages / Vercel；

先证伪再投入。README 已公告 NewsNext 下一代即将发布，接口可能变动，别写死。

**接入点**：作为 TrendRadar 的**替代试验品**，二选一，不要同时接两个聚合器。

## 4. 配图工具类

### 4.1 satori —— ⭐14,159 / 2026-10-23 / MPL-2.0 / TypeScript · **评分 93**

**简介**：Vercel 出的 HTML/CSS → SVG 渲染器，专为 OG 图/社交卡片设计，无浏览器依赖。

**核心功能**：把 JSX/HTML 片段按 flexbox 布局渲染成 SVG；输出可直接转 PNG；
纯计算、无 Chromium，速度快、可在 Serverless 跑。

**对应头部哪个特点**：**这是对「35% 无封面」最对症的一个**。我们 11-01 修封面链路时
定了「找不到实体图就不配图」——方向对（不用占位图），但结果是**宁可空着**。
satori 提供第三条路：**用数据卡封面兜底**——比分 + 双方队名 + 一句判断，
版式由设计定死，零外部图源、零版权风险。头部账号的短标题依赖「有图」，
数据卡等于把「图」变成可无限量生产的确定性产物。

**接入点**：`data_collector.search_images` 之后加一层 `build_cover_card(facts) -> png`，
仅当实体图缺失时触发；产物走现有 `cover_binding` 的尺寸闸门（≥800×600）。

**适用条件与风险**（三个必须提前知道的坑）
1. **字体必须显式传入**：「Only the fonts passed in the `fonts` option are used」——
   CJK 要自带 Noto Sans SC 之类的字体文件（几 MB），**建议先做字体子集化**，否则仓库体积暴涨。
2. **CSS 只支持 flexbox 子集，不支持 grid**，复杂版式会被静默降级。
3. 输出是 SVG，**还要一个 SVG→PNG 的转换**（sharp / resvg），多一个 Node 依赖。
   若不想引 Node，可以用 `html2image`（见 4.4），但那个要 headless 浏览器。

### 4.2 Pillow —— ⭐13,966 / 2026-11-04 / PIL-CMU-MIT · **评分 80（已在用）**

**简介**：Python 图像处理事实标准。我们保存侧的「尺寸闸门 ≥800×600」就是它做的。

**核心功能**：缩放/裁剪/合成/文字绘制/EXIF 读取/格式转换。

**对应头部特点 / 增量价值**：不需要新引入，只需要**扩展用途**——
把 satori 产出的数据卡 PNG 做二次合成（叠球队色条、压角标、统一 1200×675 比例），
以及在保存侧加一条「文字压图的安全区检查」（标题文字不能被平台裁掉）。
风险低，属于「已经付过成本的资产再挖一遍」。

### 4.3 rembg —— ⭐25,325 / 2026-11-02 / MIT / Python · **评分 72（观察）**

**简介**：一键抠图（去背景），基于 U²-Net 系列模型，CPU 可跑。

**核心功能**：`remove(input) -> 透明底 PNG`；支持批量、alpha matting 细化边缘。

**对应头部特点**：球员透明底 + 渐变背景 = 体育号最常见的封面版式。
但它是**锦上添花而非雪中送炭**：我们现在的瓶颈是 65% 的稿子根本没图，
不是「图不够精致」。抠图的前提是**先有一张可用原图**，而原图恰恰是缺的那一环。

**接入点**：等有图率到 90% 之后再考虑；现在接 = 优化一个还没到瓶颈的环节。

### 4.4 html2image —— ⭐455 / 2026-03-22 / MIT / Python · **评分 40（备选）**

headless 浏览器截图，能渲染任意 HTML（含 grid、Web 字体）。
**不推荐作为主路径**：要装 Chromium，CI 里每次多几分钟、多几百 MB；satori 能做同样的事且快一个量级。
只有在「版式必须用 grid/复杂 CSS」时才回退到它。

### 4.5 明确不推荐：icrawler / gallery-dl

- `icrawler` ⭐935，**最后提交 2025-12-10（停更 11 个月）**：Bing/Baidu/Google 图片搜索抓取。
  两个问题叠加——停更 + **版权**。抓来的是新闻社/俱乐部的图，直接商用发布是明确的风险，
  和 11-01 停用 footyrenders 是同一类问题（那次是占位图质量问题，这次是版权问题）。
- `gallery-dl` ⭐20,363：面向图片托管站（Pixiv/DeviantArt 等）的批量下载，**场景完全不对**。

## 5. 写作技巧类

### 5.1 Humanizer —— ⭐64,478 / 2026-10-28 / MIT / Python · **评分 94**

**简介**：Agent skill，删掉 AI 写作痕迹且不改变原意。作者做过盲测，
评审在 **16/16** 次里更偏好改写后的版本；明确声明**目标不是骗过 AI 检测器**
（检测器仍会标记其中大部分），而是「让文字像人写的」。

**核心功能**：内置 **26 类模式**检查，命中即改写。README 列出的最强五个 tell：
1. `Not X but Y`（「不只是功能，而是一次转变」）
2. 一句话收尾（「让这句话沉淀一下」）
3. 听起来很深的套话（「本质上，真正重要的是……」）
4. 铺垫式开场（「事情是这样的」「说实话？」）
5. 跟空气辩论（「我不是说 X，但是……」）

**对应头部哪个特点**：这一条直接命中我们最丢人的一次事故——
生成侧无条件包 `---\n**💬 各位老铁：xx**`，**249 次强插同一句关注引导**。
头部 `英超那些事` **96% 不做关注引导**。也就是说：我们不仅写了头部不写的东西，
还是用同一句话写了 249 遍。「兜底话术比没有钩子更伤信任」这条教训，
Humanizer 的 26 条里有现成对应项（`一句话收尾`、`套话`）。

**接入点**：`orchestrator` 生成后置、`compliance_guard` 之后加一道 `deai_pass()`；
**只做删除与替换，不重写结构**（正文已过忠实度/反洗稿/一致性三道闸门，不能重掷骰子，
这条和 `repick_title` 只改标题不改正文是同一个原则）。

**风险**：它是**通用英文语料**上总结的模式；中文效果要自己验。
而且它优化的是「像人写的」，**不等于「有人点」**——别把它的效果记到 CTR 账上。

### 5.2 Humanizer-zh —— ⭐21,914 / 2026-09-23 / MIT · **评分 90**

**简介**：Humanizer 的汉化版（Claude Code Skill），针对中文表达习惯调整。

**判断**：**中文场景直接用它，不要用英文原版**。中文的 AI 味和英文不是同一批 tell

代价是它 **42 天没提交**（原版 7 天前），汉化质量需要自己抽 20 篇稿子对比。

### 5.3 中文文案排版指北 —— ⭐15,829 / 2026-10-12 / MIT · **评分 85**

**简介**：`Chinese copywriting guidelines`，中文排版规范：中英文之间加空格、
数字与单位之间加空格、全角标点、专有名词大小写、不重复使用标点等。

**核心功能**：一套**可机械判定**的规则（这正是它能进闸门的原因）+
可选的自动修复工具链。

**对应头部哪个特点**：不是「学头部」，是**修我们自己的事故**——
10-24 熔断过一次，原因是比分口径 `0-1` vs `0比1` **三处判定各写各的**，
同一篇被打回 5 次。这类问题的本质是「格式没有唯一口径」。
头部账号的正文看起来「整齐」，不是因为写得好，是因为**排版是机械一致的**。

**接入点**：保存侧格式闸门（`compliance_guard` 同级），
检查项：数字与中文之间的空格、全角/半角混用、比分格式唯一化（`0-1` 一种写法）。

### 5.4 LangGPT —— ⭐12,673 / 2026-09-11 / Apache-2.0 · **评分 68**

**简介**：结构化提示词（Structured Prompt）方法论与模板库。

**对应头部特点**：头部账号的「12 字一个判断」是可以被模板化的，
LangGPT 提供的是「角色/目标/约束/输出格式」的结构化写法，
可以把「标题三要素」沉淀成可复用模板而不是散落在 6 处 prompt 里。

**判断**：**借方法论，不引代码**。我们踩过最贵的一次坑就是
「85.5% 疑问收尾」——三处 prompt 各写死 2 处「必须以疑问？收尾」。
提示词分散在 6 个文件里，改口径必然漏。LangGPT 的价值是提醒你**单一入口**，
这件事用 20 行配置就能做，不需要引一个 Jupyter 仓库。

## 6. 组合方案与风险

### 6.1 许可证：先说这条，因为它会否决方案

**本仓库 `chenwu6688/football-auto-publish` 是 public 且没有 LICENSE 文件。**
这意味着任何 GPL-3.0 / AGPL-3.0 代码一旦提交进来，就构成「分发」，
必须整仓以兼容许可证发布。因此：

| 项目 | 许可证 | 允许做法 | 禁止做法 |
|---|---|---|---|
| RSSHub | AGPL-3.0 | 调它的 HTTP 输出 / 自建实例当服务 | 复制路由代码进本仓库 |
| TrendRadar | GPL-3.0 | 只读它产出的 JSON/网页 | vendor 代码、改完合并 |
| satori | MPL-2.0 | 作为 npm 依赖调用（文件级 copyleft，不改它就没义务） | 改它的源码后不公开改动 |
| Humanizer / 排版指北 / newsnow / Pillow / rembg | MIT / MIT / MIT / PIL-CMU-MIT / MIT | 自由使用 | — |

### 6.2 三条最小落地路径

**P0（本周，零外部服务）**
1. `satori` 出数据卡封面 → 直接压 `35% 无封面`。先做**一种**版式（比分+队名+一句判断），
   字体子集化后再进仓库。
2. `中文文案排版指北` 的规则做成保存侧格式闸门 → 修「比分三处口径」的根。
3. `Humanizer-zh` 后置一道 `deai_pass()`，**先只删不改**（删套话、删一句话收尾、
   删我们自己的固定 CTA）。

**P1（两周，先验证再投入）**
4. `RSSHub` 自建实例，补 2-3 个被反爬拦的信源，复用 `scraper_diagnostics` 分类。
5. `newsnow` **或** `TrendRadar`（二选一）验一次「热榜能不能补活社媒信号」，
   判据是 `external_signals` 的非零率，不是「看起来有数据」。

**P2（观察，不进排期）**
6. `rembg`：等有图率 ≥90% 再说。
7. `LangGPT`：只借「提示词单一入口」这个思路。

**不做**：`icrawler`（停更+版权）、`gallery-dl`（场景不符）、
`DailyHotApi`（停更 8 个月，只抄 schema）、`awesome-chatgpt-prompts-zh`（适配度最低）。

### 6.3 五个必须写在方案里的风险

1. **这批工具都不提高 CTR。** 它们降低成本、抬高下限。CTR 仍要靠标题三要素 + 选题 + 封面组合。
2. **热榜制造同质化。** 越容易拿到的选题，越多人在写。热榜补「不漏」，不补「不同」。
3. **satori 的 CJK 字体是隐性成本**：必须自带字体、必须子集化、CSS 只支持 flexbox 子集。
   不做子集化，仓库会多几 MB 二进制。
4. **Humanizer 的中文效果未验证**，且可能删掉我们真正想要的「钩子」——
   必须配负向用例（删完之后标题/首段是否还在），不能只看「像不像人写的」。
5. **`verify_*` 要跟着加。** 按项目纪律，任何进主链路的改动都要有
   「实现模块 + 验收脚本 + 单测 + CI 接入」四件套，否则就是又一次「写了等于没写」。

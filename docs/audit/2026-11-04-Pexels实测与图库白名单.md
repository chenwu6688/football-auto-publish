# Pexels Key 实测：图库不能当足球图源用

- 日期：2026-11-04 傍晚
- 触发：用户提供 Pexels Key（200 次/小时，免审核）并要求「补充 API 并测试」
- 结论一句话：**Key 是好的，但图库这条链路原本就有个会配错图的 bug；修完之后，
  它仍然只能覆盖 16 支主流球队里的 10 支，其余走数据卡。**

---

## 一、Key 可用性：可用

| 探测 | 结果 |
|---|---|
| `api.pexels.com/v1/search`（Authorization: Key） | **HTTP 200**，1.0~2.0s |
| 英文球队名检索 | `Real Madrid CF` → 8000 条，首图正是伯纳乌 |
| 返回图尺寸 | 3000×2000 ~ 8000×6048，远超 800×600 闸门 |
| 免费额度 | 200 次/小时；每天 5~8 篇成稿，一次一篇 = 远低于限额 |

探活脚本（`scripts/probe_image_sources.py`）现在报 **可用源 3/7**：
新闻源正文图 ✅ / Pexels ✅ / images.unsplash.com ✅；维基超时、Pixabay 无 Key、
Unsplash 401、DDG 被代理挡。

---

## 二、第一次真跑就撞上三个错误

### 1. 中文 query 进英文索引 → 配出完全无关的图

`search_images` 原本这样调用图库：

```python
core = _cb.build_bound_query(ents, ...)     # ents 是「皇马」「巴萨」这类中文实体
for img in _gallery_pixabay(core, ...):     # 三家都是英文标签索引
```

实测（Pexels，per_page=30）：

| query | 第一条返回 | 判定 |
|---|---|---|
| `皇家马德里` | 酱油饺子特写（dumplings with soy sauce） | 完全无关 |
| `欧冠` | 欧元纸币 / 兔子 | 完全无关 |
| `欧冠 皇马` | 空看台 + 欧冠标志 | 勉强相关 |

因为那一段是 `if core: 查图库`，**中文永远满足条件** —— 也就是说，
每一篇没走到维基的稿子都会配上一张「看起来合理、实际无关」的图。
这比无封面更糟：无封面还有 `cover_card` 数据卡兜底，错图是事实错误。

### 2. 球员名搜图库 → 一定是陌生人

| query | 返回 20 张里 alt 含该名字 |
|---|---|
| `Mbappe` | **0** |
| `Haaland` | **0**（返回奥地利一个村庄的风景照） |
| `Bellingham` | 2 |
| `Messi` | 1 |

图库没有球员肖像的版权图。用球员名检索，等于随机抓一张路人照当封面。

### 3. 球队名搜图库 → 一半是错的（而且错得很像真的）

16 支主流球队，每队 per_page=30，只统计「alt 里出现该队主场球场名」：

| 球队 | 命中 | 典型错法 |
|---|---|---|
| 阿森纳 | 23/30 | — |
| 巴萨 | 18/30 | — |
| 拜仁 | 11/30 | — |
| 皇马 | 9/30 | — |
| 曼城 | 9/30 | — |
| 利物浦 | 6/30 | — |
| 曼联 | 3/30 | — |
| 多特 | 3/30 | — |
| AC米兰 / 国米 | 2/30 / 2/30（改查 `San Siro`） | — |
| 尤文 / 热刺 / 马竞 / 纽卡 | **0** | 搜出「小孩踢球」「足球派对」 |
| 巴黎 | 1 | 搜出巴黎街景 |
| 切尔西 | 1 | 更衣室 |

错法举例（都是实测）：

- `FC Internazionale Milano` → 返回**诺坎普**（巴萨的主场）
- `Club Atlético de Madrid` → 返回**阿根廷**的 Estadio Libertadores de América
- `Paris Saint-Germain` → 返回巴黎街景
- `Juventus FC` → 返回儿童足球派对用品

**配错球场和配错人脸一样，是事实错误。** 一篇国米稿配上诺坎普，
懂球的读者一眼就看出来，这比没有封面伤信任得多。

## 三、处置：把「查图库」改成「在白名单上开闸」

新增 `gallery_query.py` + `config/gallery_entities.yaml`，规则四条：

1. **中文一律不查图库** —— 不翻译就不查，绝不把中文丢给英文索引。
2. **球员名一律不查** —— 图库里没有对应照片，查了只能配错。
3. **只查实测确有货的球队**（白名单 10 支），用英文队名或球场名检索。
4. **返回图必须 alt 命中该队主场名**，否则丢弃 —— 空 alt 也拒绝（无法校验＝不可信）。

白名单不是照知名度排的，是照实测张数排的：**verified ≥ 2 才登记**。
尤文/热刺/马竞/纽卡/巴黎/切尔西实测 0~1 张，一律不登记 ——
登记了也只是把「无图」换成「错图」。这些稿子走 `cover_card` 数据卡。

唯一例外是米兰双雄：两队共用圣西罗，图上就是那座球场，对两队都成立。

### 一个差点酿成事故的实现细节

第一次测量时皇马被判 **0 张**，差点被从白名单里删掉。原因是 Pexels 的 alt 写的是
`Santiago Bernabéu`（**带重音**），而我用 ascii 的 `bernabeu` 去比。
加了 NFKD 重音折叠后立刻变成 9 张。

这类「字符形态差异导致判定恒假」的问题，和 `has_anchor()` 被写成方法调用是同类：
**函数在、调用在、结果恒假**。已经在 `verify_gallery_entities.check_fold` 里做成硬项。

## 四、同时修掉的另外两处

### 1. DuckDuckGo 那段：中文 query 且无任何校验

它是唯一「中文可用」的一层（网页图片搜索），所以保留中文 query，
但原来**不做任何校验**就等于拿标题词随机抓图。现在要求返回结果的标题必须点名
正文实体，否则丢弃；没有实体时干脆不发请求（反正 100% 会被全量拒绝）。
`except: pass` 也换成落台账。

### 2. 配置写错会静默丢弃

`gallery_query` 第一版对「query 含中文 / accept 为空」的条目直接 `continue` 丢掉 ——
写错一个字段，功能就少一支球队，而没人知道。现在非法条目单列 `invalid()`，
由验收硬性报红。这与本项目反复踩的「静默失效」是同一类问题。

## 五、验收

`scripts/verify_gallery_entities.py`，6 项：

| 项 | 类型 | 判据 |
|---|---|---|
| 白名单配置自检 | 硬 | 非法条目 0 条；每个名字都能对上 entity_map 的 club；query 全英文；accept 非空 |
| 声明实测张数 ≥2 | 硬 | 每项都写了 `verified` 且 ≥2 |
| 运行时解析 | 硬 | 球员/未登记球队/无实体 → 不查；别名能解析；白名单每项都能解析出自己 |
| 接线 | 硬 | 所有 `_gallery_*` 调用都带 `accept`，且首参不是 `build_bound_query`（回归本次 bug） |
| alt 重音折叠与负向 | 硬 | `Bernabéu` 能被 `bernabeu` 命中；别家球场/空 alt/空 accept 都不通过 |
| 联网实测 | 软 | 有 Key 时重跑 per_page=30，与登记值偏差 >60% 告警；无 Key → skip（返回 2，不算通过） |

单测 `tests/test_gallery_query.py` **30 项**，负向是重点：

- 中文标题进 `search_images` → 发给图库的 query 里不得出现任何中文字符
- 未登记球队 → **一次请求都不发**
- `accept` 不匹配的图 → 丢弃且不占 `need`
- 空 accept / 中文 query / 文件缺失 → `check_config` 必须报红（3 个负向用例）

本地实测（`--measure`）复现了全部 10 项登记值：18/23/11/9/9/6/3/3/2/2。

## 六、还没验证的（明确标出来）

1. **真实批次命中率**：本地没有真实 `match_data` 快照，白名单能出图的比率要等
   11-05 之后的批次，看 `data/audit/scraper_fetch_latest.json` 里 `pexels` 的 count。
2. **Pixabay 仍无 Key**：它的元数据只有 tags（"football, stadium, ball" 这类通用词），
   几乎不含球场名 —— 也就是说**带校验的 Pixabay 检索大概率一张都过不了**。
   Key 到手后先跑一次 `--measure` 看 tags 到底装了什么，再决定这条链路留不留。
3. **Unsplash**：应用仍是 In review，401。代码已改成同一套白名单 + 校验口径，
   Key 生效后无需改代码。

---

## 七、建议

1. **别把图库当主力图源**。它的定位应该是「新闻源正文图与维基都空的时候，
   给几支大球队补一张真球场照」，其余交给数据卡。想提高配图率，
   最有效的仍然是消费 `media_scraper` 已抓到的 `source_images`（零网络、零版权风险）。
2. **白名单要定期复测**。图库的检索结果是会漂的（同一个词两次请求结果不同），
   `weekly` 层已经接上 `verify_gallery_entities`，偏差 >60% 会告警。
3. **如果以后要覆盖更多球队**，比买图库更划算的是补 `entity_map` 的球场名字段，
   然后继续走「英文队名 + 球场名校验」这条已经被证明有效的路。
4. 用户侧：把 `PEXELS_KEY` 加进 GitHub Secrets（本机 `gh` 未登录，只能手动加）；
   `PIXABAY_KEY` 有空再拿；Unsplash 等审核。

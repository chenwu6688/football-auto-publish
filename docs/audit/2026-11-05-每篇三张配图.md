# 每篇至少 3 张配图（2026-11-05）

> 用户原话：「光有文字，没有配图不行，单篇文章至少保证 3 张相关配图，试试通过爬取、免费图库解决。」

## 一句话结论

免费图库在足球题材上**结构性无解**（球员肖像权不在图库手里），所以这次的主抓手是
**爬新闻站正文图**（本机与 CI 都能通），再用 Commons 扩面和原创信息图保底，
把「每篇 0~1 张」拉到「每篇 ≥3 张」。落地后实测：三类选题各 3 张、端到端落盘 3 张、
把网络全掐掉仍能补 3 张。

## 一、改之前的实况

noon 批次（3 篇已发布）的 metadata：

| 篇 | images | 来源 |
|---|---|---|
| 瓦伦西亚主帅…皇马27分 | 1 | 原创信息图（封面兜底） |
| 当年那个追风少年… | 1 | 原创信息图（封面兜底） |
| 老六心中的历史射手榜… | 1 | 原创信息图（封面兜底） |

`degrade_events` 里两条「封面兜底：图源全断，改用标题数据卡」。读者看到的就是
「一篇长文 + 一张标题卡」。

## 二、为什么「再加一个免费图库」这条路走不通

2026-11-04 已经逐条实测过（结论写在 `data_collector.search_images` 的 docstring 里）：

| 图源 | 足球题材的真实表现 |
|---|---|
| Pexels / Pixabay | 英文标签索引，`query=皇家马德里` 返回酱油饺子；16 支主流球队只有 10 支有球场照；**球员肖像 0 覆盖** |
| Unsplash | 应用状态 In review，Key 401 |
| Wikimedia Commons | 唯一合规有真人照的源，但本机（国内网络）全超时，CI 也只有 1~2 张 |
| Openverse | 本机超时 |

根因不是搜索技巧：**肖像权归俱乐部/经纪公司/联赛**，免费图库拿不到素材。这条是行业结构，
不会靠再注册一个 Key 解决。

真正的存量在新闻站——一篇报道本身就是「图 + 文」成套产出的。

## 三、五处改动

### 1. 新增爬取层 `news_images.py`

- `parse_index` → 直播吧足球新闻列表（当次 608 条），按文章 ID 去重；
- `pick_articles` → **只挑标题命中正文实体的报道**，命中的实体越多排越前；
  别名反查做了（正文写「皇家马德里」、标题写「皇马」也能对上）；
- `parse_article_images` → 只取**正文容器**里的 `<img>`，过滤站内静态域名 / logo / icon /
  gif / 占位图 / 宽高 <200 的小图；容器找不到就返回空（**不退回整个 `<body>`**，
  否则列表页几十张小图全混进来，等于自建随机图库）；
- `upgrade_url` → 图床 URL `xxx_720.jpg` 改写成 `_1280.jpg`。这条是必需的：
  720×480 **过不了**下载端 800×600 闸门，不升级就是「爬到了但一张都没落盘」的黑箱；
  下载失败再回退到 `_720`（不是「去掉后缀」——那是 3 MB 原图，撞 5 MB 上限）。
- 取图顺序：**先每篇报道各 1 张，不够再取第 2 张**。实测踩过：一篇「欧冠夺冠概率」
  的报道正文有 3 张图，按篇取满会让整篇稿子的 3 张配图全来自这一篇，看着像复制粘贴。

边界（合规）：只爬与本文同实体的报道正文图，属转述性使用，与 `media_scraper` 抓战报
正文图同一口径；**不做百度图片/必应图片那种"按关键词扒全网图"**——那是版权雷区，
项目 11-04 已经明确不做。

### 2. `search_images` 接线 + Commons 扩面

- 新增 ⓿' 层（排在战报正文图之后、维基之前）：没有实体就**不爬**，直接落
  `scraper_diagnostics` 说明「无正文实体，不爬新闻图」；
- Commons 的实体遍历从 `ents[:2]` 放宽到 `ents[:4]`，每个实体只取「还差的张数」
  （多查实体是提覆盖率，不是让同一支球队堆三张一样的球场照）。

### 3. 尺寸闸门分档（否则爬取层白干）

`image_service.download_image` 新增 `min_width / min_height` 覆盖：

- **第一张**会被头条选作封面 → 800×600；
- **其余**是正文插图（渲染宽度 ~640px）→ 600×400。

实测数据支撑：`_1280` 版本 1280×853 过闸门，但「无尺寸后缀」的原图只有 644×476，
一刀切 800 会把它整批拒掉。

同时新增 `fallback_url`：主地址失败自动回退 `_720`，台账仍记原始地址（可回溯）。

### 4. 下限由信息图保底（`cover_card.fill`）

`render()` 支持三种版式，全部由**这篇稿子自己的内容**派生：

| 版式 | 素材 | 用途 |
|---|---|---|
| `points` 要点卡 | 正文 `## ` 小标题 + 该节首句（最多 3 条） | 结构感 |
| `numbers` 数字卡 | 标题里最关键的数字做 160px 大字 | 焦点感 |
| `title` 标题卡 | 标题 + 关键数字标签 | 封面 |

`fill()` 补齐到 3 张，并保证**版式不重复**（`skip_variants`）——否则「3 张配图 = 同一张
复制三遍」，用户一眼看出是凑数。素材不足时跳过该版式（要点少于 2 节就不出要点卡），
不硬凑。

样张见 `assets/`：`2026-11-05-配图版式-要点卡.jpg` / `-数字卡.jpg` / `-标题卡.jpg`。

### 5. 正文注入不丢图

旧实现 `if si < len(downloaded)`：稿子只有 2 节、图有 3 张时，第 3 张既不进正文也不报错
——图下载了、读者看不见、台账却记 3 张。抽成 `_inject_images()`：按节插，多出来的
**追加到文末**，保证「下载几张，正文就有几张」。

### 断网兜底

| 场景 | 结果 |
|---|---|
| 候选 0 张 | 3 张（1 封面卡 + 2 信息图），正文引用 3，降级记「封面兜底 + 配图补齐」 |

## 五、风险与边界（必须说清楚）

1. **相关性是「报道级」而非「图片级」**。校验能保证「这张图出自一篇讲本文实体的报道」，
   保证不了「图里就是标题说的那个人」。例如「半场零封巴黎」召回到「欧冠夺冠概率」的
   配图——报道讲巴黎，图是概率榜。比无图好，比精确配图差。要再进一步只能靠图像识别，
   成本与收益不成正比。
2. **可能混入历史图**。报道正文偶尔嵌旧图（实测出现 2023 年的图床路径）。目前不过滤，
   因为它仍属于这篇报道的内容。
3. **图源单一依赖直播吧**。列表页 608 条，够用；将来若改版/反爬，`parse_index` 会返回空
   并落 `scraper_diagnostics`（不会静默），届时再补第二家（懂球帝本机 567 被拦）。
4. **信息图是保底不是目标**。断网时 3 张全是原创信息图，观感仍不如真实照片——它是
   「不让读者看到纯文字」的底线，不是「配图做得好」的证明。

## 六、验收

`scripts/verify_article_images.py`（已登记 `config/audit_tiers.yaml`，pre-publish / advisory）：

- 硬项 A 爬取层接线（`search_images` 真调用 `news_images.fetch`，只 import 不算）
- 硬项 B 补齐接线（`save_articles_local` 真调用 `cover_card.fill`，参数齐、下限是常量 3）
- 硬项 C 注入不丢图（2 节 + 3 张 → 正文里 3 张）
- 硬项 D 断网可兜底（掐掉网络仍补 3 张、互不相同）
- 硬项 E 闸门分档（720×480 拒于封面档、放于正文档）
- 硬项 F 真实产物（生效日 `metadata.image_floor.since` 之后每篇 ≥3）
- 告警 G 降级台账（`配图不足` 说明连信息图都补不上）
- 负向自检 `--selftest`：1 张的批次必须报红、3 张的必须达标

三态：窗口内没有对齐生效日的批次 → 退出码 2（**未判定 ≠ 通过**）。

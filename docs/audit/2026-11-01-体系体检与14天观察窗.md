# 账号发文 + 运营体系体检（2026-11-01）

> 目的：把现有体系整条链路摊开，用后台真实数据定位「哪一段在漏水」，为 11-02 起的 14 天观察窗定验收口径。
> 数据口径：`output/performance_log.json`（76 篇有曝光量的实证样本）+ 10 月成稿 242 篇 + `data/metrics/dashboard_2026-11-01.md`。

## 一、体系全景（五段）

| 段 | 入口 | 主要模块 | 当前状态 |
|---|---|---|---|
| ① 供给 | 赛程/节点日历、热点信号、软性蓄水池 | `deterministic_supply`+`season_calendar`、`event_result`、`event_cluster`、`reservoir`、`supply_mix`(30/50/20)、`ranker`/`awareness_gate` | 三源齐备，配额与禁发类型已有硬约束 |
| ② 生成 | 事实卡 → LLM → 五道闸门 | `fact_card`/`extractor`、`orchestrator`、`compliance_guard`、`differentiation`、`consistency_stats` | 事实与合规闸门较严，误报已收敛 |
| ③ 发布 | 标题闸门 → 头条 | `title_gate`、`template_gate`、`title_antipattern`、`publisher`、`publish_ledger` | 标题闸门 11-02 生效；台账 11-01 刚上线 |
| ④ 回流 | 导出 → 绩效 → 看板 → 调参 | `collect_toutiao_exports`、`toutiao_import`、`weekly_review`、`ratio_tuner`、`build_metrics_dashboard` | 闭环已通，T+1 入库 |
| ⑤ 治理 | CI 门禁 / 巡检 / 告警 | 31 个 `verify_*`、14 个 workflow、`heartbeat`、`check_scheduler_health` | 门禁密度高，是全仓最扎实的一段 |

**整体判断：治理与合规这一段已经过剩，供给和生成也够用；真正漏的是「③ 发布」里的封面，以及「④ 回流」缺少 CTR 这个主指标。**

## 二、体检数（实证）

### 2.1 流量到底卡在哪

| 指标 | 我方实测 | 计划目标 | 差距 |
|---|---|---|---|
| 曝光量（中位） | **4,020** | — | 均值 4,633，>1 万仅 2 篇 |
| **点击率（聚合）** | **0.95%** | 3.5% | 目标的 27% |
| 篇均阅读 | 44 | 200 | 22% |
| 完成率（中位） | 27.6% | 40% | 69% |
| 粉丝阅读占比 | 0.66% | 2.0% | 33% |
| 篇均互动 | 1.26 次 | — | 基本为零 |
| 溯源覆盖率 | 32.2% | 100% | **硬缺口** |

**关键结论：曝光是有的（中位 4020，是标准的冷启动流量池），不是「没进推荐池」。**
之前对标报告里「可能是账号权重太低、根本没被推」的猜测，被这组数字否掉了。
体系卡在**点击率**：4020 次曝光 × 0.2% = 8 次阅读。头部 15 万粉的「英超那些事」中位阅读 5,526，
差距不在分发，在**被看到之后有没有人点**。

### 2.2 最大的一处漏水：37% 的已发布文章没有封面

10 月已发布 143 篇里，**53 篇（37%）是「无封面」模式发出的**。按封面分层：

| 组 | 篇数 | 聚合点击率 | 篇均阅读 |
|---|---|---|---|
| 无封面 | 50 | **0.52%** | 26 |
| 有封面 | 26 | **2.07%** | 77 |

**4 倍差距。** 12 篇「零阅读」里有 11 篇在无封面组。

根因是一条本意正确的合规规则：

```
cover_binding.filter_bound_images()   # 计划 2.2「禁用随机图库配图」
    → 找不到与正文绑定的图 → 「本篇不配随机图」（只 print，不落台账）
        → publisher：images == 0 → 主动点「无封面」
```

为了不违反「不放随机图库图」，系统选择了**不配图**，代价是无封面卡片在信息流里的点击率只有有封面的 1/4。
这条规则把「合规」和「有效」做成了二选一，而现实中应该做的是**提高绑定图的召回率**。

### 2.3 更隐蔽的一层：有封面的那 63%，图也常常是错的

实测 `search_images({"title": "史上最佳之争：马拉多纳贝利梅西"})` 返回：

```
footyrenders  cristiano-ronaldo.png   ← 查询词是 Messi，第一个结果是 C 罗
footyrenders  lionel-messi.png
footyrenders  jude-bellingham.png
```

原因：`search_footyrenders` 抓的是 `?s=<slug>` **搜索结果页的全部 png 链接**，其中包含站点侧栏的
「热门球员」推荐位，而我们直接 `[:count]` 取前几张 —— 于是封面经常是与正文无关的另一名球员。
`cover_binding` 放行了它们，因为 `alt` 字段被写成了查询词本身（自己给自己背书）。

这解释了为什么「有封面」组点击率也只有 2%：**图在，但和标题不是一回事。**

### 2.4 发布成功率仍在掉

10-31 成稿 6 篇，只有 2 篇带 `platform_id`；10-29 是 8 篇里 5 篇。
`publish_ledger` 11-01 才上线，所以这段时间的失败原因还是黑的 —— 这是 14 天窗口要盯的第二块。

### 2.5 标题：改完「疑问收尾」，还有下一个模板在排队

近一周 42 篇标题里，6 字重复片段扫描出两个高频句式：

- 「谁先变阵 / 谁先慌 / 谁先崩」× 6（5 天内）
- 「到底哪一步走错了」× 3

`template_gate` 的 `SIGNATURES` 是**人工维护的黑名单**（主帅压力体等），这两个句式都不在表里，
所以 14 天 ≤2 篇的规则对它们完全没生效。同期还出现**同一场比赛两次出稿**
（10-29 尤文 vs 那不勒斯晨读、午间各一篇，标题几乎同义）。

黑名单式句式闸门的结构性问题：**新句式永远比名单早到一步。**

### 2.6 结构性：只有一个内容形态

全仓发布通道只有图文 `publish_article`，没有微头条 / 视频 / 问答。
粉丝 11,733，日增 1~4。图文的单篇流量天花板 + 0.95% 点击率 = 涨粉只能靠量，
而量已经被 38% 的发布成功率卡住。

## 三、对「14 天观察窗」的意见

**同意先跑 14 天，P1 先不动。** 但现在的窗口设计有两个问题，会让结论失真：

1. **封面不修就跑，锚点覆盖率涨到 40% 也读不出效果。** 因为 37% 的样本是无封面（0.52%），
   标题改得再好也被这 37% 拽住；14 天后大概率看到「锚点上去了、CTR 没动」，
   然后错误地归因到「标题没用 / 账号权重太低」，把 P1 的方向带偏。
   封面这条不是新功能，是**已知缺陷**，应该在窗口开启前修掉。
2. **「14 天后自动跑台账」现在不成立。** 标题锚点验收挂在 `plan-invariants-verify.yml`，
   cron 是每周一 12:30 CST（11-02、11-09、11-16），不是「14 天后」一次性跑。
   要的是 11-16 那次之后的**复盘报告**，而不是通过/不通过。

### 建议的窗口验收口径（11-02 ~ 11-15）

| 看什么 | 指标 | 判定 |
|---|---|---|
| 主指标 | **分层点击率**（有封面 / 无封面分开算） | 有封面组 ≥ 2%，无封面组篇数趋零 |
| 过程指标 | 锚点覆盖率 | ≥ 40% |
| 过程指标 | 疑问收尾篇数（14 天） | ≤ 2 |
| 发布健康 | `publish_ledger` 的 failed 原因分布 | 归零或单一已知原因 |
| **不看** | 篇均阅读、粉丝增数 | 噪音太大，76 篇样本分不开 |

## 四之二、封面链路修复（2026-11-01 当天落地）

**做之前先查实了三个断点**（都不是「策略不对」，是「链路断了」）：

| 断点 | 实测 | 修法 |
|---|---|---|
| 手工实体表只有 33 个 | `WIKI_PLAYERS` 18 人 + `WIKI_TEAMS` 15 队 | 改用 `cover_binding.article_entities`（读 `config/entity_map.json`，**1522 条**）→ `search_wikipedia_entity()` 走维基「精确页 → 搜索 → 摘要」三级 |
| footyrenders 是死图源 | CDN 返回 **50×50 / 2,173 字节**占位 PNG，保存侧 800×600 闸门必拒 | 退出候选链（函数保留，供单测与将来换源） |
| 侧栏污染 | 查 Messi 第一个返回 `cristiano-ronaldo.png`——抓的是搜索结果页**全部** png，含侧栏「热门球员」位 | 只收 slug 与检索词匹配的那张 |

**顺带补的三条闸门**：

- `search_wikipedia_entity` 加了页名相关性校验（`_title_matches`）：维基里「米兰」可能是城市条目，
  重定向「国际米兰 → 国际米兰足球俱乐部」放行，而「国际米兰 → 2021年国际冠军杯」直接丢弃。
  没有这一步，扩召回就等于用「图文不符」换「有图」，CTR 一样起不来。
- **不做标题词兜底**：没有实体时宁可不配图。拿标题词去搜维基，几乎必然搜到无关条目——
  计划 2.2 的「宁可不配图也不放随机图」在这里优先于覆盖率。
- `publish_ledger` 新增 `published_without_cover`：正文 0 图 = 发布时选了「无封面」，
  这个数字以前只 print。现在每批都留证据。

**验收**：`scripts/verify_cover_coverage.py`（4 硬项：零配图率 ≤5% / 实体→维基已接入且真被调用 /
尺寸闸门 ≥800×600 / 负向验证），已进 `plan-invariants-verify.yml` 硬门禁，未软化。
`tests/test_cover_recall.py` 15 项，含「没实体就干脆不搜」「搜索飘了必须丢弃」「只有定义没调用必须 FAIL」。
全仓单测 1275 → **1290**；33 个 verify 脚本全绿（`verify_fixture_pool` 本地无 Key 返 2 属正常）。


## 五、局限

- 76 篇样本、单账号，所有分组比较都是**方向性**的，不是显著性结论（无封面组 n=50、有封面组 n=26）。
- 没有曝光来源维度（推荐 / 关注 / 搜索），所以分不清「冷启动池」与「粉丝池」的占比。
- 封面相关性（2.3）是**机制性推断 + 单次实测**，没有全量样本验证，需要在修完后用 CTR 变化反证。

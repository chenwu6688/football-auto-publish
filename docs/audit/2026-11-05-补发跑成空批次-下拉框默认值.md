# 补发跑成了空批次：`choice` 输入不给 default 会预选第一项

**日期**：2026-11-05 19:07 · **run** `42016246302`（#1841）·
**结论**：Success / 41s / 无产物 / 0 篇 —— 是一次**什么都没做的绿勾**。

## 一、现象

18:00 批次因预置 `NameError` 失败（详见 `2026-11-05-闸门分级v2上线.md` 第七节）后，
19:07 手动补发 evening。run 页面显示：

- Status **Success**，Total duration **41s**；
- Artifacts 为空，注解里一句
  `No files were found with the provided path: /home/runner/work/tmp/outputs/2026-11-05/`；
- 分步看：第 9、10 步 success，**第 11–33 步全部 skipped**，只有
  「上传产物」「推送诊断」两个 `always()` 步骤在跑。

`output/2026-11-05/metadata.json` 仍是 `batches_completed=['morning','noon']`，
当日成稿仍是 4 篇 —— **确实一篇没生成**。

## 二、根因

`.github/workflows/batch.yml` 的 `workflow_dispatch.inputs.batch` 是
`type: choice` 且**没有写 `default`**：

```yaml
batch:
  type: choice
  options: [morning, noon, evening]   # 没有 default
```

GitHub 的行为是：choice 输入不指定 `default` 时，**自动预选列表里的第一项**。
第一项是 `morning`。操作者点「Run workflow」时没有动下拉框 → 实际提交
`inputs.batch = "morning"`。

于是第 9 步走到「手动指定」分支，`BATCH=morning`，接着幂等保护读到
`batches_completed = "morning,noon"`，`grep -q "morning"` 命中 → `skip=true`、
`exit 0`。后续所有步骤的 `if: steps.params.outputs.skip != 'true'` 全为假。

**这行 `exit 0` 是正常的幂等语义**（同批不重复发），问题在于：

1. 输入默认值把「补发 evening」静默变成了「重跑 morning」；
2. 跳过以 **success** 收场 —— 界面只有绿勾和「Success 41s」，
   人工无法区分「发了」和「什么都没做」。这正是 10 月「有结论没留证据」的
   同类问题：**结果页没有承载「本批到底做了没有」**。

## 三、修法（三条，都不改动发布语义）

1. **给 `default: auto`，把 `auto` 放到选项第一位**。盲点「Run workflow」时
   `auto` → 按当前 CST 小时判定（<10 morning / <15 noon / 其余 evening），
   19:07 就判成 evening，不会撞已完成批次。
2. 第 9 步手动分支加 `&& [ "${{ inputs.batch }}" != "auto" ]`，让 `auto`
   落到原有的按小时判定；第 186 行「时区校验」的条件补 `|| [ ... = "auto" ]`，
   保证 `auto` 仍然受时间窗校验（否则 19 点选 auto 判成 morning 也不会被拦）。
3. **跳过必须留痕**：幂等跳过时写 `$GITHUB_STEP_SUMMARY`（表格：目标批次 /
   日期 / 已完成批次 / 本次动作=无）+ `::warning::`，run 页面直接看到
   「本批未执行（幂等保护跳过）」，不再只有绿勾。

## 四、验证方式（不靠「看着对」）

把第 9 步的 `run:` 原文抽出来，替换 `${{ … }}` 表达式后真跑，`gh` 用假脚本
返回 `morning,noon`：

| `inputs.batch` | 判定批次 | 幂等结果 | 输出 |
|---|---|---|---|
| `auto` | evening | 未执行 → **继续** | `batch=evening`, `skip=false`，时区校验通过 |
| `evening` | evening | 未执行 → **继续** | `batch=evening`, `skip=false` |
| `morning` | morning | 命中 → 跳过 | `skip=true` + warning + Job Summary |

`yaml.safe_load` 解析通过，`steps` 数不变（36），crons 6 条不变。

## 五、残留风险（未解决，先说清）

- 跳过仍是 **success 的 job**。GitHub 没有「neutral」结论可给单个 job，
  只能在 Summary / annotation 上做提示 —— 依赖人去看。想彻底解决要让
  「跳过的批次」另起一个 workflow 或给告警通路（WxPusher）补一条
  「本批已跳过」通知，目前没做。
- `auto` 的按小时判定在 **CST 10:00–10:59** 之间会判成 noon，
  15:00 之后一律 evening；凌晨补发（00:00–05:59）会被死区护栏拦住（仅 schedule），
  手动补发不受限 —— 这些是既有语义，本次未改。

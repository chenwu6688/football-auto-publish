# 2026-11-05 事故复盘：批次「生成文章」1 秒崩 —— Python 3.12-only f-string

## 现象

- 11-04 18:04 evening（run `41811329994`）、11-05 08:01 morning（run `41938115638`）连续两批失败，
  WxPusher 只有「失败步骤: 生成文章（详见运行日志）」。
- Actions 分步计时：两次「生成文章」都是**同一秒起止**（`00:01:28 -> 00:01:28`），
  产物目录只有 3.6KB、无 LLM 调用、漏斗台账 `topic_funnel.jsonl` 完全没落盘。
- 中间所有显示「success」的批次其实 step 18 是 `skipped`（重复 cron 触发的空批次），
  最后一次真正生成成功是 11-04 12:00 CST（`14e9db2`，step 18 跑了 4m17s）。

## 根因

CI 日志（用一次性诊断 workflow 让 CI 自带 token 抓取后回写仓库取得）：

```
File "orchestrator.py", line 37, in <module>
    import title_elements
File "title_elements.py", line 281
    "detail": [f"三要素 {e.count}/3 达标（{'、'.join(
               ^
SyntaxError: unterminated string literal (detected at line 281)
```

`title_elements.check()` 里用了 **Python 3.12 (PEP 701)** 才允许的写法：
单行 f-string 的 `{...}` 表达式内跨行（还复用了引号）。批次 job 是 **Python 3.11.17/3.11.18**，
导入期直接 SyntaxError，进程没进 `main()` 就死了——所以没有漏斗台账、没有生成失败告警，
只有 workflow 兜底写的「失败步骤: 生成文章」。

本地是 3.12/3.13、单测 CI job 是 3.12，全部绿灯；用干净 venv、干净检出、CI 全套环境变量
反复跑本地都复现不出秒崩，方向一度被带偏到依赖/网络/日志鉴权。

## 为什么三道防线全没拦住

| 防线 | 失效原因 |
| --- | --- |
| 本机单测 1559 passed | 3.12/3.13 解释器，PEP 701 合法 |
| CI 单测 job（3.12） | 从 11-03 起就因 `unit-tests.yml` 漏装 `beautifulsoup4` 收集期 exit 2 一直红；长期红灯被当成噪音，没人看 |
| batch.yml「静态分析」步骤 | `tests/test_no_dead_references.py` 的 `FILES_TO_CHECK` 只有 `orchestrator.py` / `publisher.py`，压根没解析 `title_elements.py` |
| `ast.parse(feature_version=(3, 11))` 全仓扫描 | **假绿**：feature_version 管不到 f-string 分词，3.12 的解析器照样接受 PEP 701 |

教训：**判断「CI 能不能跑」必须用真的那个解释器编译**，语法兼容不能靠本地高版本推断，
也不能靠 ast feature_version。

## 修复

1. `title_elements.py`：把 `'、'.join(...)` 从 f-string 表达式里提出来先算成 `hit_names` 再插值，
   3.9+ 都能编译，输出字符串逐字不变（有单测守着）。
2. `unit-tests.yml`：
   - 依赖改成 `pip install -r requirements.txt pytest`，修掉漏 bs4 导致的收集期红，
     且以后生产新增依赖单测自动同步；
   - 新增 `py311-compat` job：用真 3.11 `python -m compileall -q .`，硬门禁、不加软化。
3. `batch.yml` 静态分析步骤：用与生成步骤同一个 `python`（3.11）先编译全仓，
   语法问题提前到「静态分析」阶段报红，不再伪装成「生成文章失败」。
4. `tests/test_py311_compat.py`：三条守线——detail 字符串不变 / 本机有 3.11 时全仓编译 /
   **负向自检**（把 PEP 701 代码喂给 3.11 必须报 SyntaxError，否则闸门是摆设）。
   本机无 3.11 时明确 skip（未判定 ≠ 通过），由 CI job 兜底。
5. 一次性诊断 workflow 与回写的日志片段用完即删。

## 验收

- 真 Python 3.11.17 + `requirements.txt`：`compileall -q .` 返回 0，`import orchestrator` 成功。
- 修复前同一份源码在 3.11 下 `compile()` 精确报 line 281 SyntaxError（确认闸门有效，非假绿）。
- 本地全量单测 **1562 passed / 94 subtests**（新增 3 项）。
- 下一批 CI：unit-tests 两 job 应转绿；batch.yml 静态分析步骤应打印「全仓编译」不再秒崩。

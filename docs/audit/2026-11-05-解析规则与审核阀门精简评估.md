# 固定解析规则与多层审核阀门的精简评估

日期：2026-11-05　｜　性质：评估 + 可验证原型（`fact_assert.py`），生产逻辑未改动
依据：`config/audit_tiers.yaml`、45 个 `scripts/verify_*.py`、`orchestrator.py` 生成链、
`data/compliance_state.json` 熔断史、`data/audit/topic_funnel.jsonl` 漏斗台账、
`docs/benchmark/` 181 条头部样本、GitHub API 实查 star

---

## 〇、一句话结论

**问题不在「审得严」，在于审的姿势错了。**

现在的校验问的是「正文里有没有出现我预期的那几个字」——这是**存在性校验**；
你要保的是「别改原意、别臆造」——那是**矛盾校验**。
两者差一个量级：过去 4 次自动熔断，**4 次全是存在性校验的误报，零次真实违规**。
把「没写」当「写错」拦，等于用误杀换安全感；而真正该拦的「比分写反」，
现有实现反而漏（`_score_mentioned` 允许主客顺序颠倒）。

所以方案不是「再加几道阀门」，而是**把校验范式从「必须命中」换成「不得冲突」**，
然后把省下来的算力放到「事实源收敛」上——后者才是头部账号真正在做的。

## 一、现状清点

### 1.1 固定解析规则：约 40 条正则、6 张词表、9 个判定函数

| 位置 | 做什么 | 脆弱点 |
|---|---|---|
| `media_scraper.py`（31 处 `re.`） | 从标题按「比分前=主队／比分后=客队」切队名；比分归一；球员名清洗 | **队名来自字符串切片**，不是实体识别。切出「科莫血洗」「欧冠」「科莫留力仍」都发生过 |
| `team_names.py` | 剥两端赛果动词 + 介词（科莫血洗→科莫） | 只能剥**已知动词**；任意短语（科莫留力仍）剥不掉 |
| `orchestrator._team_forms/_same_team/_team_in_content/_relaxed_team_mention/_teams_in_content` | 别名感知 + 最长匹配 | 5 个函数判同一件事的 5 个侧面，10-12 与 11-05 两次熔断分别打在不同侧面上 |
| `_SCORE_RE` + `_DATE_LIKE/_TIME_LIKE/_ROUND_LIKE` | 比分形态识别 | 10-24 之前三处各写一份，只认 ASCII `-`/`:` |
| `_clean_player_name` / `_looks_like_team` / `_TEAM_DIRTY_TOKENS` | 脏串过滤 | 黑名单是开放集合，补一次只挡一次（10-13 补「首发」，11-05 又被「血洗」打穿） |
| `title_features/title_elements/title_antipattern/rumor_wording` | 标题锚点、三要素、反模式、传闻分级 | 规则本身没问题，问题是**硬打回**的用法 |

**判断**：解析层承担了「语义理解」的职责，但工具只有正则。这是所有熔断的共同上游。

### 1.2 审核阀门：六层，45 项验收（13 硬 / 32 告警）

```
L0 生成前  选题漏斗 6 层   llm → dedup → material → category → batch_mix → slot
L1 生成中  一次尝试 7 道   字数 → 保真度 → 一致性 → 反洗稿相似度 → 信息增量 → 标题评分 → 互动引导
L2 保存侧  2 个兜底        关注引导注入、配图补齐
L3 发布前  10 项（3 硬）   content_mix / article_images / image_relevance
L4 发布后  12 项（6 硬）   publish_success / cover_coverage / batch_mix / effect_loop / llm_quota
L5 代码侧  20 项（3 硬）   口径与接线
L6 元层    8 项（2 硬）    audit_health（清单本身有没有失真）、test_gate
```

| 指标 | 数值 |
|---|---|
| 验收项 | **45**（pre-publish 10 / daily 12 / code-change 20 / weekly 8，含跨层重复） |
| 其中 hard（FAIL 就挡发布） | **13** |
| advisory（FAIL 只告警） | **32** |
| 有负向用例（能证明判定真的在判定） | **15**，债务 **30** |
| 日均实际发布 | **约 2 篇** |

**45 项验收 / 日均 2 篇发布**——这个比例本身就是问题。

### 1.3 生成侧一次尝试内的 7 道串联闸门

| # | 闸门 | 判什么 | 失败后果 | 可恢复性 |
|---|---|---|---|---|
| 1 | 字数 | 正文 ≥ 目标 60% | 重写 | 可 |
| 2 | `check_rewrite_fidelity` | 比分一致、球员名出现 | 重写 | 可 |
| 3 | `validate_article_vs_match_data` | **主队名/客队名必须出现**、比分必须出现、进球断言 | 重写 → 降级 → 丢弃 + **熔断计数** | **不可** |
| 4 | `check_similarity_gate` | 与源文最长公共片段 | 重写 | 可 |
| 5 | `check_information_increment` | 新事实条数 | 重写 | 可 |
| 6 | `score_title_plan` | 标题 60 分及格 | 先只重拟标题（≤2 次）→ 再重写 | 半可 |
| 7 | `check_interaction_bait` | 关注/互动引导 | 重写 → 保存侧注入 | 可 |

**关键结构缺陷**：这是 7 个「与门」串联，一次尝试必须全部通过。
单道 95% 的通过率，整条链只有 **69.8%**；单道 85%，整条链 **32.1%**。
而第 3 道是唯一会写熔断计数的——它一旦误报，代价不是「这篇重写」，是「全批停发」。

## 二、问题定位（全部有据）

### 2.1 四次熔断，四次都是解析误报

| 时间 | 现场 | 真实情况 | 是否真实违规 |
|---|---|---|---|
| 10-12 | 缺少客队名: 拜仁慕尼黑 | 正文写「拜仁」，别名表未覆盖全称 | ❌ 误报 |
| 10-13 | 缺少客队名: 大田市民首发 | 采集粘连「首发」，正文写简称「大田」 | ❌ 误报 |
| 10-24 | 比分不一致: 蓉城 0-1 英博 | 正文写「0比1」，三处正则各写各的 | ❌ 误报 |
| 11-05 | 缺少客队名: 血洗 | 采集把赛果动词切进队名字段 | ❌ 误报 |

**四次误报没有一次是稿子写错了。** 全部是「没按我们预期的字面写」。
这四次里，稿子的实际事实都是对的。

### 2.2 串联与门的乘性衰减

| 单道通过率 | 7 道串联全过 | 3 次尝试后至少一次全过 |
|---|---|---|
| 99% | 93.2% | ~100% |
| 95% | **69.8%** | 97.3% |
| 90% | **47.8%** | 85.8% |
| 85% | **32.1%** | 68.6% |
| 80% | 21.0% | 50.6% |

对照：收敛成 2 道硬闸门（事实矛盾 + 合规）+ 5 道只记分，同样单道 90% 时，
3 次尝试后通过率从 85.8% 升到 **99.3%**。

### 2.3 主通道实测：今天两个批次，主稿 4 请求 0 成稿

`data/audit/topic_funnel.jsonl`（今天刚接的埋点）：

| 批次 | 选题 | 分类砍 | 配比降级 | 主稿请求 | 主稿失败 | 最终成稿 |
|---|---|---|---|---|---|---|
| 午间 12:01 | 3 | 1（战报比分软上限） | 2 | **2** | **2** | 3（补位） |
| 晨读 15:09 | 3 | 1（同上） | 2 | **2** | **2** | 1 |

今天 4 篇成稿的供给层：`一级·确定性` ×2、`三级·软性` ×2，**新闻改写通道 0 篇**。
（近 7 天 `二级·突发` 共 20 篇，说明这条通道平时是通的——今天是打穿了，不是常态。）

两批的失败原因各一：一篇是「缺少客队名: 血洗」打回 → 降级 → 丢弃；一篇是生成失败。
**这就是「环环相扣反而增加限制」的实测形态**：选题被砍一次、配比降级两次、
主稿再全灭，最后靠兜底池凑数。产出没少，但产出结构变差了。

### 2.4 同一规则多处定义，是反复出事的结构原因

| 事故 | 同一规则写了几遍 |
|---|---|
| 10-24 比分口径 | 3 处（fidelity / 一致性 / 事实卡），各写各的正则 |
| 11-05 队名清洗 | 4 处（两处解析 + 校准 + 校验），漏一处就复发 |
| 11-05 金句卡 | 3 处（`_extract_quote` / `fill` / `_FILL_PLAN`），第 2 张永远出不来 |

不是「注意力不够」，是**结构上允许同一规则有多份实现**。

### 2.5 观测缺口：反洗稿闸门的实际指标没有留证

`_similarity` / `_increment` 只写进内存里的 `art`，**没有进 `metadata.json`**。
所以「反洗稿卡了多少篇、卡在相似度还是增量」这件事，事后完全查不到。
一道每天在拦人的闸门，拦了多少次没人知道——这比没有闸门更危险。

### 2.6 阀门数与产出规模错配

45 项验收 + 145 个测试文件，对应日均 2 篇发布、篇均阅读 63。
头部样本里最高的账号（英超那些事，15 万粉）**中位阅读 5,526，是人工选题 + 人工终审**。

## 三、根因：校验范式错配

### 3.1 存在性 vs 矛盾

| 情况 | 现在的判法 | 应该的判法 | 例子 |
|---|---|---|---|
| 正文写「主队」「他们」，没写队名 | ❌ 拦（缺少客队名） | ✅ 放过，记覆盖度 | 10-13 大田 |
| 正文写「拜仁」而非「拜仁慕尼黑」 | ❌ 拦（别名没覆盖到） | ✅ 放过（别名感知） | 10-12 拜仁 |
| 正文写「0比1」而非「0-1」 | ❌ 拦（正则不认） | ✅ 放过（形态归一） | 10-24 蓉城 |
| 正文写「科莫1-9朗斯」（方向反） | ✅ **放过**（`_score_mentioned` 允许颠倒） | ❌ **拦**（矛盾） | 未被发现过 |
| 正文写「姆巴佩梅开二度」但实际 1 球 | ✅ 拦（这条是对的） | ✅ 拦 | 保留 |

**注意最后两行的反差**：现在的实现**该拦的放过、不该拦的死拦**。
不是「太严」，是「判据和诉求不是同一件事」。

### 3.2 为什么改成矛盾校验能一次性消灭四次熔断

因为四次熔断的共同点是「事实**没有冲突**，只是**没有以预期写法出现**」。
矛盾校验的判据是「正文断言 ∩ 事实卡 = 冲突」，缺失根本不在判定范围内。

### 3.3 原型已验证

`fact_assert.py`（新增，未接生产链）：

- 4 个历史熔断现场 → 全部放过（`ok=True`）
- 4 类真矛盾 → 全部拦住：比分方向反、比分数值造假、进球数造假、编造对阵
- 空事实卡 → `judged=False`（未判定，不算通过）
- 缺失 → 只降 `coverage`，不拦

自检 `python3 fact_assert.py --selftest` → **11 项全过**；
单测 `tests/test_fact_assert.py` → **12 passed**；3.11 真编译通过。

其中一条是自检抓出来的真 bug：正文里「…只提了 4-0 赢曼联的旧账」，
第一版会把 13 字外的「科莫」当成这条比分的主队，判「科莫进 4 球」。
现规则：**比分两侧只要出现本场之外的球队，就整条跳过**——旧账不是本场事实。

## 四、对标头部：他们不靠阀门数量

数据来自 `docs/benchmark/` 的 181 条真实作品（账号主页抓取，2026-11-01）。

| 账号 | 粉丝 | 样本 | 中位阅读 | 过千率 | 过程锚点 | 疑问句 |
|---|---|---|---|---|---|---|
| 英超那些事 | 15.0 万 | 14 | **5,526** | **100%** | **35.7%** | **0%** |
| 我爱英超 | 10.3 万 | 84 | 1,090 | 56% | 13.1% | 20.2% |
| 西甲二人转 | 23.0 万 | 83 | 77 | 10% | 7.2% | 8.4% |
| 足球记忆FM | 30.7 万 | 80 | 10,008（播放） | 98.8% | 2.5% | 22.5% |
| **我方** | ~0 | 76 | **8** | **0%** | **2.6%** | **85.5%** |

**能观察到的运营做法**（只有输出可观察，内部流程看不到，不猜）：

1. **单事件饱和覆盖**：头部一个事件写 15 篇不同切口，我们 1 篇。这需要的是「同一事实卡的多种角度」，**不是更多校验**。
2. **过程锚点优先于结论**：「让3追4」「第94分钟」——这类内容的事实密度最高，也最容易被事实卡校验覆盖（都是可核对的数字）。
3. **少而精**：中位阅读最高的账号样本量只有 14 条。**他们宁可少发，也不发一条没有锚点的稿。**

**三个不能抄的**：
- 「人工终审」——我们是无人值守，只能靠结构化事实卡替代人的判断，不能靠「多几个人看」；
- 「蹭热点情绪」——需要编辑判断，我们做不了；
- 「账号矩阵互推」——与内容质量无关。

**一个能抄且立刻见效的**：把「一条事实卡 → 多个切口」当成产能来源，
而不是「多个选题 → 各自一套事实校验」。前者事实只核一次，后者核 N 次、错 N 次。

**三个值得抄的设计**：

1. **约束解码（outlines / instructor）**：让模型「只能输出合法结构」，而不是「输出后靠正则修」。
   我们的队名之所以会变成「科莫血洗」，根子是**让 LLM 自由写字符串、我们再去切**。
   改成输出 `{"home": "科莫", "away": "朗斯"}` 且限定必须从实体表取值，这条错误链从源头断掉。
2. **eval 与 gate 分离（promptfoo / deepeval）**：45 项验收里绝大多数是「回归测试」，
   应该在代码变更时跑，而不是每批发布前跑。**这也是 `audit_tiers.yaml` 已经写对、但执行没跟上的一点。**
3. **原子事实（FActScore）**：不要「整篇是否忠实」的布尔值，要「第 N 条断言是否被事实卡支持」。
   这正是 `fact_assert.verify()` 返回 `contradictions[]` 而不是 `True/False` 的原因。

**明确不引入任何新依赖**：真问题是「判据错」和「规则重复」，不是「缺框架」。
引入 guardrails 只会让阀门从 7 道变 8 道。

## 六、优化方案

### 6.1 分层原则：按「错误的可修复性」分级，不按「规则重要性」

| 级别 | 定义 | 处置 | 举例 |
|---|---|---|---|
| **A 不可撤回** | 发出去就收不回 | 发布前硬拦 | 事实矛盾、禁发类型、AI 标识缺失、图片许可 |
| **B 可修复但影响增量** | 差一点，但能发 | 兜底 + 记分，**不拦** | 标题分不足、配图不足、互动引导缺失、事实覆盖度低 |
| **C 口径/接线** | 代码对不对 | 代码变更时跑 | 常量自洽、别名表、标题口径 |
| **D 观察** | 只回答「发生了什么」 | 只记录，不判定 | 漏斗、效果、配额 |

现在的错配：把大量 B 类当 A 类拦（标题分、反洗稿、互动引导），
又让真 A 类漏（比分方向反）。

### 6.2 必须保留的合规保障（6 项，一项都不能删）

| # | 保障 | 依据 | 现状 |
|---|---|---|---|
| 1 | **AI 生成内容标识** | 《人工智能生成合成内容标识办法》2025-09-01 施行，第十条要求发布者主动声明 | `append_ai_annotation` 已在做，保留 |
| 2 | **事实矛盾校验** | 用户核心诉求「不臆造」；平台对不实信息扣分 | 用 `fact_assert` 替换存在性校验 |
| 3 | **禁发类型 + 传闻措辞分级** | 历史回顾类不可撤回；传闻用肯定语气=失实 | `content_mix` / `rumor_wording`，保留 hard |
| 4 | **图片许可与署名** | CC BY/BY-SA 必须署名；错图是事实错误 | `wiki_media` 白名单，保留 |
| 5 | **熔断**（改按篇计、区分误报） | 真系统性失真时唯一能停下来的东西 | 已改为按篇计，保留 |
| 6 | **发布成功 / 无封面** | 读者可见的失败，且无封面 CTR 0.52% vs 2.07% | `publish_success` / `cover_coverage`，保留 hard |

### 6.3 可精简的环节（5 项，按收益排序）

**① 7 道串联 → 2 道硬闸门 + 5 道评分**（收益最大）

```
硬拦（发布前必过）：
  A1 事实矛盾      fact_assert.verify()["ok"] == False → 打回
  A2 合规          content_mix / rumor_wording / AI 标识 → 打回

只记分（不阻断，进 metadata 供 14 天复盘）：
  B1 标题分 < 60        → 照发，记 title_gate.score
  B2 反洗稿相似度超阈   → 照发，记 _similarity（必须落盘）
  B3 信息增量不足       → 照发，记 _increment
  B4 互动引导缺失       → 照发，保存侧注入（已在做）
  B5 事实覆盖度 < 0.5   → 照发，记 fact_coverage
```

依据：B1-B5 失败**不构成违规**，只影响点击率/原创判定；而它们每道都在消耗一次重写额度。
B2 尤其明显——来源是主流媒体、事实卡已锁死，洗稿风险远低于误杀成本。

**② 删掉「正文必须出现队名/比分」的存在性规则**

由 `fact_assert` 取代。这一条直接消灭 4/4 熔断同族问题。
**但不能只删不补**：覆盖度 `coverage` 必须落盘，否则「通篇不提队名」的稿子会静默变多。

**③ 45 项验收 → 发布路径 8 项 + 离线 37 项**

| 层 | 保留在发布路径 | 移到离线 |
|---|---|---|
| pre-publish | `content_mix`、`article_images`、`image_relevance`、`fact_assert`（新） | `batch_quota`、`publish_gate`、`fixture_pool`、`api_budget`、`rumor_wording`、`content_reference`、`differentiation` |
| daily | `publish_success`、`cover_coverage`、`batch_mix`、`effect_loop`、`llm_quota` | `growth_loop`、`perf_ingest`、`performance_import`、`scraper_diagnostics`、`acceptance_metrics` 等 |
| code-change / weekly | 全部离线（本来就不该进发布路径） | 20 + 8 项 |

注意：**「移到离线」不等于删掉**。它们继续在 CI 跑，只是不再决定「这一批发不发」。

**④ 反洗稿：从硬打回改为「打分 + 连续告警」**

保留「连续 3 篇相似度 > 阈值 → 告警」的监测，但单篇不过不再重写。
理由：平台原创判定看的是账号整体，不是单篇；而单篇重写的代价是额度 + 重新掷骰子。

**⑤ 标题 60 分硬线 → 硬违规拦 + 分数只排序**

`title_antipattern`（赛果播报式、纯赛事名词）和 `rumor_wording` 继续硬拦——
这两条有真实回测支撑（命中组零爆款、最高阅读 67）。
但「三要素不足 60 分」不该丢弃整篇：**标题差是点击率问题，不是合规问题**。
现有实现已经在做「只重拟标题 + 事实字段拼接兜底」，方向是对的，只需把最后一档「丢弃」改成「照发 + 记分」。

### 6.4 核心改造：把「必须命中」换成「不得冲突」

`fact_assert.py` 已实现并通过自检，接线只需替换一处：

```python
# orchestrator._rewrite_with_retry 里
- match_passed, match_issues = validate_article_vs_match_data(fixture, art, match_context)
- if not match_passed:
+ res = fact_assert.verify(art, fixture, match_context)
+ art["_fact"] = {"coverage": res["coverage"], "missing": res["missing"],
+                  "suspicious": res["suspicious"]}   # 必须落盘，否则又成黑箱
+ if not res["ok"]:                                    # 只在有矛盾时打回
      last_hint = "; ".join(i["detail"] for i in res["contradictions"])
```

**接线必须走影子模式**（这是本次方案里最重要的执行纪律）：

```
第 1 周：新旧判据并行，新的只记录不拦
        每天产出对照表：新判据会拦的 N 篇 vs 旧判据拦的 M 篇 vs 实际人工看是否真错
        若「新判据会拦、实际没错」出现 → 规则有问题，改规则，不许上线
第 2 周：切换为「新判据拦、旧判据只记录」
        观察 3 批，确认无新增丢稿
第 3 周：删除旧判据
```

没有影子期直接切换，等于把「4 次熔断」的风险重演一次。

### 6.5 落地路线

| 阶段 | 动作 | 验收 | 风险 |
|---|---|---|---|
| **P0（1-2 天）** | `fact_assert` 影子接线；`_similarity/_increment/_fact` 落盘 | 连续 3 批 `contradictions` 为 0 误报；台账字段非空 | 低（不改变放行结果） |
| **P1（本周）** | 反洗稿降为评分；标题「丢弃」改「照发+记分」 | 主稿通道成稿率从 0/4 回到 ≥2/3 | 中（可能短期出现低分标题） |
| **P2（下周）** | 45 项验收分层：发布路径 8 项，其余离线 | 发布路径步骤数下降、daily 硬项全部仍在 | 中（漏看风险，靠 daily 兜） |
| **P3（两周后）** | 解析层收敛：采集只产**结构化事实卡**（队名/比分/球员来自实体表，不从标题切） | 连续 7 天无「队名粘连」类事故 | 高（改采集，需独立灰度） |

### 6.6 不建议做的三件事

1. **不要继续往 `_TEAM_DIRTY_TOKENS` 补词**。赛果动词是开放集合，补一次只挡一次，
   10-13 补了「首发/替补/阵容」，11-05 照样被「血洗」打穿。
2. **不要在发布路径引入 guardrails / NeMo-Guardrails**。它们解决「评测」，不解决「发布」，
   引入后阀门从 7 道变 8 道——与诉求相反。
3. **不要一次性删 37 项验收**。先影子、再切换、最后删；顺序反了就是「用未知换已知」。

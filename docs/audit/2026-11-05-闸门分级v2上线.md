# 闸门分级 v2 上线（2026-11-05 P1 即时生效）

> 用户决定：**P1 马上，今晚的批次按新规则处理**。不等影子模式观察一周。
> 因此本轮的重点不是「放松」，而是**把放松做成可回滚、可对照、有保险丝**。

## 一、改了什么

一次尝试内的 7 道串联与门 → **2 道硬闸门 + 5 类只记分**。

| 判据 | 旧 | v2 | 依据 |
|---|---|---|---|
| 事实矛盾（比分方向/数值、进球数断言、编造对阵） | 硬 | **硬** | 直接违反「不臆造」 |
| 合规（禁发类型、传闻断言、AI 标识） | 硬 | **硬** | 违反即扣分/封号 |
| 名字缺失（正文没写球员/队名） | 硬 | 记分 | 用「他们」「主队」指代是正常写法 |
| 反洗稿（相似度/信息增量） | 硬 | 记分 | 只影响增量（有没有人看） |
| 标题评分（及格线 60） | 硬（重拟→丢弃） | 记分 + 三要素兜底 | 丢弃换来的不是质量，是当天少一篇 |
| 互动引导 | 硬（末次放行） | 记分 | 保存侧本来就有模板注入 |
| 字数 | 硬 | 记分 | 提示词已约束，硬拦只会逼注水 |

**「按语义分级，不按判据名分级」**是本轮唯一不能让步的原则。旧判据
`validate_article_vs_match_data` 同时产出两类问题：

- `缺少客队名: 利物浦` —— 存在性，正文用「利物浦」以外的说法就误杀；
- `卡外比分 9-0` —— 数值冲突，就是臆造。

整条降成记分会把后者一起放掉。上线自检时 `test_degrade` 正是拿
「卡外比分」当样本，一降就放过去了。故新增 `LEGACY_CONFLICT_MARKERS`：
旧判据里带矛盾类措辞的 issue，在 v2 下**仍是硬闸门**。

## 二、可回滚

```bash
GATE_MODE=strict   # 环境变量，回到旧的 7 道与门口径
```

不需要改代码、不需要回滚提交。**默认 v2**。

strict 模式下 `fact_assert` 仍会跑（回滚只恢复旧口径的严格度，
不是关掉事实校验），两者任一判定有问题都拦。

> 自检发现过一次 strict 漏拦：分支写成 `elif not hint`，而 fact_assert 有矛盾时
> hint 已非空 → 该分支永远进不去。**回滚开关失灵等于没有回滚**，已改为显式赋值。

## 三、两道保险

### 1. 旧判据照跑，结果落 `_gate.legacy`

v2 下旧判据**不被删除**，照常执行，结果写进 metadata：

```json
"_gate": {
  "fact": {
    "mode": "v2",
    "judged": true,
    "contradictions": [],
    "legacy_issues": ["缺少客队名: 利物浦"],
    "legacy_conflicts": []
  }
}
```

「新判据放过了谁、旧判据本来会拦谁」每天可查。没有这份对照，
「放松了多少」就只能靠回忆——而「有结论没留证据」正是发布率 38%
一个月无人发现的原因。

### 2. 批内矛盾配额（首日保险丝）

`fact_assert` 是首日上生产的新判据。若它系统性误报，后果与旧熔断相同：全批停发。

```python
MAX_CONFLICT_SUBJECTS = 3   # 本批被判矛盾的不同选题超过 3 篇 → 剩余改记分
```

触发后 `_gate.fact.fail_open` 写明原因，同时打日志。同一选题重试只算 1 篇
（10-25「热刺1-1曼联」那篇重试三次曾被算成三篇）。

**只在 v2 生效**：`GATE_MODE=strict` 时该停就停。

## 四、其余记录

- 空事实卡 → `judged: false`：不拦，也不记成通过（未判定 ≠ 通过）。
- 判据自身抛异常 → 只记 `error`，不阻断发布（闸门坏了不许替人做决定）。
- `degrade` 阶段名保留「一致性校验」（统计维度改名会让历史数据断档），
  detail 写「事实矛盾·…」。
- metadata 新增 `_gate` / `_title_score` / `_anti_copy` / `_fidelity` /
  `_interaction` / `_consistency`。

## 五、首日观察项（18:00 evening 批次）

1. `_gate.fact.judged` 为 true 的比例——若大量 false，说明事实卡供给有问题，
   等于事实校验形同虚设。
2. `legacy_issues` 非空但 `contradictions` 为空的篇数——这是「新口径放过的误报」，
   预期 100%，否则说明还有残留的存在性判据。
3. 是否触发 `fail_open`——触发即代表判据有系统性问题，需立刻人工看那几篇。
4. 成稿数与新闻改写通道篇数——旧口径下 4 次请求 0 成稿，v2 应恢复供应。

## 六、明确不做

- **不继续补脏词表**：赛果动词是开放集合，补一次只挡一次（10-13 补「首发/替补」，
  11-05 被「血洗」打穿）。
- **不在发布路径引入 guardrails 一类框架**：那是把阀门从 7 道变 8 道，与诉求相反。
- **不一次性删掉 37 项离线验收**：它们不阻断发布，先留作观测。

## 七、首日实跑记录（18:00 evening 批次，失败）

批次确实按 v2 跑了（日志可见 `降级[反洗稿记分]`、`降级[一致性校验]：事实矛盾·…`），
但**整批 exit 1，未发布**。两个根因，都不是「新规则太严」这个笼统说法：

| # | 现象 | 根因 | 性质 |
|---|---|---|---|
| ① | `NameError: name 'topic' is not defined` → 整批 exit 1 | `orchestrator.py:5905` 预测稿配图调用 `_img_topic({...}, pred_art, topic, ...)`，凭空引用该作用域不存在的 `topic`（11-04 引入）。此前 evening 要么没未来赛程、要么预测稿失败，**从没执行到这一行**；今天 40 场未来赛程 + 预测稿成功 → 首次执行即崩 | 潜伏 bug，与 v2 无关 |
| ② | `科莫 1-0 朗斯，事实卡是 朗斯 1-9 科莫` → 整篇丢弃 | 正文同时写本场（1-9）与历史交锋（上赛季 1-0），我把历史比分也判成本场矛盾 | **v2 判据误报，最该防的形态** |

### 修法

1. 删掉 `_img_topic` 里多余的 `topic` 参数（`*cands` 本就接受任意个候选）。
2. 比分判据改为**先看本场有没有写对**：
   - 本场比分已正确写出 → 其余对不上的比分记 `suspicious`（疑为历史交锋），不拦；
   - 通篇没有一个对得上 → 才算把本场写错，拦；
   - 单侧归因（只认出左边或右边一支队）数值不符 → 只记 `suspicious`。
3. 改写路径的 `except` 补 `traceback.print_exc()`——原先只留 `str(e)[:60]`，
   第 2 篇的 `'int' object has no attribute 'get'` 因此完全无法定位。

### 没能补发

- 18:30 / 18:50 两个兜底 cron **均未触发**（GitHub schedule 今晚整批丢失）。
- 环境无 GitHub token，无法 `workflow_dispatch` 手动补发。
- `batches_completed` 仍是 `['morning','noon']`，幂等标记没拦——是 cron 根本没跑。

**这暴露一个监控盲区**：主调度失败 + 兜底 cron 被丢 = 整批归零，而失败告警只在
「跑了但失败」时发。「今晚根本没跑」没有任何告警路径。

### 复核（19:05，关键结论：红叉跑的是修复前的代码）

差点把这条红叉读成「修了没用」。查 run 元数据才发现**时间差**：

| 事件 | 时间（CST） |
|---|---|
| 批次触发（workflow_dispatch） | 18:00:50 |
| 批次所用 `head_sha` | `9ee9668`（09:55 提交，**不含修复**） |
| 修复 `74c92d6` 提交 | **18:19:33（比批次晚 19 分钟）** |

步骤级证据（run `42007122553`）：第 18 步「生成文章」failure，10:07:01→10:10:05（3m04s）；
第 19–28 步验收照跑（因为 `if: always()`），**第 29 步合规熔断复核与第 30 步发布
`skipped`**，第 37 步失败通知 success（所以手机上收到了告警）。整批 0 篇。

修复有效性另做三项复核（不靠「我觉得改了」）：

1. 调用点：`orchestrator.py:5906` 现为 `_img_topic({...}, pred_art, match_data=...)`，`topic` 已删。
2. AST 扫全仓 9 个 `_img_topic` 调用点：位置参数 2–4 个不等，但签名是
   `def _img_topic(topic, *cands, match_data=None)`，**可变参数**，个数不设限 —— 用
   「位置参数个数 ≤ 形参个数」这种文本/半 AST 判据会误报 4 个「越界」，别拿它当门禁。
3. `test_fact_assert / test_gate_v2 / test_team_result_verbs` → **40 passed, 26 subtests**。

CI 现状：`a5946e2` 上「单元测试」「计划结构不变量验收」均 success；其后三个提交
（`28ecef4` / `5fbee03` / `7c4ed88`）只有 docs、`data/audit` 与 merge，**无代码变更**。

额度：`deepseek-v4-flash-202605`(802k)、`deepseek-v4-pro-0813`(865k) 已触本地硬上限
800k 被跳过，实际可用只剩 `0731`（余 ≈31.7 万 token）。够 2 篇，但**不够反复重试**——
补发只点一次，别连点。

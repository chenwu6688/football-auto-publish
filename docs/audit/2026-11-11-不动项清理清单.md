### 1.2 `_compute_phash` → **直接删除**

- **调用情况**：定义 `image_service.py:118`，唯一调用点 `image_service.py:230`，随返回值以 `"phash"` 键带出。全仓除自身与测试外**零消费者**。
- **更关键的是它连落盘都没有**：`output/*/metadata.json` 里 `"phash"` 出现 **0 次**、`"md5"` 也 **0 次**——产物只存 `local_path` 字符串。算完即丢，连「留给以后用」的数据积累都不存在。
- **实际去重**走 MD5，且 `existing_hashes = set()` 是 `download_article_images` 内的局部集合（`image_service.py:265`），同一篇内生效。
- **运行依赖**：Pillow。本函数是全仓唯一的 `getdata()` 调用点（`getdata` 自 Pillow 13 弃用、Pillow 14 移除，requirements 是 `Pillow>=10.0` 无上限）。
- **删除理由**：零消费者 + 零落盘 + 删掉后全仓再无 Pillow 14 定时炸弹。修（`tobytes()`）是次优解，删是更彻底的解。
- **删除影响**：`tests/test_image_phash.py` 全部 12 条用例围绕它（与 `download_article_images` 的 default-dir 回归）→ 建议改为 **1 条 AST 守卫**「全仓不得出现 `getdata()` 调用」。

### 1.3 `match_scheduler` → **直接删除**

- **调用情况**：110 语句、47% 覆盖；生产代码 **0 处 import**，全仓仅 3 处提及：自身 CLI、`README.md:291` 目录树、`tests/test_match_scheduler.py`（6 例）。
- **产物追溯**：其 `save_schedule()` 默认写 `output/schedule/match_schedule.json`——**该目录不存在，从未生成过**。文档声称「供 orchestrator 读取」，orchestrator 里没有任何相关读取。
- **运行依赖**：`constants.FOOTBALL_DATA_KEY` + football-data.org HTTP（本机无此 Key，未覆盖的 58 行全在 `fetch_upcoming_matches` 41-118 的网络段）。
- **功能已被完全替代**：`scripts/fixture_library.py`（计划第一阶段核心）负责同样的 14 天赛程预取，且额外做 API 额度记账、认知度分级、时效闸门，产物 `data/fixtures/topic_pool.json` 才是 `data_collector.deterministic_supply` 真正读的东西。
- **额外风险（决定性的）**：它直连 football-data.org 却**不经 `api_budget` 台账**。哪天真接进流程，就是「额度账本少记 = 按量扣钱」——事故谱系第 ① 条的原样复现。
- **删除影响**：-110 语句 / -6 用例 / 生产覆盖率 +0.1pp / CI 无任何引用（`batch.yml` 不跑它），无需改 workflow。
- **同步点**：删 `README.md:291` 那一行。

### 1.4 五个 rc=2 验收脚本 → **全部保留**

先说清一件事：**rc=2 不是「脚本废了」，是「本机没有判定证据」**。这五个在 CI 里都在跑，四个是「只告警不阻断」，两个（compliance / image_relevance）是发布阻断件。

| 脚本 | 本机 rc=2 的真实原因 | 运行依赖 | CI 位置与是否阻断 | 对发文流程的作用 |
|---|---|---|---|---|
| `verify_compliance.py` | `report["articles"]==0`：成稿 `.md` 不入库，本机读不到正文；或 block 级规则判过不足半数 | 成稿 md / `metadata.json` 回放 | `batch.yml`（`--days 1 --drop-violations`，**阻断**）；`daily-result.yml`（`--from-ledger --offset 1`，结论回放） | **合规唯一入口**：`orchestrator.py:59` 直接 import 作生成侧判定，发布前逐篇剔除 |
| `verify_fixture_pool.py` | `data/fixtures/topic_pool.json` 不存在（本机未跑 `fixture_library.py`） | `FOOTBALL_DATA_KEY` / `API_FOOTBALL_KEY` / 聚合数据 + 网络 | `batch.yml`（只告警）+ `fixture-pool-verify.yml`（定时） | 确定性供给（约 30% 稿源）的原料质检：五类覆盖 / 单日候选≥6 / 前瞻体为 0 |
| `verify_gallery_entities.py` | 无 `PEXELS_KEY` → 联网实测项 `skip` → `pending` → rc=2 | `PEXELS_KEY` + 网络 | `weekly-audit-health.yml`（只告警） | 图库层（第 3 层配图）实体白名单能否命中 |
| `verify_image_relevance.py` | `rep["ok"] is None`：窗口内没有本机可读的成稿+图片产物 | 正文 md + `output/<date>/images` | `batch.yml`（`--fail-on-hard-only`：硬项 exit 1 **阻断**，产物相关性只告警） | 图文相关性闸门：`orchestrator` import 后逐篇处置，画假图/残留图/未接线属硬项 |

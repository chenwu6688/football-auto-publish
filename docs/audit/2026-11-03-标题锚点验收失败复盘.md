# 标题锚点验收失败复盘（P0-1，2026-11-03）

> 复现命令：`PYTHONPATH=. /usr/bin/python3 scripts/verify_title_anchor.py --days 7` → 退出码 1  
> 唯一未过硬项：**锚点覆盖率 0/5 = 0.0%（目标 ≥40%）**  
> 本文件只做诊断与方案，不含任何判定放宽。

---

## 一、一句话结论

**不是生成侧没写过程，是测量侧认不出来。**

生效日后 5 篇被判样本里，有 4 篇标题里明写了过程——「站满90分钟」「九人苦撑」「染红」  
「换人失误葬送」「赛前加练到凌晨」——词表**一条都没认出来**。补词表后覆盖率 0% → 60%~80%。

但只改词表，下周还会以别的方式红。本次同时暴露出两个设计缺陷：

1. **判定在样本量阈值两侧行为相反**：n=4 静默通过，n=5 硬失败；
2. **生成侧对锚点没有任何逐篇压力**：及格线 60 分，没锚点也能拿 65 分，`repick` 永不触发。

## 二、事实：先把样本数说清楚

报告里写「样本 5 篇」，但 `output/2026-11-02` 和 `2026-11-03` 的 `metadata.json` 里一共 6 篇。  
差额来自 `template_gate.recent_titles` 的口径——**预测稿不进标题口径**：

| 日期    | 标题                            | `is_prediction` | 进口径   |
| ----- | ----------------------------- | --------------- | ----- |
| 11-02 | 巴萨更衣室还在笑，维拉队长赛前加练到凌晨憋的到底是什么   | False           | ✅     |
| 11-02 | 利物浦主场哑火吞零蛋，阿森纳这次把悬念提前掐灭       | False           | ✅     |
| 11-02 | 费耶诺德主帅场边站满90分钟，国际米兰还没换人他先动了三次 | False           | ✅     |
| 11-02 | 德尔加多挥拳染红致歉，大连九人苦撑3-4，绝无冒犯更刺耳！ | False           | ✅     |
| 11-02 | 欧冠大戏巴萨曼联拜仁全来了，这四场不熬夜真亏        | **True**        | ❌ 预测稿 |
| 11-03 | 半场零封后崩盘，纽卡换人失误葬送好局，埃弗顿一箭封喉    | False           | ✅     |

口径本身没问题（预测稿不发布，不该进标题质量统计）。但它带出一个副作用：  
**11-02 这一天实际只有 4 篇真稿，7 天窗口里累计 5 篇，正好压在 `MIN_SAMPLE=5` 的临界线上。**  
下面 R2 会说明，就是这条线把「样本不足」直接切换成了「硬失败」。

### 逐条判定：过程写在标题里，词表没认

| 标题                                | 标题里的过程          | 当前判定 | 缺口                                |
| --------------------------------- | --------------- | ---- | --------------------------------- |
| …赛前加练到凌晨…                         | 赛前加练到凌晨（准备过程反常） | ❌    | 13 类里**没有「赛场外过程」这一类**             |
| 利物浦主场哑火吞零蛋…                       | 无（赛果陈述）         | ❌    | **真无锚点**，不该硬凑                     |
| 费耶诺德主帅场边**站满90分钟**…**还没换人**他先动了三次 | 全程在场 + 换人时机     | ❌    | ①`第N分钟` 要求有「第」；②`换人见效` 只收正向结果词    |
| 德尔加多挥拳**染红**致歉，大连**九人苦撑**3-4      | 红牌、少打一人         | ❌    | ①只认 `9人`（ASCII），不认「九人」；②`染红` 不在词表 |
| 纽卡**换人失误葬送**好局                    | 换人失败            | ❌    | `换人见效` 只收 `见效/奏效/改变/翻盘`，负向全漏      |

4 篇有过程、1 篇确实没有。**0/5 是测量结果，不是生产结果。**

## 三、根因（三层，逐层给证据）

### R1｜词表是从 3 个爆款逆推的「具体枚举」，不是按过程类型做的正交分类

`title_features.PROCESS_ANCHOR_PATTERNS` 的 13 类，每一类后面都标注了出处（「让3追4」「第94分钟」  
「球迷第80分钟退场」——同一篇对标文章里的 3 个例子）。这种写法有个隐性代价：  
**它枚举了那 3 个爆款的字面形态，而不是「过程」这件事的类型。**

于是出现四个系统性缺口，全部是「同一语义、不同写法」：

| 缺口     | 词表写法                         | 真实写法           | 本质                        |
| ------ | ---------------------------- | -------------- | ------------------------- |
| 中文数字   | `9人\|10人应战`                  | 九人苦撑、十人应战      | 与 10-24「`0-1` vs `0比1`」同源 |
| 必须有「第」 | `第\d+分钟`                     | 站满90分钟、踢了66分钟  | 只认一种句式                    |
| 换人单向   | `(换人).{0,6}(见效\|奏效\|改变\|翻盘)` | 换人失误、还没换人、迟迟不换 | **只写了正面结局**，负向与时机全漏       |
| 赛场外    | 无                            | 赛前加练到凌晨、通宵开会   | 整类缺失                      |

**为什么自检 18 项全过却没发现？** 因为 `title_features.selftest()` 的用例和词表是**同一批、同一人、  
同一时刻**写成的——用例只覆盖词表已经想到的形态，等于自己判自己。这和 `verify_content_mix`  
首版只比 `BANNED_TYPES`（把「历史回顾」加回 `SOFT_TYPES` 仍全过）是同一类失效：  
**判据与被判对象同源，校验就退化成复读。**

### R2｜判定在样本量阈值两侧行为相反（这是最该修的一条）

`check_anchor_coverage()` 现在的逻辑：

```python
if cov["n"] < MIN_SAMPLE:                    # MIN_SAMPLE = 5
    return {"ok": True, "advisory": True}    # ← 样本不足 = 通过
...
ok = pct >= TARGET_ANCHOR_COVERAGE           # n>=5 才真判
```

而 `verify()` 里 `hard = [c for c in checks if not c.get("advisory")]`——advisory 项**既不算失败也不算通过**，  
报告结论却写着「通过 ✅」。于是：

- 某天只有 **4 篇**真稿 → 「跳过/告警」，整体判**通过**；
- 某天有 **5 篇**真稿且全是 0 锚点 → 整体判**失败**，CI 红。

**同一份真相，4 篇通过、5 篇失败。** 判定对样本量不单调，这是逻辑缺陷，不是口径争议。

再叠加统计粒度：

- n=5 时 40% 的目标等价于「至少 2 篇有锚点」，**单篇翻转 20 个百分点**；
- 若真实达标率恰好 40%，n=5 时「一篇都没命中」的概率 = 0.6⁵ = **7.8%**；n=10 降到 0.6%，n=14 降到 0.08%。

也就是说，**一个完全合规的流水线，用 n=5 判定，每天仍有约 1/13 的概率被判失败。**  
配上 11-02 是改造首日（新 prompt 只跑了一天），这次红几乎是必然事件。

### R3｜生成侧没有逐篇压力：锚点是「加分项」，不是「竞争项」

`score_title_plan` 的采纳逻辑是 `passed = score >= 60`，docstring 原文写着  
「及格线，不做择优漏斗」。而分数构成是：

```
字数达标 25 + 含主客队 25 + 板块保底 15 = 65  → 无锚点也已过线
过程锚点 +30（fixture）/ +15（plan）         → 把 65 变成 95，但 95 和 65 待遇一样
```

`repick_title()` 只在 **<60 分**时触发。所以：**没有任何环节会让一篇 65 分的无锚点标题被重写。**  
锚点覆盖率高不高，完全取决于模型当天自觉不自觉。

这正是项目自己记过的那条教训——「规则只写在提示词里、没有任何生成后校验」。  
本次是它的加强版：**校验写了，但校验只看 0/1 及格，不看「够不够好」。**

## 四、修改方案

### P0-1｜补齐四类词表缺口（纯测量修复，不改判定口径）

`title_features.PROCESS_ANCHOR_PATTERNS`，改动点已按上表四条对齐：

| 类别             | 现正则                                     | 改为                                                                            | 说明                         |
| -------------- | --------------------------------------- | ----------------------------------------------------------------------------- | -------------------------- |
| `第N分钟`         | `第\s?\d{1,3}\s?分钟`                      | `(第\s?\d{1,3}\s?分钟\|(?:站\|踢\|打\|守\|撑\|熬\|跑\|枯坐\|坐)\s?满?\s?\d{1,3}\s?分钟)`      | 要求「动作词 + 分钟」，避开通篇讲时长的标题    |
| `红牌/罚下`        | `(红牌\|罚下\|两黄\|9人\|10人应战\|少打一人)`         | `(红牌\|罚下\|两黄\|染红\|(?:9\|10\|8\|九\|十\|八)\s?人(?:应战\|苦撑\|硬扛\|作战\|撑完\|踢完)\|少打一人)` | 中文数字必须**带谓词**，挡住「九人轮换」     |
| `换人见效` → 拆两类   | `(换人\|替补席\|临场调整).{0,6}(见效\|奏效\|改变\|翻盘)` | 保留原名不变，正向词不动                                                                  | 不破坏既有语义与历史可比性              |
| **`换人时机`（新增）** | —                                       | `(换人\|变阵\|临场调整).{0,6}(失误\|葬送\|太晚\|迟到\|失败)\|(?:还没\|迟迟不\|未\|不肯)换人`              | 负向与时机独立成类，便于后续分开做 CTR 回流   |
| **`赛前异动`（新增）** | —                                       | `(加练\|通宵\|凌晨.{0,6}(加练\|训练\|抵达\|开会)\|赛前.{0,4}(密谈\|开会\|加练))`                    | 赛场外过程。**刻意不收裸「熬夜」**——见下方误报 |

> **误报拦截（我自己踩到的）**：初版把裸 `熬夜` 收进 `赛前异动`，结果  
> 「欧冠大戏巴萨曼联拜仁全来了，这四场**不熬夜**真亏」被判成有锚点。  
> 那是劝读者别熬夜，不是比赛过程。已删除，只保留「通宵」「凌晨+训练/抵达」。  
> 这条必须写进自检的**负向用例**，否则下次还会犯。

改完是 **15 类**（13 + 2）。三处必须同步，缺一处 `verify_title_anchor` 的「config 与代码类别一一对应」硬项就会红：

1. `title_features.PROCESS_ANCHOR_PATTERNS`（唯一正则来源）
2. `config/title_antipattern.yaml` → `规则三.锚点类别` 追加 `换人时机`、`赛前异动`
3. `tests/test_title_features.py` + `title_features.selftest()` 追加真实用例

### P0-2｜修判定的单调性（不解禁、不放宽目标）

目标仍是 40%，不改。改的是「样本不足时怎么说话」——从两态（pass/fail）换成**三态**：

```python
MIN_SAMPLE = 5       # 硬判所需最小样本（不动，避免同一次提交里既改尺子又改读数）
ROBUST_SAMPLE = 10   # 5~9 篇照判，但标「样本偏薄，仅供趋势」
CUM_MIN_SAMPLE = 30  # 生效日累计 ≥30 篇且从未达标 → 直接 FAIL

if n < MIN_SAMPLE:
    return {"ok": None, "pending": True, ...}   # 未判定：既不是通过也不是失败
if cum_n >= 30 and cum_pct < TARGET:
    return {"ok": False, ...}                   # 堵「永远样本不足」的永久豁免
```

配套：`verify()` 把 `hard_failed` 与 `pending` 分开统计，`ok = not failed`；
`render_md` 里 pending 显示 **⏸ 未判定（≠ 通过）**，CI 另打一行 `::warning::`。
**`None` 不等于 `True`**，这是本次 bug 的根。

> **为什么没把 `MIN_SAMPLE` 提到 10**（原方案如此）：那样今天会变成「未判定」，
> 就分不清转绿是因为词表修对了、还是因为阈值挪开了。**一次提交只改一个变量**——
> 词表先修，等观察窗攒到 n≥10 再单独评估阈值。n=5 的结论会标 `thin=True` 提示仅供趋势。

### P0-3｜实际落地的改动（本次已实施）

| 文件 | 改动 |
|---|---|
| `title_features.py` | 词表 13→**15 类**；`第N分钟` 补「动作词+时长」、`红牌/罚下` 补中文数字与「染红」、新增 `换人时机`、`赛前异动`；selftest 18→**30 项**（含 4 条负向） |
| `config/title_antipattern.yaml` | `锚点类别` 追加 2 类，注明与代码一一对应 |
| `scripts/verify_title_anchor.py` | 三态判定 + `ROBUST_SAMPLE` / `CUM_MIN_SAMPLE` 两条护栏 |
| `tests/test_title_features.py` | +9 条（5 正 4 负，正例全取真实成稿） |
| `tests/test_title_anchor_verify.py` | 新增 8 条：样本不足≠通过、4 篇与 5 篇方向一致、累计硬线、pending 不得渲染成 pass |
| `orchestrator.py` | 注释里的类别数同步（仅文档字符串） |

**实测结果**：`锚点覆盖 4/5 = 80.0%`，命中类别 `换人时机×2、赛前异动×1、第N分钟×1、红牌/罚下×1`；
对标样本不受影响（英超那些事 35.7→**35.7**、我爱英超 13.1→16.7、西甲 7.2→7.2、
足球记忆FM 2.5→2.5、我方 30 天历史稿 3.6→4.8）；单测 1357→**1374**。


### P1｜让锚点变成竞争项（建议与 11-16 复盘一起做）

`repick` 现在的触发条件是「分数 <60」。建议加**第二个触发条件**，不动及格线：

```
若 score >= 60 且 anchor_kinds 为空 且 事实卡里存在可用的过程事实（进球时间/红牌/换人）
  → 触发一次 repick_title（只重写标题，正文不动），
    且只在「新标题有锚点」时才采纳，否则保留原稿。
```

为什么这样改安全：`repick_title` 已经把事实边界焊死（只准重排原标题与选题里已有的人名/数字/时间），  
失败返回 `None` 走原兜底。它不会为了凑锚点去编一个「第94分钟」。

同时把事实卡里的过程事实**显式喂进标题 prompt**（进球时间列表、红黄牌、换人），  
现在模型只能从正文里自己找，找不到就退回赛果陈述。

## 五、改后必须验证的场景（缺一项就可能又红一次）

| # | 场景                  | 判据                                                                                       | 为什么必须验                                                          |
| - | ------------------- | ---------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| 1 | 11-02/11-03 真实 5 篇  | 3/5（60%）或 4/5（80%），均 ≥40%                                                                | 直接决定本次能否转绿                                                      |
| 2 | **对标样本不塌陷**：181 条重算 | 英超那些事仍 35.7%（±0）、我爱英超 13.1→16.7、西甲 7.2→7.2、足球记忆FM 2.5→3.8                                | 若头部账号一放宽就冲到 60%，说明 40% 目标失去可比性，得重定标                             |
| 3 | 我方 30 天历史稿（84 篇）    | 3.6% → 4.8%，**不得大幅上涨**                                                                   | 若历史稿也涨到 30%，说明新词表在「认旧句式」，指标失去区分度                                |
| 4 | 误报逐条过目（345 条）       | 每条新增命中都要人工看一眼                                                                            | 实测：`第N分钟`扩 1 条（踢66分钟，真）、`红牌`扩 4 条（全是染红，真）、`换人时机` 0 条、`赛前异动` 1 条 |
| 5 | 负向用例（单测硬断言）         | 下列必须**不**判锚点：九人轮换、满90分钟的比赛、凌晨三点的机场、换人后失误                                                 | 中文数字与裸分钟是误报重灾区                                                  |
| 6 | 阈值两侧单调性             | n=4 与 n=5 结论方向一致（都不判失败）                                                                  | R2 的回归测试，用合成目录构造                                                |
| 7 | 全量验收 + CI 复跑        | 31 个 verify 脚本 `$?` 全 0（`verify_fixture_pool` 本地返 2 除外），`git checkout -- data/audit` 清漂移 | 硬项改动极易带偏别的脚本                                                    |

> 判据 2 和 3 是这次复盘的**方法论产出**：任何放宽词表的改动，都必须同时证明  
> 「头部涨得少、我方历史不涨」——否则就是在把尺子做松，而不是把内容做好。

## 六、不算改动的三件事（防止下次「为了变绿」）

1. **不降目标**。把 40% 改成 10% 能让报告立刻变绿，但那是把尺子改短。
2. **不加 `|| echo` 软化**。CI 里已经吃过「`|| echo` 让每批跑完必红」的亏。
3. **不动 `TITLE_SINCE`**。把生效日往后挪一天也能变绿，但等于把改造首日的问题藏起来。

## 七、建议节奏

| 时间            | 动作                                                                         |
| ------------- | -------------------------------------------------------------------------- |
| 今天            | P0-1 词表（15 类）+ P0-2 判定单调性 + 9 条单测（5 正 4 负）+ 重跑 7 项验证                       |
| 11-04 ~ 11-15 | 观察窗，`verify_title_anchor` 每天跑，看覆盖率趋势而不是单日结论                                |
| 11-16 20:00   | 复盘时看的是**锚点覆盖 vs CTR**，不是覆盖率本身。锚点 60% 但 CTR 仍 0.95% → 说明瓶颈不在标题，P1 的择优改造就不该做 |

**「赛前异动」已按「计入但独立成类」落地**（4/5=80%；不计则为 3/5=60%，两种都过线）。
独立成类的目的是 11-16 之后能分开看「赛场内过程」与「赛场外过程」的 CTR——
若前者有效、后者无效，就该把它从锚点里摘出去，而不是让两类互相稀释。

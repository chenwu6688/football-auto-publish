# 2026-11-05 封面方框图 / 蓄水池标题准入（noon 批次复盘）

## 用户看到的现象

noon 批次 3 篇都发出去了，台账 `published_without_cover = 0`、每篇 `images = 1`，
但用户反馈「图片还是有问题」。把 CI 自己渲染的卡片取回来一看：**两篇封面是黑底
加一排 □□□□** —— 汉字一个都没画出来。

| 篇 | 供给层 | 图片 | 封面实际内容 |
|---|---|---|---|
| 1 瓦伦西亚主帅先动…皇马27分这趟客场不好踢 | 一级·确定性 | 1 张（Commons，Valencia CF） | 真图 ✅ |
| 2 当年那个追风少年如今发福谢顶… | 三级·软性（蓄水池） | 1 张（数据卡） | 黑底 + 方框 ❌ |
| 3 老六心中的历史射手榜：巴蒂C罗领跑… | 三级·软性（蓄水池） | 1 张（数据卡） | 黑底 + 方框 ❌ |

## 根因一：CI 没有中文字体，Pillow 静默退化成位图字体

`cover_card._font()` 的候选表全是「本机才有」的路径（`/usr/share/fonts/opentype/noto/...`），
在 `ubuntu-latest` 上一个都不存在，于是退回 `ImageFont.load_default()`。这个内置位图字体
**没有汉字字形**，`draw.text("球评人老六")` 画出来是一排 `.notdef` 方框——而 `render()`
认为成功、返回路径、台账记 1 张图、发布端照常上传。

复现证据：一次性诊断 workflow 在 CI 上直接调 `cover_card.render()`，产出
`docs/audit/assets/2026-11-05-封面方框图-CI实测.jpg`（整张卡只有一排 □）；
本机同一份代码渲染出来是正常中文。也就是说这条链路**本机永远测不出来**，
和 11-05 早上的 py3.11 语法事故是同一类：「本地绿、CI 错，但错得静默」。

修法（三层，缺一层就会复发）：

1. `_font()` 找不到能画汉字的字体时抛 `NoCJKFont`，`render()` 返回 `None` 并写
   `cover_card.LAST_ERROR`。宁可回到「无封面」（有台账），也不发布方框图。
2. 字体发现不写死路径：候选表之后再用 `fc-match :lang=zh` 问系统，并用
   「中 / 〇 位图是否相同」粗判字体是否真有汉字字形（DejaVu 会判成没有）。
3. CI 装 `fonts-noto-cjk`（`batch.yml` / `unit-tests.yml`），装完当场
   `python3 cover_card.py --fontstatus` 自检；单测里**静态断言这两行存在**，
   防止「本地有字体、CI 没字体」再次静默复发。

顺带把数据卡从「黑底白字」改成信息图版式：渐变底 + 栏目胶囊 + 左侧红竖条 +
数字标签行 + 来源标注，避免「看着像占位图」。

## 根因二：蓄水池稿一律不配图（`images_map[...] = []`）

转正分支里写死了空列表，所以软性稿 100% 落到数据卡。现在改成和主稿一样走
`_img_topic` + `search_images`：有实体才配图（C罗/巴蒂这类能命中维基/Commons），
无实体仍是 0 张 → 数据卡兜底。「宁可不配图也不放随机图」的口径没变。

## 根因三（顺带发现）：蓄水池旧标题绕过标题闸门，把发布闸门刷红

修完前两条跑全量验收，`verify_publish_gate` 从 0 变 1：noon 发布的两篇软性稿标题
（「…你的青春还能找回吗？」「…谁才是你眼中的最强？」）落在 `GATE_SINCE = 2026-11-05`
之后，被判「疑问收尾超限」硬违规。往上追是三层：

1. `refill_reservoir` 的 prompt 明写「标题 26-30 字，套用公式…+ **疑问收尾**」——
   等于在生产端批量制造空问标题（这正是 11-01 头部对标后明令放弃的形态：
   85.5% 的标题成了「他到底图个啥」，中位阅读 8）；
2. 备货时调 `score_title_plan` **不传 `recent_titles`**，靠「14 天疑问收尾 ≤2 篇」
   判的那条规则永远不触发（分数看着及格，规则其实没跑）；
3. 转正时完全不过闸门，10-11 存进来的标题直接发出去。

修法：prompt 改成陈述句 + 过程锚点；备货评分带真实历史标题；**入库前过闸门**
（不过不入库）；**转正前过闸门**（`reservoir.fill_gap(accept=...)`，不过则留池标
`rejected`，不占配额、不重复重试）。实测：旧存量 9 条全部不过（都是空问），
新 prompt 生成的 2 条分别是 65 / 77 分，能过。

存量口径：这两篇的标题是 10-11 入库的，`verify_publish_gate` 现在用蓄水池台账的
`stocked_at` 作证据，把「入库早于生效日」的标题单列留证、不计退出码——与封面台账
「按兜底生效日判、旧链路样本单列留证」同一口径，不是手写豁免名单。

## 验收

- 真 3.11：`compileall -q .` = 0。
- 单测 **1580 passed / 94 subtests**（新增：无字体不许出图 3 项、CI 装字体 3 项、
  蓄水池配图接线 1 项、蓄水池准入 4 项、补货 prompt/评分 5 项、存量证据 3 项）。
- 43 项 verify：**40 返 0 / 3 返 2**（`fixture_pool`、`gallery_entities` 无 Key，
  `wiki_media` 本机维基不通 —— 都是「未判定」不是失败）。
- `verify_cover_coverage` 新增负向：把字体探测清空后 `render()` 必须返回 None
  且不留半张图；本机字体可用性单独报（缺字体只标「未判定」，不冒充通过）。
- 下一批应观察：`degrade_events` 里「封面兜底」原因是否变成「数据卡生成失败」而非
  静默；软性稿是否开始出现真实配图；`data/reservoir` 里旧条目是否被标 `rejected`。

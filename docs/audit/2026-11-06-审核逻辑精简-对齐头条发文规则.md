# 审核逻辑精简：对齐头条号发文规则（2026-11-06）

> 唯一目标：**遵守头条号发文规则、避免被扣分**。
> 本文回答四件事：① 平台规则是什么；② 现有各环节在做什么、是否必要；
> ③ 删了什么、为什么；④ 留了什么、为什么。

## 一、平台规则：一张以「扣分」为刻度的表

信用分满分 100，扣到 **60 分及以下自动取消分成权益**，扣到 **0 分封号**
（《信用分机制》，2026 年公告把门槛从「<60」改为「≤60」，并把「回升至 100 分才能
重新申请」放宽为「>60 即可申请」——方向是给整改留口子，但红线没松动）。

| 违规内容 | 扣分 | 我方能否触发 |
|---|---|---|
| 违反法律法规和相关政策（含涉赌、侵害著作权/名誉权） | **70** | ✅ 博彩话术、配图版权 |
| 诱导低俗 | 70 | 低 |
| 发布谣言或不实内容 | **70** | ✅ 编造/比分写错/无信源 |
| 严重旧闻新发 | **70** | ✅ **历史高频**（曾把 2018 年 RSS 当新闻源）|
| 严重标题党 | **70** | ✅ 把传闻写成确定信息 |
| 违规推广 / 标题党 / 画风不良 / 网暴谩骂 | 20 | 低 |
| 内容中关键信息与事实不符 | **20** | ✅ 比分方向、进球数、对阵 |
| 旧闻翻炒 | **20** | ✅ 同上 |
| 违规涨粉 / 引导互粉 / 诱导交互 | **20** | ✅ **原体系在主动生产** |
| 违背公序良俗 / 账号违反平台行为规范 | 20 | 低 |
| 发布已过时效内容 | 10 | ✅ |
| 图文不符 / 相关性差 | **10** | ✅ 图上印了正文没提的队 |
| 格式低质（排版混乱/语意不明/逻辑混乱） | 10 | ✅ 一句话成稿 |
| 失实表述（**含 AI 生成未标识**） | **10** | ✅ 全流程 AI，漏标即稳定违规 |
| 轻微标题党 | 10 | ✅ |
| 违规声明头条首发 | 5 | 当前未开通首发，n/a |

另一条独立罚则：**首发激励计划**——「非原创非首发每篇扣 5 分，30 天上限 50 分」，
且「洗稿、复制拼凑重新整合」被明列为**非原创**。

再一条不在扣分表里、但风险最高的：**低质 AIGC**。平台 2025 治理白皮书口径是
**账号级处置**（流量打压、禁言、封号），全年处置 260 万条内容、1.1 万个账号。
它没有分值，所以最容易被当成「不紧急」。

> 结论：**27 个扣分项里，与足球图文稿有关的是 14 条**（见
> `config/toutiao_rules.yaml` 的 TT-01…TT-14）。其余 13 条（医疗、投资、K12、
> 司法、地图、抽奖、商品卡、视频违约…）我们不产生这些内容形态，明写 `n/a`，
> 不是漏登记。

## 二、现状盘点：47 个脚本在判四种完全不同的东西

盘点方法：逐个读 `scripts/verify_*.py` 的判项函数与 `config/audit_tiers.yaml` 的登记，
对照上面那张表归类。结果是——**只有 10 项判的是「会不会被扣分」**：

| scope | 项数 | 判什么 | 与扣分的关系 |
|---|---|---|---|
| **compliance** | **10** | 平台扣分风险 | **就是它** |
| quality | 9 | 标题三要素、配图张数、封面率、句式多样性 | 影响推荐量，**不扣分** |
| ops | 10 | 发出去没有、几点发、篇数、额度、采集诊断 | 生产线健康，**不扣分** |
| growth | 9 | 点击率、涨粉、内容类型配比、差异化 | 增长指标，**不扣分** |
| dev | 7 | 接线、常量自洽、信号排序、信源清单 | 代码正确性，**不扣分** |
| meta | 4 | 验收体系自身（清单一致性、单测门禁、规则覆盖） | 元层，**不扣分** |

四类判据混用同一套「硬项 / 告警项」语义，产生了两个具体后果，而且**同时存在**：

- **该拦的没拦**：发布前 10 项里有 5 项非合规（篇数、赛程池、额度、差异化、配图张数），
  而真正判扣分的 5 项里 4 项带 `|| echo`——FAIL 了稿子照样发。
- **不该拦的拦了**：那 5 个非合规项一旦抖动（图源挂了、额度紧了），**整批停发**。
  而停发不减少任何扣分风险——11-05 的「图源抖动 → 整批 0 篇」就是这么来的。

## 三、这次真删减了什么

### 3.1 结构性删减：发布前门禁 10 项 → 6 项（且全部为合规）

| | 改前 | 改后 |
|---|---|---|
| pre-publish 项数 | 10 | **6** |
| 其中非合规项 | **5**（篇数/赛程池/额度/差异化/配图张数） | **0** |
| 合规入口 | 无（散在 5 个脚本里，4 个带 `|| echo`） | `verify_compliance` 1 个，真阻断 |
| 复杂度上限 | 无 | 硬校验：compliance 项 ≤ 10，超了 CI 红 |

由 `verify_rule_coverage.py` 的 C/D 两项**硬性校验**，不是靠人记得：

- **C**：tiers 含 `pre-publish` 的项，`scope` 必须 `compliance` 且挂 `rule_ids`；
- **D**：`scope=compliance` 的项数 ≤ 10（这是「审核复杂度」唯一可量化的指标）。

### 3.2 删掉的三条「审错对象」的判据

**① 强制「关注引导」——方向反了（最严重）**

`interaction_bait` 原口径：正文必须同时有「关注引导 + 互动引导」，缺一打回重写，
最后一轮由保存侧**注入**「关注老六，这波后续我替你盯着」。
11-06 实测成稿带 `interaction_bait_source=template_fallback`——**在生产**。

而信用分表写着：诱导交互 **20**、违规涨粉 **20**、引导互粉 **20**。
这等于为了让稿子涨粉，系统在批量生产平台明列扣分的话术。而这条规则的源头是
R11 诊断的「粉丝阅读占比 0%」——**增长指标变成了合规要求**，这是本次最该记住的教训。

处置：
- `关注引导必需: false`（配置开关，可回滚，代码不用动）；
- **不再注入关注话术**（`inject()` 只补互动引导）；
- 新增 `check_inducement()` 黑名单：索要关注 / 互关互粉 / 扣1站队投票 / 博彩术语；
- 升为 `gate_v2.HARD_GATES` 之一（`inducement`），命中即打回，不放行；
- 删掉「下注/押注/扣1/站队/投票」——它们原本写在**达标模式**里，等于奖励诱导话术，
  其中「下注/押注」还是博彩术语（70 分档）。

**② 反洗稿被降级为「只记分」——理由不成立**

11-05 把 `anti_copy` 从硬拦降为记分，理由写的是「只影响增量（有没有人看），
不伤存量（信不信）」。这个理由在平台规则面前不成立：洗稿对应**抄袭侵权**
（社区规范「平台不允许」），且首发计划明列「洗稿、复制拼凑重新整合」为**非原创**。

处置：升为 TT-06，但**只拦重度**——连续重合 > 200 字 或 5-gram 重合率 > 50%。
阈值取在告警线之上，正常改写不会触发（实测样本 30 字 / 12%）。

**③ 把质量分当红线**

`score_title_plan` 的 0 分里混着三要素不足、赛果播报式、疑问收尾限额——
全是提点击率的内部公式。旧验收拿「评分 0 分」当「标题硬违规」，
于是每一篇「三要素只命中 1/3」的正常稿都被算成 70 分档标题党。

处置：TT-04 只判平台**点名**的两类——夸张耸动词（震惊/重磅/全世界…）
与传闻写成确定信息（复用 `rumor_wording`，不另写一套）。
第三类「标题与内容不符」没有判据，**登记为 `coverage_gap`** 由覆盖校验报出来，
不假装判过。

### 3.3 补上的四条空白（原体系完全没有）

| 规则 | 原状态 | 现判据 |
|---|---|---|
| TT-07/08 诱导交互·违规涨粉 | **方向相反** | `check_inducement()` 黑名单，硬拦 |
| TT-10 格式低质 | **无** | 段落数 <4 / 乱码控制字符 / 相邻重复段 |
| TT-11 AI 未标识 | 有实现，**无验收** | 正文必含「本文由 AI 生成」，读不到正文则看 `ai_generated` 标记 |
| TT-13 无资质发布时政 | **无** | 负面词表（总书记/国务院/外交部/台独…），命中即拦交人工 |

### 3.4 明确划出的「不属于审核」清单

写进 `config/toutiao_rules.yaml` 的 `out_of_scope` 段，四类各有理由：
quality（平台不鼓励但不扣分）、ops（生产线健康）、growth（增长指标）、
dev（工程自检）。**它们不是被删掉，是被移出「审核」这个筐**——
仍然每天跑、仍然留痕，只是不再决定「今天有没有稿子发」。

## 四、改后结构：一个入口 + 一张表 + 两个反向校验

```
每批生成后、发布前
        │
        ▼
  verify_compliance.py  ←── config/toutiao_rules.yaml（唯一权威，14 条）
        │                    每条：信用分 / 原文条款 / 判据 / 拦截档
        │  判据只调用现有模块，不重写：
        │    interaction_bait / image_relevance / rumor_wording /
        │    fact_assert / data_chart.entity_hits / compliance_guard
        ▼
  命中 block 级 → 停发这一篇（不是停整批）
  未判定       → 发布前放行（避免 11-06 noon 那种整批 0 篇），
                 每日层裸 rc=2 暴露
        │
        ▼
  verify_rule_coverage.py  ← 反向校验，防规则表与实现脱节
        A 规则表自洽  B 判据可达  C 发布门禁纯净
        D 合规项数不反弹  E 每条规则有人维护  F 缺口可见
```

**为什么判据不重写**：同一个量两处定义，必然只改一处——这是本项目 11-04
「规则相斥」和 11-05「三处镜像」两次事故的共同形态。所以 `verify_compliance`
只做调度，判定一律调现有模块。

**为什么「未判定」在发布前不拦、在每日拦**：
11-06 noon 那批 0 篇的根因，正是把「读不到正文」当成了「不通过」。
发布前若也这样，一次跨 runner 就会整批 0 篇；但若一律放行，
「读不到证据」就会被当成「通过」——那是同一个错误的反面。
所以分两档：**发布前只拦真违规**，**每日把未判定显式报红（rc=2）**。

## 六、保留部分为什么保留

| 保留 | 理由 |
|---|---|
| `image_relevance` 硬拦 | 平台明列「图文不符/相关性差 10 分」，且 11-05 出过「图上印了正文没提的球队」。这是全仓唯一做到「绘图侧与验收侧共用 `data_chart.entity_hits`」的地方 |
| `rumor_wording` 硬拦 | 「把传闻写成确定信息」同时命中谣言 70 与标题党 70，是双罚点 |
| `content_reference` | 洗稿＝抄袭侵权，属「平台不允许」。它判的是「抄方法论不抄选题」 |
| `content_mix` 禁发类型 | 唯一「发出去不可撤回」的项（历史回顾＝旧闻），保留 hard |
| `hot_freshness` / `event_result` 的成稿判定 | 旧闻与「未揭晓就写结果」分别对应 70 分档两条 |
| `wiki_media` 许可 fail-closed | 著作权是 70 分档（侵害知识产权），且体育图片维权最成熟 |
| `verify_audit_health` / `audit_health` 元层 | 防「验收器自己失真」——长期红灯本身就是漏洞 |
| 39 项体检 | 不是删掉，是移出「审核」。仍然每天跑、仍然留痕 |

## 七、残留风险

1. **TT-04 子类缺口**：「标题与内容原意有偏差」需要标题↔正文语义比对，
   当前无判据，已在规则表登记 `coverage_gap`，由覆盖校验持续报出。
2. **TT-03 成稿侧证据弱**：素材侧靠 `hot_sources` 的 36h 闸门，成稿侧只能查
   `publish_by` / `source_age_hours`；两者都没有时判「未判定」，不像「通过」。
3. **本机 rc=2 属预期**：正文留在生成它的 runner 上（`/home/runner/work/_temp`），
   本机读不到。所以本地跑 `verify_compliance` 会返回 2，CI 里应显著更低。
   **若 CI 里也是 2，说明正文落盘链路断了，那时要查的不是规则而是产物。**
4. **TT-14 阈值无公开标准**：结尾话术重复率 ≥50% 只 warn，是经验值。
   它的价值在于「让账号级风险可见」，不在于精确。
5. **未验证的假设**：`check_inducement` 的博彩词表取窄（赌球/博彩/下注/押注/庄家/
   盘口/让球盘/滚球/买球/外围盘/赔率盘），刻意不含「赔率」「竞猜」——它们在
   正常赛事报道里也出现。若后续发现漏网，加词即可，不要在正文里写「赔率」就拦。

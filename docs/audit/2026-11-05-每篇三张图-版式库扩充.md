# 每篇 3 张图（硬条件）：版式库扩充与研究结论

> 2026-11-05 · 对应提交 `feat(配图): 版式库 7 种 × 4 套配色`
>
> 用户原话：「硬条件：单篇文章必须至少有三张图，自制图片除了这种表现形式还有什么其他表现形式，搜索下 github 高星数项目。看看有没有自动配图的技能可以用。」

## 一、先纠正一个事实：之前一直是 1 张

「每篇 3 张」的代码是 11-05 白天写的（`MIN_ARTICLE_IMAGES = 3`），但**实际没兑现**：

| 批次 | 每篇图数 | 图片构成 |
|---|---|---|
| 2026-11-05 noon（CI 实跑） | 1 / 1 / 1 | 全是标题卡 |

根因不是「没写补齐逻辑」，而是**补齐逻辑手里的牌只有三张**：

| 版式 | 素材要求 | 真实稿件命中率 |
|---|---|---|
| `title` 标题卡 | 有标题 | 100% |
| `points` 要点卡 | 正文 ≥2 个 `## ` 分节 | 取决于 LLM 是否听话 |
| `numbers` 数字卡 | 标题或正文里有数字 | 纯观点稿常没有 |

三条都抽不到素材时，`fill()` 只能出 1 张。**「每篇 3 张」在那时是一句愿望，不是一条约束。**

这次补充后，版式库变成 7 种 × 4 套配色，且新增的四种**不要求任何格式约定**，只看句子本身。

## 二、新增的四种版式

| 版式 | 素材 | 视觉特征 | 为什么需要它 |
|---|---|---|---|
| `quote` 金句卡 | 正文里最像判断的一句 | 巨大引号 + 居中大字 | 不要求 `## `、不要求数字，只要有正文 |
| `qa` 问答卡 | 标题问句 + 正文答案句 | 上下分栏「问 / 答」 | 问句标题天然有落差，别的版式表达不了 |
| `outline` 结构卡 | 按空行分段，每段取首句 | 竖排时间线 + 序号 | 实测最常见的「三段话没有小标题」 |
| `compare` 对比卡 | 同单位的两个值 / 一个比分 | 左右双栏大字 | 数字卡只能强调一个数，两个数的关系它画不了 |

四套配色：`navy`（深海军蓝，原配色）、`crimson`（暗红，冲突/争议类）、`paper`（米白纸感，盘点/人物类）、`forest`（墨绿，战术/复盘类）。

主题不是装饰。三张图如果只是同一版式换个字，读者看到的仍然是「一张图发三遍」。

## 三、保底逻辑：任意稿件都能补满 3 张

`_FILL_PLAN` 是一个 14 项的候选序列，从「信息量最高」排到「只是换配色」：

```
points → numbers → quote → outline → qa → compare
      → quote(第2句) → quote(第3句) → outline(换起点)
      → title+crimson → title+paper → title+forest
      → quote(第4句) → quote(第5句)
```

三类最难的稿子实测：

| 稿件 | 产出 |
|---|---|
| 正文仅一句 | 标题卡(navy) + 金句卡 + 标题卡(crimson) |
| 正文为空 | 标题卡(navy) + 标题卡(crimson) + 标题卡(paper) |
| 多段无小标题 | 数字卡 + 金句卡 + 金句卡(crimson) |

**正文为空时三张都是标题卡、只是配色不同** —— 这是承认现实的最差情况。它比「只发一张」好，但不该成为常态：`verify_image_diversity` 会在产物里查「同一篇的信息图版式是否 ≥2 种」，把这个退化暴露出来。

## 四、内容不重复的三个判据

补满张数不难，难的是**三张别在说同一句话**。三处去重：

1. **句子级**：要点卡用掉的摘要句会进 `avoid`，金句卡不能再抽同一句。若剩余句子只剩导语（「谁几比几赢了」），金句卡直接跳过——那是数字卡已经画过的事。
2. **版式级**：`skip_variants` / `used_cards` 两个粒度。前者整类跳过，后者只跳过「版式+配色」这一个组合。
3. **画布级**：md5 去重，撞了就删掉重画，不在 `images/` 留孤儿文件。

第 2 条是端到端测试抓出来的真 bug：封面兜底已出了 `title+navy`，当时传的是 `skip_variants=("title",)`，把整个 title 版式排除掉，于是「正文仅一句」只能补到 2 张。

## 五、对比卡的第一版是错的

第一版取标题里前两个数字 token，给「皇马2-1瓦伦西亚，27分还是不够用」画出了：

```
   2-1        |        27分
         对比
```

比分和积分并排 —— 读者只会觉得这张图在胡说。现在只认两种合法对比：

1. **同单位**的两个值（`34分` vs `27分`，标签取各自最近的队名）
2. **一个比分**拆成左右两半（`2` vs `1`，标签取比分两侧最近的队名）

都不是就跳过，让 `fill` 换下一张牌。宁可少一张，也不出一张误导图。

标签位置用 `draw.textbbox` 的字形实际包围盒算，不用「字号 × 系数」估算——估算法在「34分」这种带下沉笔画的串上会把标签压到数字上（第一版就是这样）。

## 六、GitHub 调研：为什么没有直接抄

| 项目 | Star | 它做什么 | 为什么不直接用 |
|---|---|---|---|
| `anuraghazra/github-readme-stats` | 79.9K | 数据 → SVG 卡片 | 思路就是本次方案（数据驱动 + 模板），但它的产出是 GitHub 统计，与我们无关 |
| `matplotlib/matplotlib` | 23.4K | Python 绘图库 | 装得上但 CI 体积 +150 MB，且它只会画图表，画不了「金句卡 / 问答卡」这类版式 |
| `plotly/plotly.py` | 18.9K | 交互图表 | 输出 HTML/JS，导静态图要额外装 kaleido + Chromium |
| `vercel/satori` | 14.2K | HTML/CSS → SVG（MPL-2.0） | **技术上最优**：用 CSS 写版式，不用手算坐标。但要 Node + resvg，CI 多一条工具链 |
| `bubkoo/html-to-image` | 7.3K | 浏览器端 DOM → 图片 | 需要真实浏览器 |
| `mermaid-js/mermaid-cli` | 5.2K | 文本 → 流程图 | 只能画流程图，而且同样要 Chromium |
| `Kozea/CairoSVG` | 957 | SVG → PNG | 本机实测可装可用（`pip install cairosvg` 后中文正常），但需 libcairo 系统库 |

**结论：这次没有引入任何新依赖。**

理由不是「省事」，而是权衡后 Pillow 已经够用：
- 真正的问题从来不是「画布能力不足」，而是**素材不够**（只有三种版式）和**坐标是手算的**（易压叠）。
- 这次用手算坐标的修正（`textbbox` 定位、标点优先断行）解决了观感问题，没有引入 Node / Chromium / cairo。
- CI 里每多一条工具链，就多一个「本地能跑、CI 崩」的地方——11-05 的 py3.11 事故正是这么来的。

**如果以后版式要继续加（比如 CSS 那种自由布局），satori 是首选**：MPL-2.0 允许商业使用，只需在修改它自身文件时开源那部分。届时要在 CI 加 Node 步骤 + 字体打成 ArrayBuffer 传进去。

## 七、Skill 调研：有，但接不进流水线

在 WorkBuddy 推荐市场搜「配图 / 图片生成 / 卡片」，相关的有：

| Skill | 版本 | 能力 | 能不能用在我们这儿 |
|---|---|---|---|
| `card-poster` | 1.3.3 | 文字/Markdown/JSON → 中文卡片图，5 版式 × 7 风格 × 8 配色，支持长文自动拆卡、整目录批量出图 | **最贴切**，但它是给会话内用的，CI 里调不到 |
| `baoyu-article-illustrator` | 1.117.4 | 分析文章结构，选配图位置、类型、风格、配色 | 思路可借鉴（「按段落决定配哪种图」），实现接不上 |
| `toutiao-writer` | 1.0.1 | 头条文章 + 标题 + 封面 + 配图 | 生成环节依赖 LLM 出图，CI 里没这条通道 |
| `gpt-image` | 1.2.0 | 文生图 | 按张扣积分，日更 6 篇 × 3 张 = 18 张/天，成本与失败重试都不可控 |
| `image-design-master` | 1.0.1 | 22 套设计模板 + 541 条逆向提示词 | 同上，是「给人用」的工具，不是可编程模块 |

**核心区别**：这些 Skill 是**会话内的能力**（我给一个 AI 助手装上，它就会用），而我们的生产跑在 GitHub Actions 里，没有会话、没有交互、只能跑 `python3 orchestrator.py`。

所以这次的做法是「借鉴设计思路、自己实现」：
- 从 `card-poster` 借「多版式 × 多配色」的矩阵思路 → 7 × 4
- 从 `baoyu-article-illustrator` 借「按文章结构决定配哪种图」→ `_FILL_PLAN` 的排序与素材门槛

## 八、验收从「建议」升为「硬条件」

用户说的是硬条件，所以 `config/audit_tiers.yaml` 里 `article_images` 从 `advisory` 改成 `hard`，CI 里的 `|| echo "::warning::"` 改成三态处理（`rc=1` 阻断 / `rc=2` 未判定只告警）。

**敢升硬的底气**：下限已经不再依赖外部图源。7 种版式全部由本文标题与正文派生，连「正文只有一句话」的稿子都能补满 3 张（有自检兜着）。这时失败只意味着一件事——系统没有能画汉字的中文字体，那就是 11-05 封面全方框的同款事故，必须立刻知道。

元验收当场抓出我自己的漏洞：改完 `kind: hard` 后它报「声明为发布前硬项但调用行带 `|| echo`」——这正是它该干的活。

新增三项检查：

| 检查 | 类型 | 查什么 |
|---|---|---|
| `check_variant_variety` | 硬 | 拿四类极端稿直接跑版式库，出不满 3 张即红 |
| `check_variant_diversity` | 硬 | 产物里同一篇的信息图版式 ≥2 种 |
| `check_products`（已有，加强） | 硬 | 生效日后每篇 `images ≥ 3` |

## 九、边界与遗留

**能保证的**：任何稿件都有 ≥3 张图，全部零版权风险、由本文内容派生、正文里真的有 3 处引用。

**不能保证的**：
- 正文为空的稿子三张都是标题卡换配色——张数达标，观感单调。`check_variant_diversity` 会把它暴露出来，但不会自动修好（正文为空时确实没有第二个素材来源）。
- 信息图是「文字排版」，不是「画面」。要真的画面只能上 AI 生图或正版采购，两者在 CI 里都不可行。
- 新闻图仍在灰线上（未授权但未去 logo），目标是把新闻图降为补位、最终停用，需先观察一段各篇图源构成。

## 十、补记：CI 红灯追查（同日）

上报「1680 passed」是读错了数——真实结果是 **1678 passed / 2 failed**。CI 的
`pytest（全量单测）` job 红的就是这 2 项，不是字体差异，是代码缺陷。

**症状**：`_extract_quote(content, skip=(first,))` 在「正文两句」的稿子上返回空串；
`render(variant="quote", nth=1)` 返回 None。

**根因是同一个错误写了三遍**——「这篇稿子还有没有没用过的判断句」：

1. `_extract_quote` 里做成 `allow_lead` **参数**交给调用方决定，而全仓**没有一个
   调用方传过 True**。参数形同虚设，于是「导语不算可用句子」这条规则永远生效，
   非导语句用光后直接返回空串。
2. `fill` 里又写了一遍本地判据 `len(spare) <= nth → continue`，口径与第 1 处不同
   （它把导语算进了 spare）。两句稿 `spare=[导语]`、`nth=1`，被这里直接拦掉。
3. `_FILL_PLAN` 再给 quote 传 `nth=1/2/3/4`，而 `fill` 自己已经用 `avoid` 记了
   「本篇用过哪几句」——同一件事记两遍，第 2 张时「再跳过 1 句」必然越界。

**修法（三处一起收口）**：
- 导语退回逻辑放进 `_extract_quote` 内部（`_pick(False) or _pick(True)`），
  删掉 `allow_lead` 参数——规则不能靠「谁记得传参」生效。
- 删掉 `fill` 里的 spare 判据，可用性只由 `_extract_quote` 说；抽不到时 render
  返回 None，代价只是一次空尝试。
- `_FILL_PLAN` 里 quote 一律 `nth=0`，句子去重只由 `avoid` 负责；`nth` 只留给
  「不维护 avoid、只要第 n 句」的调用方。

**效果**：正文两句的稿子从「金句卡 + 标题卡×2」变成「两张不同句子的金句卡 + 标题卡」，
即同一篇里最好的两句判断都上了图。

**这一环也补了验收样本**：`check_variant_variety` 原来只有「正文仅一句 / 为空 /
多段无小标题」三类样本，**恰好没有「正文两句」**——缺陷只被单测抓到、没被验收抓到。
样本集不全，验收本身就是漏网的原因。现已补第四类，并加单测
`test_two_sentence_body_gets_two_quotes` 直接锁住「两句稿必须出两张金句卡」。

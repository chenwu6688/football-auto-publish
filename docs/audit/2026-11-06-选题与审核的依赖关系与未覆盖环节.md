# 选题 ↔ 审核：依赖关系分析与待调整事项（2026-11-06）

> 背景：今天先梳理了**选题链路**（热点池、槽位账、去重 5→2、认知度兜底），
> 再梳理了**审核逻辑**（14 条规则、合规唯一入口、发布前门禁 10→6）。
> 这份文档回答第三个问题：这两件事**到底怎么咬合**，还差哪几块。

---

## 一、结论先说

**审核的每一条判据，证据都来自选题阶段的产物；而选题阶段的产物，有一半没落盘。**

实测（`output/2026-11-06/metadata.json`，4 篇）：

| 审核规则 | 需要的证据 | 本次真实可得 | 即使正文可读能判吗 |
|---|---|---|---|
| TT-03 时效 | `publish_by` / `source_age_hours` | **0/4** | ❌ 不能 |
| TT-05 事实 | `_gate.fact.judged` | 2/4 | 一半不能 |
| TT-06 洗稿 | `_similarity` | **0/4** | ❌ 不能 |
| TT-09 图文 | `image_anchors` | 2/4（另 2 篇是**空数组**） | 一半不能 |
| TT-14 低质 | 可读正文 ≥5 篇 | 0/4（日更约 4 篇 < 5） | ❌ 永远不能 |

于是 `verify_compliance` 今天的输出是：**12 条 block/rewrite 级规则，只判出 1 条**
（而那 1 条是 TT-12，恰好不需要正文）。`rc=2`。

要注意区分两种「未判定」，它们的修法完全不同：

- **A 类：正文不可读**（跨 runner）。这是环境的锅，CI 里会好。
- **B 类：字段根本没写**。这是**代码的锅**，CI 里照样未判定。
  TT-03 / TT-06 / TT-14 属于 B 类，TT-05 / TT-09 有一半是 B 类。

**B 类才是今天要修的。** 它意味着：即使把 CI 跑绿了，审核仍然是空的。

---

## 二、两者的真实关系：单向依赖 + 零反馈

```
选题（决定写什么）                 审核（判断能不能发）
  ├─ 选题类型 content_type  ────→ 决定哪些规则适用（战报才有赛果口径）
  ├─ 题材 topic_category    ────→ TT-13 时政边界 / TT-04 标题模板
  ├─ 素材来源 sources_used  ────→ TT-06 洗稿（有源文才能比对）
  ├─ 素材时效 36h 闸门      ────→ TT-03（现在**没有传递**，见第四节）
  ├─ 配图方案 + 锚点        ────→ TT-09（锚点空 = 无法验相关性）
  └─ 去重（同场/同事件）    ────→ TT-14 批量重复（现在**另一套实现**）

                       ↑ 只有这一条箭头
                       ✗ 审核结论没有任何一条回到选题
```

两条结论：

1. **依赖是单向的、而且是硬的**。审核不能独立成立——它只是「检查选题与写作留下的证据」。
   所以「审核太复杂」的一半真相是：**审核在替上游补证据**，补不出来就只能判未判定。
2. **反馈是零**。审核打回了什么、哪类题材反复触发哪条规则，选题侧不知道。
   今天打回一篇「标题耸动」，明天同样的选题照样被选中、照样耸动。

## 三、六个尚未覆盖 / 仍需梳理的环节

### 环节 1｜证据落盘契约缺失（最硬的缺口）

**现象**：`_similarity` / `_increment` 0/4 全空；`publish_by` 0/4；`_interaction` 0/4。

**根因不是"忘了写"，而是"只在失败时才写"**：

```python
# orchestrator.py:2013  只在未达标时落字段
_ib = check_interaction_bait(art)
if not _ib["ok"]:
    art["_interaction"] = {"ok": False, "missing": [...]}   # 达标则什么都不写
```

同样的形状出现在 `_inducement`、`_anti_copy`。而审核侧的语义是「读不到 = 证据不足 = 未判定」。
**两边语义正好相反**：生成侧用「不写」表示成功，审核侧把「没有」读成失败。

这与本项目已登记的老毛病「靠字段缺失实现排除」是同一个根，只是这次伤害的是审核。

### 环节 2｜时效保证传不下去（一个已满足的事实，事后完全看不到）

`hot_sources.HOT_MEDIA_MAX_AGE_HOURS = 36` 在**选题阶段**已经过滤了素材。
但这个判定只活在内存里，没有写进成稿的 metadata；`art` 里连 `publish_by` 都没有
（它是 topic 上的字段，没被复制过来）。

结果：**一个已经被前置闸门保证过的事实，在审核阶段变成了"无证据"**。
TT-03 只能判未判定。这是「同一事实两处，中间没有传递」的教科书案例。

### 环节 3｜选题侧砍掉的弱判据，正是审核侧要的

去重从 5 道砍到 2 道（同场 / 同事件）+ 1 道告警（关键词重叠）。这个取舍**是对的**——
弱判据不能当删题判据，供给本来窄。

但代价是：关键词重叠告警**只打印 + 记漏斗，没有人消费它**。
而审核侧 TT-14「批量发布重复低质内容」自己又写了一套「结尾话术重复率 + 相邻篇句子重合」。
于是**同一个风险、两套实现、都不阻断、互相不知道**。

今天的实例（同一批 4 篇里）：

- 「领跑，那不勒斯这一关，队长憋的劲该往哪使」
- 「登顶遇上那不勒斯，队长憋的那口气比积分更重」

同队、同主角、同句式、同角度。既不是"同场"（没有对阵键）也不是"同事件"
（`event_key` 不同），所以去重放行；TT-14 因为样本 <5 也判不出。
**两道都过，谁都没看见。**

### 环节 4｜题材边界纯事后（70 分档，风险最高）

`_BOUNDARY`（时政词表）只存在于 `scripts/verify_compliance.py`。选题侧零过滤
（`hot_topics.py` 全文没有"时政/政治"）。

后果：一旦热榜里出现「足协换届」「某俱乐部获政府专项资金」这类题材，会被正常选中、
写完、配图、然后才在发布前被 TT-13 拦下——**一次完整生成被白烧**，且这是 70 分档。

### 环节 5｜审核结论零回灌

全仓 grep：没有任何一处代码读取 `compliance_latest.json` 去做选题决策。
审核是纯单向闸门。

对账号风险而言这不算致命（每次发布前都拦），但对**产能**是持续浪费：
同一类题材反复被打回，系统不会学着避开。

### 环节 6｜「未分类」50%，让两边都变模糊

4 篇里 2 篇 `topic_category = 未分类`。这是**刻意不猜**的正确行为
（`topic_category` 的纪律是对的），但后果是：

- 选题侧：配比统计有一半是废的（`content_mix` 拿不到真实类别）。
- 审核侧：按题材判断适用性的规则（TT-13、TT-04 的模板）失去依据。

而 50% 还没触发告警——`未分类占比阈值` 是 0.8，为"不猜"留的余量太大。

## 四、待调整事项（按优先级）

### P0-1 建立「证据落盘契约」，成功也要写

**问题**：环节 1 + 环节 2。审核 12 条规则只判出 1 条。

**改法**（一处改，三处受益）：

1. 新增 `art["_evidence"]` 统一块，**无论成败都写**：

   ```jsonc
   "_evidence": {
     "freshness":  {"judged": true,  "source_age_hours": 3.2, "publish_by": "2026-11-07 03:00"},
     "fact":       {"judged": false, "reason": "no_source_text"},
     "similarity": {"judged": false, "reason": "no_source_text"},
     "images":     {"judged": true,  "anchored": 3, "total": 3},
     "ai_marked":  true
   }
   ```

2. `_similarity` 在 `_src_texts` 为空时写 `{"judged": false, "reason": "no_source_text"}`，
   而不是"什么都不写"。**"判不了"本身是一条要落盘的结论。**
3. `_interaction` / `_inducement` / `_anti_copy` 达标时写 `{"ok": true}`。
4. `publish_by` / `source_age_hours` 从 topic 复制进 art。

**验收**：`verify_compliance` 新增一段「未判定原因分布」（`no_source_text` / `no_body` /
`field_missing`），跑一次真实批次后 `field_missing` 必须为 0；`rc=2` 只在 `no_body` 占多数时出现。

**为什么排 P0**：现在整个审核体系的输出是"全未判定"，等于没有审核。这是唯一的阻断点——
其他优化都建立在这个之上。

### P0-2 题材边界前置到选题

**问题**：环节 4。70 分档的规则只能事后拦。

**改法**：把 `_BOUNDARY` 从 `verify_compliance.py` 提到共享模块（如
`config/toutiao_rules.yaml` 的 `topic_boundary_words`，或 `compliance_guard` 里），
选题打分时命中即**剔除，或降权到候选池末位**。

关键约束：**词表只能有一份**。不要在两处各写一遍——今天已经因为"同一规矩两处"踩过两次。

**验收**：造一条含「国务院」的热点，必须进不了候选池（有单测）。

**为什么排 P0**：成本极低（一张词表的位置），但它挡的是 70 分档，而且省一次完整生成。

### P1-1 让弱判据的告警有消费者

**问题**：环节 3。两套重复检测并存，今天的实例已经漏了。

**改法**：选题侧把关键词重叠的告警**落盘**为 `art["_dedup_warn"]`，
`j_low_quality_aigc` 改为**优先读它**，自己那套算法降为兜底（无该字段时才跑）。

这符合今天的反过来的一条纪律：**判据可以被两处调用，但实现只能有一份**。

**验收**：造两篇同队同句式的稿，TT-14 必须报出来（现在报不出）。

**为什么排 P1**：它是"看得见但还不阻断"，可以先记账；而且要做对得先有 P0-1 的落盘通道。

### P1-2 审核结论回灌选题（只做账本，先不做打分）

**问题**：环节 5。零反馈。

**改法**：新增 `data/review_ledger.jsonl`，每条：`{date, topic_key, rule_id, action, reason}`。
选题打分时**只读不写**，命中近 7 天同类题材被同一规则打回 → 降权。

**关键约束**：先只做账本 + 报表（"哪类题材最常触发哪条规则"），
**确认数据可信之后再接到打分上**。直接接打分是拿噪声调系统。

**为什么排 P1**：没有它系统仍能跑（每次发布前都会拦），有它是提效。但账本必须先有。

### P2-1 未分类治理

**问题**：环节 6。50% 未分类，配比统计一半失真。

**改法**：把未分类样本 dump 出来（`verify_topic_funnel` 已有漏斗），
按实际文本扩词表；把 `未分类占比阈值` 从 0.8 降到 0.4，先让它**告警可见**，
再谈分类准确率。**不要为了让数字好看去猜**。

### P2-2 TT-14 的样本量门槛与实际产能矛盾

**问题**：`len(tails) < 5 → 未判定`，而日更常态 4 篇（`BATCH_QUOTA` 6 篇是上限）。

**改法**：窗口从"当天"改成"滚动 3 天"（12 篇左右），或降阈值到 4。
两者选一，但要写进规则表，不要再出现"阈值在代码里、目标在配置里"。

**为什么排 P2**：它不影响正确性，只影响"这条规则有没有在干活"。

## 五、推进步骤

**第一步（本轮，预计最小改动面）**
1. `_evidence` 统一块 + 三个判据的"成功也写" + `publish_by` 透传（P0-1）
2. 时政词表提到共享位置 + 选题侧前置剔除（P0-2）
3. 两条都配负向单测（证明真的在拦 / 真的在落盘）

**第二步（下一批跑完后验证）**
4. 看 `未判定原因分布`：`field_missing` 是否归零
5. 若 `no_body` 仍占多数 → 问题不在审核，在**正文落盘链路**（那时要查产物，不是改阈值）
6. 有了干净的证据流，再动 P1-1（TT-14 改读 `_dedup_warn`）

**第三步（观察 3–5 天）**
7. 建 `review_ledger.jsonl`，先出「题材 × 规则」报表
8. 按报表决定是否接回选题打分

## 六、本轮明确不做的

| 不做 | 原因 |
|---|---|
| 直接接"审核结论 → 选题降权" | 没有账本数据，接上去是拿噪声调系统 |
| 把 `未分类` 强行归类 | 违反「判定不了不猜」，会让配比统计假精确 |
| 给 TT-14 加硬拦 | 平台无公开阈值，硬拦会误杀正常稿 |
| 为一篇稿重建正文落盘链路 | 跨 runner 是架构问题，先把"字段级证据"补齐，正文问题单独立项 |

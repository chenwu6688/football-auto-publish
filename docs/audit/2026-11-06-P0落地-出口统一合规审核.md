# P0 落地：出口统一合规审核（丢该篇，不停整批）

> 2026-11-06 · 对应 `2026-11-06-选题与审核的依赖关系与未覆盖环节.md` 里 P0 三条
> 结论一句话：**合规判定从「1/7 条生成通道」变成「所有通道的出口」，且处置从
> 「停整批」改成「丢该篇」。**

---

## 一、为什么要改

上一轮用 AST 扫 `orchestrator.py` 的全部 `generate_*`，查各自调用了哪些闸门：

| 生成函数 | 供给层 | gate_v2 | 诱导 | 互动 | 反洗稿 | 事实 |
|---|---|---|---|---|---|---|
| `_rewrite_with_retry` | 二级·突发 | ✅ | ✅ | ✅ | ✅ | ✅ |
| `generate_emergency_article` | 紧急球评 | ✅ | — | — | — | — |
| `generate_fixture_article` / `recap` / `event_result` / `node_angle` | 一级·确定性 | — | — | ✅ | — | — |
| `generate_prediction_article` | 前瞻 | — | — | — | — | — |

**7 条通道只有 1 条有完整合规闸门。** 当日 4 篇成稿里 2 篇（一级·确定性）
`_gate` / `_fidelity` 全空——从生成到发布，合规判定为零，全压到发布前的
`batch.yml` 那一步；而那一步命中就是 **`exit 1` 停发整批**。

两边都错：**该判的地方没判，判出来的地方处置又过重。**

---

## 二、改法：收口在出口，不在生成函数

### 1. 一处收口，而不是六处补丁

在 `save_articles_local`（所有通道唯一汇聚点）加一道出口审核，位置在
**互动话术兜底之后、`file_writer.save_article` 之前**——判的是读者最终看到的
那段文字。

为什么不在 6 个 `generate_*` 里各加一遍：**6 处要记得改，而今天已经漏了 5 处。**
这与项目已登记的「同一规矩写两处、必然只改一处」是同一枚硬币的两面——
这次是「规矩只写在一处，新通道不知道它存在」。出口收口有先例：标题三要素当初
也是 6 条路径各写一遍出问题，最后在出口补一道，注释写着「口子就留在这里」。

### 2. 判据不重写

`scripts/verify_compliance.py` 新增 `audit_article(art, date_str, body=...)`：

- 规则清单从 `config/toutiao_rules.yaml` 读（**不在代码里再列一遍**）；
- 逐条调已有的 `j_*`，与发布前、每日层**同一份实现**；
- 单测用 AST 守这三条：`_SINGLE.get(name)` 必须在、`_judge_names(rule)` 必须在、
  代码里不许出现硬编码的 `TT-xx` 字符串字面量清单。

### 3. 处置分档：丢该篇，不停整批

| 档位 | 出口处置 | 为什么 |
|---|---|---|
| `block`（≥20 分） | **丢该篇** | 平台真扣分，宁可少发一篇 |
| `rewrite`（10 分档） | **丢该篇** | 发布前那层把 rewrite 也算 blocking；出口放行会导致整批停 |
| `warn`（无分值） | 保留 + 留证 | 低质 AIGC 是账号级风险，不该因为「不扣分」就删掉可见性 |

「少发一篇」可以补发（30/50 分兜底 cron），「停一整批」就是 0 篇，
而且 0 篇还会被下游当成「上游空转」去重跑——**代价差一个数量级**。

### 4. 证据落盘契约：成功也要写

```json
"_compliance": {
  "drop": false, "blocked_by": [], "risk_score": 0,
  "judged": 8, "total": 14,
  "verdicts": [{"id": "TT-07", "status": "pass", "detail": "无诱导话术", ...}, ...]
}
```

原先生成侧用「成功就不写字段」表示 ok（`_interaction` / `_inducement` /
`_anti_copy` 都只在 `if not ok:` 里赋值），审核侧把「没有」读成「证据不足」——
**同一个「缺失」在两边含义相反**，这是「审核空转」的根因。现在成功也写，
判不了写 `status: not_judged` **并带原因**（不是省略）。

审核自己抛异常时：`drop: False` + `error` 字段 + 打印 + `degrade.note`，
**不阻断发布**（与埋点同一纪律），但必须 loud。

### 5. 发布前那层也改成逐篇剔除

`verify_compliance.py --drop-violations`：命中 block/rewrite 的成稿 md 移进
`output/<date>/dropped/`（发布器是 glob 顶层 `article-*.md`，移进子目录即自然
移出发布集合，不必改发布器），metadata 保留记录并加 `dropped_by_compliance`。

三个细节都是踩过的坑：

- **幂等不许毁证据**：已剔除的篇第二轮跳过，否则 md 已移走 → 重判拿不到正文 →
  把「为什么被剔」冲成「正文不可读」；
- **`kept` 按残留标记算**，不按本轮剔了几篇算（第二轮剔 0 篇但发布集合确实少了 1 篇）；
- **`rc=3` 单独表示「全丢」**：与 `rc=1`（批量级违规该停）、`rc=2`（未判定）
  分开。以前三种终态共用一个 exit 1，直接导致过批次永久丢失。

### 6. 配图相关性：硬项照样硬，产物相关性不再拖垮整批

`verify_image_relevance.py` 加 `--fail-on-hard-only`，`batch.yml` 改用它：

- **硬项 A–D**（接线 / 闸门行为 / 不画假图 / 无残留图）→ 红了仍然 `exit 1`，
  因为那说明闸门本身坏了；
- **产物相关性（E）** → 只告警。逐篇相关性已由出口审核（TT-09）处置，
  命中只丢该篇；这里再整批拦一次就是「同一风险两处判定」，
  而且会把「某一篇图不对」放大成「整批 0 篇」。

刻意**没有**用 `|| echo "::warning::"` 一刀切软化——那会让硬项永远绿，
正是元验收要抓的「有验收的假象」。

## 三、端到端证据（真实执行，不是推断）

拿两篇合成稿跑真的 `save_articles_local`（一篇干净、一篇带「关注我，带你复盘每场球」）：

```
⛔ 合规拦截，丢该篇（其余篇照常发布）：TT-07(20分)、TT-08(20分) → 那不勒斯更衣室炸了…
   TT-07 诱导交互：命中诱导话术：索要关注
   TT-08 违规涨粉 / 引导互粉：命中诱导话术：索要关注
   🧯 降级[合规审核]：TT-07(20分)、TT-08(20分) → 丢弃该篇成稿，不停整批
   ⛔ 合规拦截 1 篇（其余照常发布，不停整批）
saved = 1
md files = ['article-1-那不勒斯客场21-6fde1a.md']       ← 违规篇没有落盘
leftover imgs = ['article-1-img-001.jpg', …]          ← 违规篇的图也一并删掉，不留孤儿
compliance_dropped = [['TT-07', 'TT-08']]
evidence: judged=8/14 drop=False                     ← 留下的那篇有完整证据
```

## 四、这套改动之后，审核到底能判几条

用干净稿实测出口审核（`judged=8/14`）：

| 规则 | 出口状态 | 原因 |
|---|---|---|
| TT-01 违法违规 | ✅ pass | 博彩词表 + 熔断状态 |
| TT-04 标题党 | ✅ pass | 耸动词 + 传闻断言（第三子类仍缺判据） |
| TT-07/08 诱导交互·涨粉 | ✅ pass | 黑名单 |
| TT-09 图文不符 | — n/a | 无数据图锚点（有锚点则逐张核实体/数字） |
| TT-10 格式低质 | ✅ pass | 段落数 / 乱码 / 重复段 |
| TT-11 AI 标识 | ✅ pass | 正文含「本文由 AI 生成」 |
| TT-12 首发 | ✅ pass | 读 `publish_scope`，不读记忆 |
| TT-13 时政边界 | ✅ pass | 负面词表 |
| TT-02/05 事实矛盾 | ⚠️ 未判定 | 一级通道没有 `_gate.fact` |
| TT-03 时效 | ⚠️ 未判定 | 没有 `publish_by` / `source_age_hours` |
| TT-06 抄袭 | ⚠️ 未判定 | 没有 `_similarity` |
| TT-14 低质 AIGC | ⚠️ 未判定 | 批量级判据，出口单篇不判（**登记了原因，没有静默跳过**） |

**判出 8 条，比改之前的 1 条（TT-12，恰好不需要正文）多 7 条。**
但 TT-02/05/06 这 3 条是 20 分档、且正片最危险的三条，仍然拿不到证据——
因为证据字段由生成侧决定，出口拿不到就是拿不到。

## 五、还没做的（P1，附判据）

| 事项 | 为什么不能顺手做 | 判据 |
|---|---|---|
| TT-02/05 在出口跑 `gate_v2.fact_gate` | 需要 `_source_fixture` + `match_context`，且误判会直接丢篇；本轮已叠了三处改动，不宜再压一个高风险件在同一个提交里 | 用今天的 4 篇真稿跑一遍，人工核 false positive 为 0 再启用 |
| TT-03 透传 `publish_by` / `source_age_hours` | 36h 闸门的结论只在 `hot_sources` 内存里，要改供给层 | 出口 TT-03 从 `not_judged` 变 `pass/fail` 的比例 |
| TT-06 反洗稿证据 | `_src_texts` 为空时 `_similarity` 根本不写；平台的原创度检测对全网语料，两者不等价（已登记 `coverage_gap`） | 真实批次 `_similarity` 非空率 |
| 弱判据告警消费者 | 选题侧关键词重叠告警目前无人消费，TT-14 另写一套 | `review_ledger.jsonl` 落地后再接 |

**一句话区分**：本轮解决的是「判了的没处置对、能判的没去判」；
剩下的是「证据根本没产生」。后者要动生成侧，风险与前者不是一个量级。

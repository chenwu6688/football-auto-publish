# 对照《头条新手10个免费工具》做一次复杂度体检

日期：2026-11-04　｜　性质：评估，未改任何生产逻辑

## 一、被评估的文章是什么

《头条新手最常用的10个免费工具：配图、选题、写作、数据一网打尽》（拓荒者，2026-04-17）。

**它不是系统设计文，是给"一个人一天写一篇"的新手列的免费工具清单。** 十条：
头条免费图库 / Pexels / 创客贴 / 头条热榜 / 今日热榜(tophub) / 备忘录·飞书 / 易撰·乐观号 /
头条创作者中心 / 新榜 / 头条自带编辑器。

三条主张值得单独拎出来：

1. **"不要同时用太多工具，选 3-4 个用得顺手的就行"**——工具数量与产出不成正比；
2. **"不要把时间花在研究工具上，多写才是正经事"**——工具是分母，产出是分子；
3. **"平台自带的东西优先"**——头条图库（平台已买单、零版权）、创作者中心（官方数据最准）、
   自带编辑器（信息流读者喜欢清爽排版，第三方排版工具反而不必）。

还有两条可执行的具体标准，是全文最硬的部分：

- **读完率 < 30% 就去优化开头和段落**；粉丝阅读占比 < 10% 说明内容不垂直；
- **排版三要素**：每段不超过 4 行 / 每 500 字一个加粗小标题 / 关键句单独成段。

## 二、用它的尺子量本项目（全部为实测，非估计）

## 三、判断：是过度设计，但偏在"审核侧"，不在"工具侧"

文章说"工具别超过 3-4 个"。这句话对本项目**字面上不适用**——我们是流水线，工具数量与产出
本来就不该线性对应。真正的对应关系在这里：

> **41 项审核 / 1484 个单测 → 每天 2 篇发布；30 项审核连"能不能报红"都没验证过。**

所以"过度"的准确位置是：**验证投入严重大于产出规模，而验证里又有七成是装饰。**

判断每一项该不该留，只用一个判据：

> **这一项近 30 天有没有一次 FAIL 导致过动作（改文案、拦发布、改配置）？**
> 没有 → 它不是闸门，是登记表。

按这个判据分类：

**A. 必要复杂度（不能砍，砍了会重犯事故）**
- 发布台账（`publish_ledger` 三层写入）——它把"38% 发布率"从不知道变成知道；
- 采集失败分类（`scraper_diagnostics`）——区分"真没数据"与"被拦"；
- 图源误配防护（`gallery_query` 白名单 + alt 校验）——错图是事实错误；
- 三要素闸门 + `title_gate`——标题是点击率的唯一杠杆；
- 熔断与合规（第十章）、事实卡、一致性。

**B. 真过度（自造的复杂，收益未被证明）**
- 41 项 → 其中 30 项 advisory、30 项无负向用例；
- **四套配额系统同时回答"这篇写什么类型"**：`supply_mix` 三层 30/50/20、
  `content_mix` 七类型 TARGET_PCT、`batch_mix` 两槽、`topic_category`/`ratio_tuner` 另一条轴。
  项目自己的 MEMORY 里写着"两个 content_type 轴别混"——说明历史上真的混过；
- 单事件多切口六角度（`event_cluster`）+ 每批结构 + 配比 + 日上限，四层约束叠加后，
  实际能出什么由最紧的那层决定，其余三层只是让它更难出；
- `benchmark_peers` 自建 181 条对标（playwright）——价值是"可回测"，但一个月才用一次；
- 针对已被证零区分度维度的用例（"对比"维度 TOP 30% vs BOT 30%）。

## 四、可借鉴的（改造后用，不照抄）

1. **读完率作为生成侧约束**（最值得做）。文章说 <30% 优化开头；我们 33.1%，贴着线。
   现在 `content_stats` 统计了 chars/paragraphs/headings/bullets，**唯独没有段落长度和开头钩子**。
   这是 41 项审核里最明显的洞：全都在管标题和配比，没有一项管"读者会不会读下去"。
2. **排版三要素变成可校验项**：每段 ≤4 行（≈≤80 汉字）/ 每 500 字一个小标题 /
   关键句单独成段。三条都可用 `content_stats` 直接算，成本近乎为零。
3. **"平台自带优先"这条对标题同样成立**：头条的推荐逻辑吃的是完读与互动，不是我们自建的
   十维打分。`_title_score` 的十维权重是我们自己拍的，缺真实 A/B 支撑——应降级为"参考分"，
   真正的裁判只能是发布后的点击率。
4. **工具要能数出"省了多少时间"**，否则就是负债。易撰/新榜这类现成工具提醒我们：
   自建的东西必须能回答"它替代了什么等价物"。

## 五、不建议照搬的

1. **头条自带图库接进自动化**：发布走 playwright，点素材库属于 UI 自动化，脆弱且一改版就断；
   我们已有 `cover_card` 数据卡兜底，比素材库更可控。**不接。**
   若要利用，只在"零配图且当日人工值守"时补一张，不进链路。
2. **"免费版够用"**：LLM 有 80 万 token 硬上限，按"免费"决策会直接停摆。
3. **"多写才是正经事"**：我们不是写得少（6.7/天），是**发得少（2/天）+ 点得少（1.49%）**。
   这两件事都不靠"多写"解决。
4. **易撰/新榜替代自建对标**：免费版每天 10 篇、不可编程、不可回测；
   自建那套至少能进 CI 复现排序。**保留自建、降频，不替换。**

## 六、可操作清单（减法三件 + 加法一件）

**减法**
- S1 审核 41 → 12：按上面判据，`supply_mix`/`content_mix`/`benchmark_peers`/`topic_category`/
  `growth_import` 等降为"周报一行数字"，脚本保留但不进 tier，不再各自跑一个进程。
- S2 配额四套 → 一套：只留 `batch_mix`（1 主线 + 1 数据），其余三套只观测不决策。
  这一条改动最大、收益也最大：现在"出不了稿"时说不清是哪层卡的。
- S3 `orchestrator.py` 5,709 行拆出发布链路与生成链路两个模块（不是重构，是搬家）。

**加法**
- A1 `content_stats` 补 `max_para_han` / `opening_hook` 两个字段，
  在生成侧加"开篇 100 字必须有具体信息（比分/人名/时间之一）"的约束，
  验收加"段落 ≤4 行占比 ≥80%"。对应完成率 33.1% → 40%。

## 七、结论

**是过度设计，但方向和直觉相反：不是"工具太多"，是"审核太多、验证太少"。**

6.7 万行、41 项审核、1484 个单测，对应每天 2 篇发布和 63 次阅读——
这个比例本身说明复杂度已经脱离了产出规模。而 41 项里有 30 项从未证明过自己能报红，
它们贡献的不是质量，是"看起来管得很严"。

但也不能一刀切：**发布台账、失败分类、图源防误配、三要素闸门这四类必须留**，
它们各自对应一次真实事故（38% 发布率一月无人发现 / 懂球帝 567 被当空数据 /
中文 query 配出饺子 / 标题全在自我重复）。

文章真正的价值不在那 10 个工具，而在它那句"不要把时间花在研究工具上"。
对本项目的翻译是：**把时间从"加第 42 项审核"移到"让第 1 篇被读完"。**

## 1. 为什么先改标题：160 倍差距在标题层

诊断表里最刺眼的一组数：

| 指标 | 我方 | 头部对标 |
|---|---|---|
| 篇均阅读 | 40.6 | ~6400（爆款） |
| 标题三要素覆盖（三项全过） | 26.1% | 27.1% |
| 通过「≥2 项」的标题 | 60.2% | 70.7% |

三项全过比例几乎一样（26.1% vs 27.1%），差距不在「有没有要素」，而在**通过率整体低 10 个百分点**
且我方通过组与被拦组的阅读差只有 14 : 2。也就是说：我们不是不会写要素，是**写了一部分却
没写到读者会点的那一项上**——专名（86.4% 已达标）不缺，缺的是「数字」和「对比」同时在场。

## 2. 阈值为什么是「≥2 项且必含专名」，不是「三项全过」

第一版原型就是「三项全过」，回测立刻被打回：

- 我方 TOP1（494 阅读）只过 2/3 —— 三项全过会把它挡在门外；
- 我方 BOTTOM 里存在 3/3 全过的 0 阅读稿 —— 三项全过也拦不住它。

所以「三项全过」既误杀又漏放，不是一把能用的尺子。改成「≥2 项 且 必含专名」后：

| 判据 | 结果 |
|---|---|
| 我方单调性（通过组中位阅读 > 被拦组） | 14 vs 2 ✅ |
| 头部通过率 ≥ 我方 | 70.7% ≥ 60.2% ✅ |
| 头部 TOP10 通过率 ≥ 70% | 8/10 ✅ |
| 我方通过率落在 20%~85% 压力带 | 60.2% ✅ |

放宽专名的原因写在 `title_elements._TOP_PEOPLE` 的注释里：entity_map 的 558 名球员来自
五大联赛射手榜，**梅西 / C罗 / 马拉多纳 / 巴乔一个都不在**，头部样本里「梅西凭什么位列第五」
这类标题被判 0/3。补 12 位顶流 + 传奇名宿 + 中文序数（`位列|排名|第 + 十…`）后，TOP10 从
7/10 回到 8/10。

> 这条是「尺子做紧」而不是「做松」：补的是**真实专名**，不是降低专名判定标准。
> 反向证据是负向用例——裸「熬夜」曾被误判为过程锚点，这次同样给三要素配了负向断言
> （`test_ruler_not_ok_when_monotonic_flips` / `test_ruler_not_ok_when_too_loose`）。

`PEER_TOP_MIN_PASS` 最终写 **0.70** 而不是 0.80，实测 8/10 后下调，理由已写进脚本注释：
纯冲突型与代称型爆款本来就不在三要素的覆盖范围，用它们要求 100% 通过等于让尺子自己失效。
（对照 11-03 的教训：阈值红久了就会被 `|| echo` 软化，与其事后软化，不如一开始就写明适用边界。）

## 3. 出口闸门 + 供给侧必须同时改

只加出口闸门的结果是可预测的：模型开始**编数字**过闸门，或者反复被打回丢稿。

所以 P1-2 与 P0-1 一起做：

- `title_brief.collect()` 从事实卡里**搬**现成的数字 / 专名 / 对照，`-1` 占位符按缺失处理；
- `brief_text()` 把素材摊给模型，并在**没有数字时明写**「事实卡里没有可用数字……禁止自己造数」；
- 6 处 prompt 注入（`rewrite_article` / `generate_fixture_article` / `generate_recap_article` /
  `generate_event_result_article` / `generate_node_angle_article` / `generate_prediction_article`），
  AST 计数 12 个注入点（下限 6）；
- LLM 重拟失败 → `title_brief.candidates()` 机械模板兜底（4 个模板，只用事实卡里的数字），
  `art["_title_fallback"]="elements"` + `degrade.note` 留痕。

**分流是重点**：改写重试用尽后不再一律丢弃整篇，只把「三要素不足」这条判为可兜底，
其余硬违规（传闻当官宣、赛果播报式）照旧丢弃。理由写在文档里的这句：

> 三要素不足只影响「增量」（这篇大概率没人点），硬违规影响「存量」（这篇会伤信任）。

## 4. 闸门的三处口子（验收跑出来的，不是设计出来的）

第一次跑全量验收时 `verify_title_anchor` 红了：近 14 天疑问收尾 3 篇，限额 2 篇。
3 篇里有一篇是 11-04 当天的「大罗VS C罗巅峰数据对决，谁才是真正的锋线之王？」。
顺着这条线查出三个口子——**都是「有闸门但路径绕过它」**：

| 口子 | 位置 | 后果 |
|---|---|---|
| 紧急球评不传 `recent_titles` | `generate_emergency_article` | 这条路径完全不判疑问限额 |
| 预测稿不传 `recent_titles` | `generate_prediction_article` | 预测稿本身不发布，但它会以「已用过」的身份进句式池与进程内标题表，把真要发的稿挤掉 |
| 「重试 3 次不过就兜底放行」 | `ensure_fixture_title` / 各生成函数的 attempt 循环 | 结构违规（疑问收尾超限）被当成「分数不够」放行了；连 `repick_title` 返回空时也是直接放行 |

修法不是把「放行」改成「丢稿」，而是加 `_swap_to_template_title()`：结构违规时换成本地
模板标题——模板只用事实卡里已有的数字（不新增事实）、只换标题（正文一字不动）、不花 LLM 额度。
拼不出候选就保留原稿，如实留证。

> 这条与 10-25「靠字段缺失实现排除」是同一类教训的反面：**闸门只在部分路径生效，
> 等于没有闸门**。所以验收必须查「所有生成路径」，不能只查主线 `rewrite_article`。

另：`verify_title_anchor` 的疑问限额项改了判定生效日 `QUESTION_CAP_SINCE=2026-11-05`。
顺序很重要——**先补口子，再改生效日**；反过来就是拿改生效日掩盖漏洞。
11-02~11-04 那 3 篇在报告里单列「留证」，不删不藏。

## 5. 每批结构：月度配比管不住单批

`content_mix.TARGET_PCT` 是**月度占比**，一批 2 篇时它可以「今天全发战术榜单、明天全发热点」
仍然月度达标 —— 而 10 月的实际形态正是战术榜单 44%。所以单批结构必须单独管：

```
batch_mix.STRUCTURE = ("main", "data")
  main 槽：热点球评 / 紧急球评
  data 槽：数据对比 / 排行榜
  兜底：战术榜单（仅当主槽候选确实没有）
  低效不补位：人物故事 / 转会资讯 / 八卦趣事 —— 宁可少发一篇也不凑数
```

配比同步重定（热点球评 35→40、数据对比 15→25、排行榜 5→15、战术榜单 20→10、
八卦 10→4、人物故事 10→3、转会 5→3），三处镜像（`content_mix` / 两份 config）一起改。

**已知偏离，不掩饰**：A/B 结构会把「三级·软性」占比推到约 50%，超出计划 12.1 的
20%±15pp。按 11-04 的决定执行 P1-1，`verify_supply_mix` 的告警保持原样不软化——
它就该响，响了再去调结构，而不是把告警改绿。

## 6. 封面：真正的病根是「所有图源都断」

`verify_cover_coverage` 原来的判据只查图源链路，而链路上四条全部不通：

| 图源 | 状态 |
|---|---|
| 维基百科 | 本机与 CI 出口均超时 → `_WIKI_DOWN` 熔断 |
| Unsplash | 无 Key |
| DuckDuckGo | 出口 IP 常被挡 |
| footyrenders | 已停用（只返 50×50 占位图） |

结论：**即使实体识别 100% 正确，网络一断就是 0 图 → 头条主动点「无封面」→ CTR 0.52%（有封面 2.07%）**。
继续加图源治不好这个病，得加一条不依赖网络的兜底。

`cover_card.py` 生成 1200×675 的**原创数据卡**：品牌条 + 标题里已有的数字 + 标题 + 一句来源标注。
它绕开了计划 2.2 禁用的「随机图库图文不符」（图是我们自己画的，不存在版权与错配），
但也**不是**「好封面」——它只负责把最差的那条路径堵掉。这条定位写进了模块 docstring，
免得以后有人把它当成配图方案的正解。

接入点在 `save_articles_local` 的「0 图」分支，三处细节都有单测钉住：

1. 文件名必须是 `article-N-img-001.jpg` —— `publisher.extract_images` 的正则只认这个，
   否则图生成了、台账 `images` 仍记 0（测试用 **publisher 源码里的真实正则**验证，不复刻）；
2. 尺寸 1200×675 过下载端 800×600 闸门；
3. 失败返回 `None` 不抛异常，`degrade.note("封面兜底", ...)` 留痕，照旧不配图发布。

验收脚本新增 **E 项「零配图兜底」硬项**（AST 查 `cover_card.render` 且必须有 `filename` 关键字、
数据卡尺寸、degrade 策略表条目），并把 A 项判定窗口的起点改到 `FALLBACK_SINCE=2026-11-05`。

## 7. 口径纪律：生效日 + 三态

两处都按「未判定 ≠ 通过」处理，这是被 `ok=True` 假绿灯坑过之后的硬规矩：

- `verify_batch_mix` 的「产出结构」只统计**带 `batch_mix` 字段**的批次。11-04 当天早上的
  3 篇是接入前生成的（metadata 无该字段），按旧排序产出，**单列留证、不进判定**。
  这不是「靠删样本变绿」，恰恰相反：旧批次篇数会打印在报告里。
- `verify_cover_coverage` 的 `ok` 改为三态 `True / False / None`，未判定项渲染成 `⏸`，
  结论行改成「部分通过 ⏸（N 项样本不足未判定，不等于通过）」，并输出 `::warning::`。

# data 槽缺料：诊断与供给方案

日期：2026-11-09
范围：11-05 → 11-09（13 个批次 / 22 篇落盘成稿）
上游：`docs/audit/2026-11-09-选题漏斗一周复盘.md`
性质：**只诊断与提方案，未改任何业务代码、未动配额**

---

## 摘要

`batch_mix` 的 `data` 槽在 13/13 个批次里**全部降级**。上一轮把这条归因为「类型结构性缺料、
建议加媒体源」，**这个归因是错的**。真实原因是三条供给路径同时失效，其中两条是配置与映射
缺陷，不是没有数据。

| 结论 | 内容 |
|---|---|
| 是「缺数据源」吗 | **不是**。蓄水池里躺着「数据对比」26 条（可用 4 条），赛程角度表里也有对应的 BC 型 |
| 是「配额太松」吗 | **不是**。`BATCH_QUOTA` 一个数都不用动 |
| 真正的病 | 目标表要「数据对比」30%，但**没有任何一条路径能把这类稿子送进 data 槽** |
| 加媒体源有用吗 | **无用**。热点源只产「热点球评」，加十个源也不会产出一条数据对比 |

---

## 一、症状：data 槽 100% 降级，且「数据对比」产出为 0

### 1.1 槽位层

`batch_mix.STRUCTURE = ("main", "data")`，每批 2 篇就是 `main + data` 各一槽。
`data` 槽只接受 `("数据对比", "排行榜")` 两类：

```python
SLOT_TYPES = {
    "main": ("热点球评", "紧急球评"),
    "data": ("数据对比", "排行榜"),
}
```

13 个唯一「日×批次」里，**13 个都有降级记录**（降级率 100%）。但降级 ≠ 丢篇：
多数是「用次优类型补位」仍然出了稿。真损失（本批少写 1 篇）合计 9 篇。

### 1.2 产出层：目标 48%，实际 14%，其中「数据对比」是 0

22 篇落盘成稿的归一化分布：

| 类型 | 篇数 | 实际占比 | 目标 | 偏差 |
|---|---|---|---|---|
| 热点球评 | 10 | 45% | 45% | 0 |
| 战术榜单 | 7 | **32%** | 4% | **+28pp（8 倍）** |

| 八卦趣事 | 1 | 5% | 1% | +4pp |

**`data` 槽两型合计只有 14%（目标 48%），缺的 34pp 里 30pp 全是「数据对比」。**
换句话说：`data` 槽名义上有两个类型可选，实际只有「排行榜」一条腿在工作。

## 二、根因：三条供给路径同时断了

「数据对比」的稿件只可能来自三条路径。逐条查过，**三条全断**。

### 路径 A：LLM 选题 —— 提示词的品类枚举里根本没有「数据对比」

`prompts/topic_selector.txt` 的「五大内容品类」写的是：

```
- 热点球评：比赛复盘、争议判罚、战术看点
- 转会资讯：转会流言、官宣签约、续约离队
- 排行榜：现役身价榜、历史排名、教练胜率榜
- 八卦趣事：球员场外生活、教练轶事、足坛冷知识
- 战术解析：赛季前瞻、新援分析、打法演变
```

五个品类里**没有「数据对比」**，反倒有「战术解析」——而
`content_mix.ALIASES` 把「战术解析」归一成「战术榜单」，后者目标只有 4%。

「动态调配规则」也只到「八卦趣事/排行榜」，从没要求过数据对比。

结果：LLM 严格照枚举输出，22 篇里「数据对比」一次都没出现过（原始值也没有「数据对照」）。

**这是三方不一致的第三例**（前两例：`supply_mix` 规则与阈值相斥、`WIKI_TEAMS` 词表当去重基准）：
目标表（`TARGET_PCT` 数据对比 30%）与生成侧提示词（品类枚举）说的不是同一件事。

### 路径 B：赛程稿确定性供给 —— BC 型本想给「数据对照」，被「板块」抹掉了

`scripts/fixture_library.py` 的角度表里，5 型中有 1 型本该落数据类：

```python
("BC", "关注度落差", "数据对照", [...], "对照两队在聚光灯下与无人问津下的不同处境……")
```

但生成赛程稿时 `content_type` 取的是「板块」，不是 `suggested_column`：

```python
def _fixture_content_type(topic):
    """赛程分型 → 板块 content_type（计划 6.2 固定四板块：转会动态／人物故事／中国足球／战术榜单）。"""
    return topic.get("板块", "战术榜单")
```

而「板块」在 `fixture_library.py:411` 被强制成三选一：

```python
"板块": ("中国足球" if comp_name == "中超" else
         ("人物故事" if column == "人物故事" else "战术榜单")),
```

`column == "数据对照"` 既不是中超也不是「人物故事」，于是落到 `战术榜单`。

**结论：即使 BC 型赛程稿成功生成，它也会被记成「战术榜单」。**
「数据对照」这条路在供给层从来没通过，`content_mix` 那个归一别名
（`"数据对照": "数据对比"`，2026-11-06 加的）是为一个**从未到达统计层的类型**准备的。

顺带解释了「战术榜单 32%」的一半来源：LLM 的「战术解析」+ BC 型赛程稿，双双灌进同一类。

### 路径 C：蓄水池 —— 有库存，但只在「批次末尾有缺口」时救火

`data/reservoir/items.json` 共 87 条，按类型×状态：

| 类型 | used | rejected | stocked | 合计 |
|---|---|---|---|---|
| 数据对比 | 19 | 3 | **4** | 26 |
| 榜单 | 20 | 1 | 2 | 23 |
| 人物故事 | 18 | 2 | 2 | 22 |
| 历史回顾（禁发） | 13 | 3 | 0 | 16 |

**「数据对比 26 条」不能当可用量报——真正还能用的只有 4 条。**

更关键的是调用时机：`reservoir.fill_gap(_supply_gap)` 在批次**末尾**、
且 `_supply_gap > 0`（主稿已经写不够）时才触发，晨读批还直接禁用软性补位。
它在 `batch_mix.assign` 之后，**不参与槽位规划**——所以蓄水池里的数据对比
永远填不进 `data` 槽，只能当「篇数不够时的救火队员」。

### 2.4 三条路径汇总

| 路径 | 理论供给 | 实际 | 断在哪 |
|---|---|---|---|
| A. LLM 选题 | 每批若干 | **0** | 提示词品类枚举缺「数据对比」 |
| B. 赛程稿 BC 型 | 1/5 概率 | **0** | `_fixture_content_type` 取「板块」，板块强制三选一 |
| C. 蓄水池 | 4 条（可用） | 几乎为 0 | 只在末尾缺口时触发，不进槽位规划 |

## 三、为什么上一轮「加媒体源」的建议是错的

上一轮看到「13 次降级」就推「类型结构性缺料 → 加 media 源」。实际查下来：

1. **热点源只产「热点球评/八卦趣事」**，`hot_sources.PROVIDERS` 里没有任何一个源
   会产「数据对比」——加源不改变 data 槽的候选集。
2. 6 个候选媒体源已全部实测关闭（sina RSS 是 2018 死档、腾讯/虎扑纯 JS、
   goal.com 合规问题、球天下 Cloudflare、k7 博彩 SEO），加源的边际收益本来就是 0。
3. 「未选 13 次」说明候选**条数**够（只是结构只留 2 篇把候选丢了），
   不是「没料可写」。

**加媒体源对 data 槽是无效改动。撤回。**

---

## 四、方案

三处改动，全部在配置/映射层，**不碰 `BATCH_QUOTA`、不碰 `supply_mix` 比例、不加数据源**。

### 改动 1（主力）：提示词补「数据对比」，删「战术解析」

文件：`prompts/topic_selector.txt`

| 位置 | 改前 | 改后 |
|---|---|---|
| 「五大内容品类」 | ……「战术解析：赛季前瞻、新援分析、打法演变」 | 删「战术解析」，加「数据对比：积分/胜率/身价/历史交锋的数据落差，用数字讲人的处境」 |
| 输出格式 `content_type` 枚举 | `热点球评/转会资讯/排行榜/八卦趣事/战术解析` | `热点球评/转会资讯/排行榜/八卦趣事/数据对比` |
| 休赛期调配第 2 篇 | `八卦趣事/排行榜` | `数据对比/排行榜`（两者都是 data 槽可接受型） |

**为什么这是主力**：只有它能把「数据对比」送进 `batch_mix` 的候选池，
也就是唯一能真正填上 data 槽的路径。改动零成本，只改提示词文本。

**预期影响**（诚实说：无法精确预估，给区间与验收方式，不编数字）：
- data 槽候选从「仅排行榜」变成「排行榜 + 数据对比」，降级率应显著下降；
- 战术榜单占比应从 32% 回落（「战术解析」不再被要求）；
- 具体幅度取决于 LLM 是否愿意按新品类出选题，**必须跑 3 批实测，不看预估看数据**。

**风险（必须先验证）**：「数据对比」需要**可核验的真实数字**。若 LLM 选出的数据对比选题
在写作侧拿不到事实（积分/身价/历史交锋），会撞上「不许编造」硬纪律 → 稿件被出口丢掉。
所以改动 1 上线前**必须先做一次只读验证**：拿一个新批次，检查数据对比选题的
`source_facts` 里有没有真实数字。没有就先补事实供给，别急着上。

### 改动 2（补丁）：让 BC 型赛程稿真的落「数据对照」

文件：`scripts/fixture_library.py:411-412`

| 改前 | 改后 |
|---|---|
| `"板块": ("中国足球" if 中超 else ("人物故事" if column=="人物故事" else "战术榜单"))` | 增加 `column == "数据对照"` 分支 → `"数据对照"` |

或更彻底：`_fixture_content_type(topic)` 改成优先取 `suggested_column`，
没有才退回「板块」。**推荐后者**——「板块」是面向展示的四板块概念，
不该用来承载统计口径，这正是「同一量两处定义」的老毛病。

**收益有限，别高估**：`FIXTURE_PER_BATCH = 1`、`DETERMINISTIC_DAILY_BUDGET = 2`，
即使赛程源可用，BC 型只占 1/5 → 理论上限约 0.4 篇/天。而且 11-07/11-08 都出现过
「赛程源不可用」的降级。它是补丁，不是主力。

**顺带查出的问题**：一级供给实际 4/22 = 18%，低于目标 ~30%。但
`DETERMINISTIC_DAILY_BUDGET` 已经是 2 篇/天（按日 6 篇算 = 33%），**预算本身不缺**，
缺的是「赛程源拿不到」。所以**不要调大这个常量**——调了也只是空转，
和上次「supply_mix 一级 30%→20%」同型的无效改动。

### 改动 3（卫生）：清掉 `TARGET_PCT` 里的死键

文件：`content_mix.py:73`

```python
"战术解析": 0.0,   # ← 永远命中不了
```

`normalize()` 先把「战术解析」归一成「战术榜单」，所以这个键在任何统计里都查不到。
它还被算进 `ZERO_TARGET`（禁发类型），等于留了一个永不触发的禁发规则。

处理：删掉该键，或改注释说明「已归一，保留仅为兼容旧数据」。
**行为零变化**，纯粹是防止后来人以为「战术解析是禁发类型」而写错判据。

## 五、验收判据（跑满 3 批后判定）

| 判据 | 通过线 | 当前值 |
|---|---|---|
| data 槽降级率 | < 50% | 100% |
| 「数据对比」占比 | > 0（且连续 3 批都有） | 0% |
| data 两型合计占比 | ≥ 30%（先到一半目标，别一步要 48%） | 14% |
| 战术榜单占比 | ≤ 15% | 32% |
| 数据对比稿的事实点数 | > 0（否则算编造，直接判失败） | 无样本 |

**不达标就回滚改动 1**，别叠第二层补丁。

---

## 六、执行顺序

1. **先做只读验证**：新跑一批，检查数据对比选题能否拿到真实数字（不改代码）。
2. 验证通过 → 改动 1（提示词）+ 改动 3（死键），一次提交。
3. 跑 3 批，按第五节判定。
4. 改动 2 单独一轮做（收益小、依赖赛程源可用性，别和主力改动混在一起看效果）。

**本轮到此为止，一行业务代码都没改。** 要动哪一项，等确认。

  按批看降级必须用 `data/audit/topic_funnel.jsonl`，不要用 metadata。

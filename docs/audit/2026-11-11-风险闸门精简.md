# 风险闸门精简（2026-11-11）

## 一句话

`risk_gate` 现在只回答一个问题：**这篇稿子有没有断言某真人/俱乐部涉违法或丑闻？**
有 → 转人工确认；没有 → 照常发布。词表 17 个词，判定 1 个函数，没有分级、没有队列。

## 为什么删到只剩这一条

对照头条号扣分条款（`config/toutiao_rules.yaml`，27 个扣分项 / 四档分值）：

| 闸门原判据 | 平台扣分依据 | 结论 |
|---|---|---|
| 伤病（受伤/伤停/赛季报销…） | 无 | 删除。赛前伤停名单是足球稿的常规背景，命中率接近 100% |
| 合同金额（转会费/年薪/续约 + 金额正则） | 无 | 删除。续约年限、转会费同样是常规背景，还要额外维护一个金额正则 |
| 争议指控（指控/假球/禁赛/处罚…） | 虚假内容 70/20/10 三档 | 保留，但收紧词表 |

后果是实证过的：2026-11-10 晚与 11-11 晨**连续两批 4/4 篇全部转人工**，
发布集合 0 篇、`publisher` 走 `EXIT_NOTHING_EMPTY(3)`、workflow 判失败且不标批次完成。
那两篇的真实拦截原因是「伤病(伤停)」「合同金额(合同)」——**与扣分毫无关系**。
关键词闸门挡不住「推断错」「数据错」，唯一挡得住的就是「凭空给真人扣罪名」。

## 删掉的东西

| 删除项 | 原规模 | 为什么删 |
|---|---|---|
| `伤病` / `合同金额` 两类 + `_MONEY_RE` 金额正则 | 31 个词 + 1 条正则 | 与扣分无关，且是 0 篇事故的直接原因 |
| `high_risk` / `blocking` / `severity` 三层结果 | 3 个字段 | 只有「拦 / 不拦」两种现实结论，中间层没人消费 |
| `data/pending_review.json` 队列（enqueue / pending_items / resolve / materialize / CLI） | ~110 行 | 该文件在 `.gitignore`，CI runner 跑完即销毁 —— 队列在流水线上**从未存在过** |
| `metadata.risk_flags` 留证 | 1 个字段 | 留的是伤病/金额命中词，平台侧不会因此扣分，留了也没人看 |

人工确认的唯一产物是 `output/<date>/review/review-*.md`（orchestrator 落盘，
随 artifact 下载），确认后走 `workflow_dispatch` 补发。

## 留下的判定

```python
risk_gate.blocked_reason(article) -> str   # "" = 可以发
```

词表只收「断言违法违规」的词：指控、起诉、诉讼、立案、被捕、拘留、假球、赌球、
操纵比赛、禁药、兴奋剂、性侵、种族歧视、受贿、行贿、逃税、丑闻。

**刻意不收**「禁赛 / 处罚 / 罚款 / 调查 / 上诉 / 仲裁」：累积黄牌停赛、俱乐部被罚款、
足协调查青训都是正常新闻，收进来就是误伤。

## 边界

- 这道闸门是**关键词级**的，不是事实核查。判不了「数据写错」「因果推错」——
  那类由出口的合规审核（`scripts/verify_compliance.py`，TT-01/02/03…）按事实层判。
- 误伤仍然可能存在（正当地写「他被指控假球」也会被拦）。代价是一篇文章延迟发布并留原文，
  比反过来让一篇 70 分档的稿子直接发出去便宜得多。
- 放宽闸门不是取消证据：`pending_review[].review_path` 仍写进 metadata，
  `scripts/publish_zero_reason.py` 据此区分「风险闸门转人工 / 合规全剔除 / 上游空转」。

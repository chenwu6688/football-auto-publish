# 足球领域图源全网调研与维基共享落地

日期：2026-11-04　｜　提交：见 git log　｜　关联：`docs/audit/2026-11-04-Pexels实测与图库白名单.md`

## 一、结论先说

**足球领域不存在「免费 + 有球员真人照 + 可商用 + 有 API」的通用图库。** 这不是搜索技巧问题，
是行业结构决定的：球员肖像权在俱乐部/经纪公司/联赛手里，新闻图由 Getty / Reuters / IC Photo 垄断，
免费图库拿到的是摄影师自己拍的风景和球场，拿不到人。

唯一例外是 **Wikimedia Commons**（社区上传、逐张标注自由许可、1.5 亿文件、无需 Key）。
本轮把它接进链路，并补上一件此前一直缺失的事：**署名**。

## 三、网络现实：本机能到哪，CI 能到哪

实测（`curl` + `requests`，代理与直连各测一次）：

```
代理 commons.wikimedia.org  EXC ReadTimeout 10.1s
直连 commons.wikimedia.org  EXC ReadTimeout 10.2s
代理 upload.wikimedia.org   EXC ReadTimeout 10.1s
直连 upload.wikimedia.org   EXC ReadTimeout 10.2s
代理 api.wikimedia.org      EXC ReadTimeout  8.4s
```

`r.jina.ai` 与 `allorigins` 两条中转也拿不到（前者空响应、后者 520）。所以：

- **本机永远取不到 Commons 图**，这不是代码问题；
- GitHub Actions 的 runner 在境外，可以取到 —— 真实验证只能在 CI 做；
- 因此验收脚本的联网项做成三态：**不通判「未判定」并返回 2，不是通过**。

## 四、落地了什么

### 4.1 `wiki_media.py`（新模块，~380 行）

三条合规条件，缺一条就不许用：

1. **许可白名单，fail-closed**：只收 `CC0 / Public domain / CC BY / CC BY-SA`，
   含 `NC`/`ND` 变体、`Fair use`、`Non-free`、`GFDL`、未知许可**一律拒**。
   Commons 上的 `{{Copyrighted free use}}` 也拒——它既无标准许可名也无署名要求，
   没法在正文里合规标注。
2. **必须能署名**：`Artist` 为空的图直接拒。CC BY 要求署名作者+许可，
   署不了名的图就是不能用的图。
3. **尺寸与消歧**：≥800×600；文件名/描述/分类必须命中实体 token（长度 ≥5，挡短词误撞）；
   **球员类还必须落在 football/soccer 分类下**——这是挡「苏格拉底→希腊哲学家」
   「Hulk→绿巨人」「Carlos→罗伯托·卡洛斯」这类同名误配的主防线。

`attribution`（作者/许可/许可链接/文件页）随图返回，由 `orchestrator` 落到正文末尾：
`图片来源：Wikimedia Commons／Jane Doe（CC BY-SA 4.0）`

### 4.2 链路分层（现状）

```
⓿ 新闻源正文图 source_images   ← 最准（就是那场比赛的图），零版权风险
① 维基条目页首图 wikipedia     ← 33 手工实体 + 实体词典
①' 维基共享 Commons           ← 新增，按文件检索，量级大一个数量级
③ Pexels（10 队球场照，alt 校验）
④ 标题数据卡 cover_card        ← 全断时兜底，原创信息图不引版权素材
```

`_wiki_available()` 熔断管着 ①①'：连续 2 次连不上就整批跳过，不让每篇稿子白等。
`LAST["network"]` 用来区分「连不上」（熔断）与「真没图」（不熔断）——
不区分的话，一个冷门实体就把整个图源关掉。

### 4.3 删掉两条死链路（净复杂度不增反降）

- **Pixabay 停用**：元数据只有 tags（`football, stadium, ball`），不含球场名/队名，
  `accept` 校验必然全挂 → 每次白花一个请求且永远取不到图。留着只会让配图率
  看起来多一条链路，实际贡献 0。
- **DuckDuckGo 删除**：本机走代理直接超时、CI 拿不到 vqd；返回的是任意中文站点的图，
  只有「标题命中实体」一道弱校验，既是版权风险也是配错图的主通道。

### 4.4 补上一直缺失的署名

**这是一处实际存在的许可违规**：此前 `search_wikipedia` 直接取 `pageimages` 的
`originalimage`，用 CC 图**零署名**。本轮把 `attribution` 透传到下载结果，
只有真落盘的图才署名（未落盘的候选不署），正文末尾追加一行，并且幂等不重复。

## 五、明确不做的

**头条平台自带图库不接自动化。** 它确实是最省事的正版图源（平台已买单、零版权风险），
但发布链路是 playwright 点 UI，点「素材库→搜索→选图」属于 UI 自动化：
平台一改版就断，而且断的时候会静默失败。我们已有 `cover_card` 数据卡兜底，比它可控。
若要用，只在人工值守时补一张，不进链路。

## 六、验收

新增 `scripts/verify_wiki_media.py` 6 项：

| 项 | 判据 |
|---|---|
| A 模块自检（硬） | 33 项：许可白名单 / 署名 fail-closed / 消歧 / 两种 formatversion |
| B 许可 fail-closed（硬） | 8 条负向：Fair use、Non-free、GFDL、NC/ND、未知许可、无作者，一个都不许进 |
| C 接线（硬） | Commons 真被调用、真走熔断、Pixabay/DDG 真摘除、`cover_binding` 认这个源 |
| D 署名落正文（硬） | `append_credit` 生效且幂等；orchestrator 有 attribution→正文的数据流 |
| E 熔断语义（硬） | 超时→标记 network；取空→不标记 |
| F 联网实测（**三态**） | 本机不通 → 未判定，返回 2，**不是通过** |

单测 `tests/test_wiki_media.py` 27 项，负向用例都是实证的：
中文 query 不得发出请求、Fair use 图被拒、球员图无 football 分类被拒、
超时必标记 network、取空不得标记、Pixabay/DDG 不得再被调用。
已登记 `config/audit_tiers.yaml`（code-change + weekly，advisory），负向债务仍为 30。

## 七、仍未验证的（明确标出）

1. **Commons 真实取图效果**：本机网络不通，只能等 runner 上第一次 weekly 跑。
   预期风险：球员类卡片因分类不含 football 被过度拒绝（宁可少配，不会配错）。
2. **真实命中率**：一篇稿子能不能拿到 1~2 张，要看 558 名球员/151 支球队在 Commons 的
   实际覆盖。若长期 0 张，应检查是不是分类闸门过严，而不是去放宽许可。
3. **Flickr / Google CSE** 两条候选未实测（Flickr 需要申请免费 key，
   Google CSE 有 100 次/天免费额度且支持 `rights=cc` 筛选），留作 Commons 覆盖不足时的备选。

## 八、用户侧待办

**无。** 这次不需要任何 Key、不需要改 Secrets。Commons 免 Key，
署名由代码自动落正文。唯一要做的是等 weekly 巡检在 runner 上跑一次，
看 `data/audit/wiki_media_latest.json` 的 F 项从 ⏸ 变 ✅。

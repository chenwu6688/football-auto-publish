# 配图相关性：从「去 logo 转载」转向「正文事实重绘」

- 日期：2026-11-05
- 触发：用户提出「选题本来就来自懂球帝、直播吧、贴吧、腾讯体育，能不能直接调用他们的图片、去掉 logo」
- 结论：**去 logo 不可行，而且方向是反的**；改为把正文已经陈述的事实重绘成图

---

## 一、为什么「去掉 logo」不可行

《著作权法》**第五十三条第（七）项**把「故意删除或者改变作品上的权利管理信息」单列为一种侵权行为，与「未经许可复制传播」并列：

> 未经著作权人许可，故意删除或者改变作品、版式设计、表演、录音录像制品或者广播、电视上的权利管理信息的，知道或者应当知道……仍然向公众提供的，应当承担民事责任；损害公共利益的，可处二十五万元以下罚款；构成犯罪的，追究刑事责任。

关键在于**去掉 logo 这个动作本身**就是一个独立侵权行为，不需要同时构成「未经许可使用」。而「故意」这个主观要件：

- 「带水印原样转载」→ 难以证明故意，出事多是删稿道歉；
- 「写代码批量去 logo」→ 动作本身即证据，没有「我不知道这有版权」的抗辩空间。

同时它还会额外侵犯署名权（第十条第二项）与保护作品完整权（第四项，篡改）。

### 反直觉的一点：去 logo 提高了被索赔概率

带水印转载时，媒体至少还获得品牌曝光，多数选择先投诉、要求删稿。去掉 logo 后，这张图在读者眼里已经「无主」，版权方失去任何容忍动机，直接从「睁一只眼」变成「必追」。

体育图片恰好是维权最成熟的领域：中超 2017-2019 图片独家权益，东方IC（映脉）以 2000 万竞得；Osports 因擅拍销售被海淀法院判赔 300 万 + 11 万合理费用。这个行业有明确持权方、有判例、有专业维权机构。

### 平台侧也不可逆

头条号信用分规则里「侵犯著作权」扣 30 分，规则原文写「未经授权使用他人享有著作权的内容」。100 分扣满封号，且该身份信息被平台**永久拉黑**，不再支持注册新号。官方另明确表态：标注「图片来源于网络，侵删」不能免责。

## 二、改走的路：把正文事实重绘成图

免费图库在足球题材上结构性为空（球员肖像权不在图库手里），爬新闻站有版权灰线。第三条路是**换一类图**：

> 数据源就是正文本身。文章写了「皇马 27 分紧追」，就画皇马在积分榜第 2、27 分、前后各三名的位置；文章写了「2-1 瓦伦西亚」，就画这场球的进球时间轴。

三个好处同时成立：

1. **相关性不需要证明**——图里画的就是文章说的那件事；
2. **版权完全干净**——自己算、自己画，不复制任何他人作品；
3. **信息增量**——读者看完标题再看到积分榜位置，比看一张球员特写更有用。

### 三种图与数据来源

| 图 | 用到什么数据 | 真实来源 |
|---|---|---|
| 积分榜区间图 | `standings`（名次/积分/场次/净胜球） | football-data.org |
| 进球时间轴 | `goals`（`{minute, scorer, scorer_team}`） | 直播吧战报进球事件 |
| 比分卡 | `home_score` / `away_score` | 公开赛事比分 |

英文队名（`Real Madrid CF`）与中文正文（「皇马」「皇家马德里」）的归一，复用
`config/entity_map.json` 里的 `name_en` / `name_zh` / `aliases`（709 个实体）。

### 底线：没有数据就不画

`chart_goals` 无进球事件返回 `None`；`chart_score` 缺比分返回 `None`；
`chart_standings` 缺积分返回 `None`。宁可这张图不存在，也不补画一张「看起来像数据」的图——
那比配错新闻图更糟，因为它是在用数据的外形骗读者。

## 三、相关性怎么被真正保证

图与正文的一致性不靠肉眼，靠每张图自带的 `anchor`：

```json
{"kind": "goals", "entities": ["皇马", "瓦伦西亚"],
 "numbers": ["2", "1"], "source": "直播吧战报进球事件"}
```

`anchor` 在**绘图函数内部**生成，不接受调用方传入——否则会出现「图里画皇马、
anchor 写巴萨」这种自欺。

入库前由 `image_relevance.check()` 逐条核：

1. **实体全部命中**（硬门禁）。图里但凡有一支队文章没提，这张图就与本文无关。
2. **数字至少命中一个**（硬门禁）。文章讲这场比赛，不可能既不提比分也不提名次/积分。

### 串味必须消解

「国际米兰」里含有「米兰」，而 AC 米兰的别名正是「米兰」。只做 `"米兰" in content`
会把国米的文章配上 AC 米兰的图。所以判定要先扫**全局球队词典**，按最长匹配占位，
短写法被更长队名整段吞掉时不算命中。这条有独立单测与 `--selftest` 用例覆盖。

## 四、五条护栏（对应 `scripts/verify_image_relevance.py`）

| 项 | 查什么 | 失守后的表现 |
|---|---|---|
| A 接线 | 保存层真的调用 `data_chart.candidates` 与 `filter_candidates`，且闸门在入库之前 | 模块写好了但没接上，配图行为毫无变化 |
| B 闸门行为 | 六条用例（放行 2 / 拒绝 4），含串味 | 闸门恒真，配错图无人知 |
| C 不画假数据 | 无进球/无比分/无积分/无比赛数据时必须返回 None | 用数据的外形画假图 |
| D 无残留图 | 被拒的图必须从磁盘删除 | `file_writer` 扫目录仍计入 → 台账 3 张、读者看 2 张 |
| E 产物闭环 | 拿产物里的 anchor 配产物正文**重跑闸门**，必须仍通过 | anchor 是事后编的，留证无意义 |

D 项不是假想：`file_writer` 的 `image_paths` 就是扫 `images/` 目录得出的。被闸门
拒掉却留在盘上的图，会被当成「已配图」。

E 项也不假：`metadata.image_anchors` 存的是**完整 anchor**而不是一句人读摘要，就是为了
能闭环复验。只存摘要等于只留了个说法。

## 五、实测

- 数据图三型渲染通过，尺寸 1200×800（过正文 600×400 闸门）
- 端到端（正文讲皇马 2-1 瓦伦西亚）：出 2 张数据图 + 1 张信息图 = 3 张，正文 3 处引用，
  `image_anchors` 两条 confidence 均为 `high`
- 端到端（正文只讲皇马引援）：积分榜图被拒，留证
  「数字与正文不符：2、27 一个都没出现」，退回信息图
- 单测 1647 passed / 94 subtests（本项 +28）
- 45 项验收脚本：见 `data/audit/image_relevance_latest.json`

## 六、边界与遗留

1. **数据图只在当天有比赛数据时才出**。纯转会/花边稿没有 `standings` 与 `fixtures`，
   仍然只能走新闻图或信息图。这是数据源的客观限制，不是实现缺陷。
2. **新闻图仍在灰线上**。`news_images.py` 下载直播吧正文图属于未授权使用，只是没去 logo、
   保留了来源。数据图铺开后，应逐步把新闻图降为「数据图不足时的补位」，最终目标是停用。
   这一步需要观察一段时间每篇的图源构成再定，不建议一次切死。
3. **相关性是「报道级/事实级」，不是「像素级」**。数据图能保证图里那个人就是文章写的那个人，
   新闻图只能保证出自讲本文实体的报道。
4. **AI 场景图没有纳入自动流水线**。CI 里无法调用图像生成，只能人工补图；因此自动链路
   保持「数据图 + 新闻图 + 信息图」三档。

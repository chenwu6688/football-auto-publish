# 转粉与互动数据接入（R11 内容诊断 2026-10-13「建议5」）

## 最快用法：你只交文件，其余全自动

```bash
# ① 把头条后台导出的文件放到任意位置（或直接丢进 data/inbox/）
# ② 一条命令跑完：收文件 → 入库 → 滞后监控 → 刷新看板 → 调参建议 → 汇总报告
python3 scripts/weekly_review.py --from ~/下载 --commit
```

`--commit` 会把数据变更提交推送到仓库；不加就只落本地。跑完看
`data/audit/weekly_review_<日期>.md` 一份人话摘要（导入了什么、数据到哪天、
关键指标、要你注意什么）。

| 参数 | 作用 |
| --- | --- |
| `--from <文件或目录>` | 把该处导出文件收进 `data/inbox/`（按 sha256 去重，同名不同内容加哈希后缀不覆盖） |
| `--dry-run` | 只识别，不动库、不写产物（先看一眼会导入什么） |
| `--commit` | 顺带 git 提交推送（默认不提交） |
| `--no-dashboard` / `--no-tuner` | 跳过看板 / 调参建议 |
| `--days 30` | 看板统计窗口 |

纪律：识别不出的文件**原样留在 inbox** 并在摘要里点名（`ok=False`，要人看一眼）；
调参**只出建议不改配置**；缺失指标一律「待接入」，绝不用 0 冒充。

验收：`python3 scripts/verify_perf_ingest.py`（硬项 H 覆盖本入口的接线与零副作用）

## 为什么单独做一条通道

R11 真实数据：**粉丝阅读占比中位 0%**（同类健康号 20-40%）、互动率仅健康号 1/3，
账号只吃推荐流量、权重上不去。而「转粉」这条线此前**完全没有数据**——因为
头条「图文数据」导出根本没有涨粉列：

```
标题 / 发布时间 / ID / 链接 / 展现量 / 粉丝展现量 / 阅读量 / 粉丝阅读量 / 点击率 /
平均阅读完成率 / 平均阅读时长 / 点赞量 / 评论量 / 转发量 / 分享量 / 收藏量     ← 16 列，无涨粉
```

所以本模块用**两条腿**补：

| 数据 | 通道 | 落地物 |
| --- | --- | --- |
| 互动引导（评论/站队/投票） | 生成侧硬校验 | `interaction_bait.py` + `config/interaction_bait.yaml` |
| 转粉（日涨粉/粉丝总数） | 独立导入通道 | `growth_import.py` + `data/growth/fans_daily.json` |

## 一、操作节奏：现在全自动，手动是兜底

**默认不需要你操作。** collector（`scripts/collect_toutiao_exports.py` + workflow
`toutiao-collector.yml`）**每天 06:00 CST** 自动登录头条后台，把「作品数据」「粉丝分析」
两页各导出**前一天**一整天，落 `data/inbox/`；09:10 的 perf-ingest 自动识别入库。
每次运行结束都发 WxPusher 回执（成功汇总 / 失败详因），状态始终知情。

| 通道 | 频率 | 说明 |
| --- | --- | --- |
| **collector 自动投递**（默认） | 每天 06:00 | 与 perf-ingest 09:10 消费、绩效台账按日 upsert（同 date+slug 覆盖不重复计数）、转粉日差跨度守卫全部对齐；登录态与 publisher 共用同一 secret，不新增维护面 |
| **手动投递**（兜底，永远保留） | 按需 | collector 失败（登录过期/页面改版）时会告警并提示你手动导出——自动化是增量不是替换 |

### 关键前提：导出粒度必须是「每天一行」

collector 默认只导「昨天」一天，正好落在日粒度上；手动兜底时注意：

- **每天一行**（后台正常形态）→ 任意区间都能用，脚本按行内日期逐日落库，日涨粉准确；
- **只有月末汇总一行** → 跨天的区间净增会被跨度守卫拦下，**日均涨粉拿不到**；
- 第一次导出时确认一下：「统计日期」列是不是**每天一行**。

**跨度守卫**（`growth_import.derive_deltas`，2026-10-13 加固）会挡住跨天的区间值：
相邻已登记日间隔 >1 天时，差额只记为 `interval_gain`（区间净增），**不写进日涨粉**；
`check_perf_lag` 会提示「请改按每天一行导出」。宁可显示「待接入」，也不拿区间值冒充单日值。

### 作品数据与粉丝分析的节奏差异（自动模式下已抹平）

| 数据 | 旧建议 | 现在 |
| --- | --- | --- |
| 作品数据（阅读/点击率/完读率） | 每周至少一次，更勤更好 | 每天自动导前一天；`performance_logger` 按 (date, slug) upsert，数据持续增长时后一天快照覆盖前一天，不重复计数 |
| 粉丝分析（日涨粉/粉丝总数） | 每周一次足够 | 每天自动导前一天一行，正好匹配日差逻辑 |

**手动兜底实操**：收到 collector 失败告警 → 登录头条后台 → 选「昨天」→ 导这两个文件 →
丢进 `data/inbox/`，剩下的交给 CI（每天 09:10 自动消费 + 滞后监控）。

## 二、转粉数据怎么进

### 0. 最省事的做法：丢进投递箱（推荐）

```bash
# 把头条后台下载的导出文件（作品数据 / 粉丝分析都行）直接丢进：
data/inbox/

# 然后跑一次（或等 CI 每天 09:10 自动跑，见 .github/workflows/perf-ingest.yml）
python3 scripts/ingest_exports.py
```

脚本会**自动识别类型**并入库、把文件归档到 `data/processed/<日期>/`、按 sha256 幂等去重；
识别不出类型的文件**原样留在 inbox** 并报 `unknown`（不猜、不导入）。
滞后再由 `scripts/check_perf_lag.py` 量化告警（绩效 >3 天 / 转粉 >7 天 / 覆盖率 <50%）。

### 1. 从后台导出

头条后台 → 数据 → **粉丝分析** → 选日期范围 → 导出。
导出文件只需含两列中的任意一列（脚本自己认列名）：

```
统计日期,粉丝总数,涨粉数
2026-10-01,10000,12
2026-10-02,10025,        ← 涨粉数缺失也没关系
2026-10-03,10060,35
```

- 只有「粉丝总数」时，脚本按**相邻已登记日差分**算出日涨粉（`10-02 = 10025-10000 = 25`）；
  缺失日**不插值、不猜**；**相邻日间隔 >1 天则不算**（区间净增 ≠ 单日涨粉，见第一节跨度守卫）。
- 后台占位符 `-1 / -1.00`（＝无数据）一律判 `None`（待接入），**绝不折算成 0**；
  真实的 `0` 才是 `0`。
- 也可以手抄两列成 CSV（模板见 `docs/粉丝分析_导入模板.csv`），或直接放 `.xlsx`。

### 2. 入库

```bash
# 先干跑看看解析结果（不入库）
python3 growth_import.py --from ~/下载/粉丝分析.xlsx --dry-run

# 确认无误后落盘（合并写：不覆盖已有真实值）
python3 growth_import.py --from ~/下载/粉丝分析.xlsx --write

# 自检
python3 growth_import.py --selftest
```

落盘位置 `data/growth/fans_daily.json`：

```json
{
  "updated_at": "2026-10-13 17:20",
  "source_files": ["粉丝分析.xlsx"],
  "days": {
    "2026-10-01": {"total_followers": 10000, "new_followers": 12},
    "2026-10-02": {"total_followers": 10025, "new_followers": 25,
                   "derived": "total_delta", "derived_from": "2026-10-01"},
    "2026-10-31": {"total_followers": 13000,
                   "interval_gain": 3000, "interval_span_days": 30,
                   "interval_from": "2026-10-01"}
  }
}
```

> `interval_*` = 跨度守卫拦下的**区间净增**（例中 10-31 那天没有 `new_followers`，
> 因为 3000 是 10 月整月的净增、不是单日值）。补上日粒度导出后这些键会被自动撤掉。

### 3. 看板口径

`scripts/build_metrics_dashboard.py` 的「日均涨粉」取数顺序：

1. **文章级**：`metadata.performance` / `output/performance_log.json` 的 `new_followers`
   （来源标 `文章级导出`）；
2. **账号级兜底**：`data/growth/fans_daily.json` 落在同一统计窗口内的日涨粉
   （来源标 `粉丝分析通道`）；
3. 两者皆无 → `null`，看板显示「待接入」，**绝不用 0 冒充**。

> ⚠️ 2026-10-13 修正：`toutiao_import._fill_metrics` 此前对「缺列」填 0，
> 导致 550 篇成稿全部被写成 `new_followers = 0`、看板虚报「日均涨粉 0.0」。
> 已改为「缺列 = None（待接入）」，并清理了这 550 条伪造值。

## 三、互动引导怎么硬落地

提示词里一直写着「粉丝沉淀钩子·必须满足」，但**没有生成后校验**，等于没写。
现在由 `interaction_bait.py` 把「关注引导 + 互动引导」变成可打回的门禁项：

| 环节 | 行为 |
| --- | --- |
| 生成侧（Pipeline A / 确定性供给） | 缺任一类 → 打回重写（附 hint），最多 2 次 |
| 保存侧（`save_articles_local`） | 仍缺 → 按 `interaction_type` **模板兜底注入**并复核 |
| 留痕 | 兜底命中的成稿在 metadata 落 `interaction_bait_source = "template_fallback"` |

「缺互动引导」**只打回/兜底，绝不丢弃整篇成稿**——正文事实才是主体。
另外 `interaction_bait` 字段非空（此前被静默跳过）现在也会被注入，不再白丢。

判定用的正则**必须带引导语境**，所以「值得关注，这事闹大了」这类事实性用词不会误判成钩子。

```bash
python3 interaction_bait.py --selftest
python3 interaction_bait.py --file output/2026-10-13/article-1-xxx.md
```

验收：`python3 scripts/verify_growth_loop.py`

## 四、绩效回填自动化（建议7）

```bash
python3 scripts/ingest_exports.py        # 消费 data/inbox/
python3 scripts/check_perf_lag.py        # 滞后监控（绩效/转粉/覆盖率）
```

CI：`.github/workflows/perf-ingest.yml`（每天 09:10 CST + 手动触发）——消费投递箱 → 滞后监控 →
把 `data/growth`、`data/processed`、`data/ingest_state.json`、`output/*/metadata.json`、`data/audit`
回写提交。这样「导出 → 入库 → 看板 → 告警」是一条自动链路，数据不再滞后一周。

验收：`python3 scripts/verify_perf_ingest.py`

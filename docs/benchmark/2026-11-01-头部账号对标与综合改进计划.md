## 一、先说清楚这份对标的数据边界

**我拿到的是什么**：4 个账号主页上 181 条真实作品的「标题 + 阅读量 + 评论数 + 发布时间」。这是账号主页自己显示的数字，不是转述、不是榜单软文。

**我没拿到的**：粉丝增长曲线、推荐曝光量、完播/阅读时长、选题来源、收入。这些只有后台能看，我没有，不做推测。

**两个必须说明的口径差异**：

1. 账号主页显示的是「**N 阅读**」，我方后台是「阅读量」。两者都是最终阅读数，但**统计窗口可能不同**（头条作品数据会随时间累加，主页显示的是当前累计值）。所以下面的对比是**数量级对比，不是精确对齐**。
2. 我抓的 181 条是**账号主页近期滚动窗口**（约 1~7 天），不是我方固定的自然月口径。

**我主动排除的样本**：

| 排除对象 | 原因 |
|---|---|
| "2026世界杯观赛指南：5位顶尖足球赛事科普博主"这类榜单文 | 通篇是"全网粉丝 400 万""单场播放 500 万"的招商话术，无一处可验证，属付费软文 |
| 俱乐部/联赛官方号（巴萨、皇马、阿森纳、中超联赛、咪咕足球） | 运营目标不同（品牌曝光≠流量变现），且实测数据极低（见发现五） |
| 蹭词噪音号（"我拿蚂蝗给国足…"29.9 万粉、"江苏欧冠装饰"4.7 万粉、"国足臭豆腐总店"） | 关键词命中但赛道不同 |

### 这张表最刺眼的一行

**西甲二人转 23 万粉，中位阅读 77。我方 0 粉起步，中位阅读 8。差 9.6 倍。**

但它 83 条里只有 8 条过千，最高 5.4 万 —— 它跟我方一样是"抽奖模式"，只是**彩票中奖率高 10 倍**。

而 **英超那些事 15 万粉，14 条全部过千**。同一赛道、同样内容类型、粉丝还少一半。**这说明"发多少"不是变量，"每条值不值得点开"才是。**

### 足球部落那条最该被记住

79.2 万粉的足球头部号，主页近期内容是：

```
孙颖莎4-3险胜 保持对早田希娜22战全胜 晋级蒙彼利埃女单四强    1.4万人看过  5539赞
WTT蒙彼利埃冠军赛-陈熠3-0淘汰王曼昱 晋级女单八强           112.8万人看过  5840赞
```

**它在足球赛道做到 79 万粉之后，把内容主力换成了乒乓球。**

这不是它"不专业"，是**足球在头条的流量池天花板本身就低于国乒**。今天热榜第一是「江苏省委书记省长为苏超冠亚军颁奖」（热度 1572 万），能上榜的足球话题是"苏超"这种全民情绪事件，不是欧冠战术分析。

**对我们的含义**：不是要改做乒乓球，而是**别指望靠"写得好"突破项目流量上限**。足球赛道的现实水位就在这，改善空间在"单篇点击率"，不在"涨粉速度"。

## 三、六个可验证的发现

### 发现一：我们的标题 85.5% 用疑问句收尾，头部几乎不用

| 标题特征 | 我方（n=76） | 头部（n=181） |
|---|---|---|
| 疑问句收尾 | **85.5%** | 13.3% |
| 感叹句 | 1.3% | 54.1% |
| 含具体数字 | 40.8% | 72.9% |
| 冒号结构（主体：细节） | 6.2% | 42.5% |

我们的典型标题：`米兰德比谁先崩？国米22分压着米兰，两位主帅的底牌竟然差在这？`
头部的典型标题：`主场0-3大败，利物浦彻底崩盘！近7轮输了6场，球迷第80分钟退场`

**「疑问收尾」在头条是明确的反向信号**。我方 65/76 篇用这个句式，中位阅读 8。

### 发现二：数字和感叹单独都没用，必须组合

| 标题组合 | 头部样本 | 中位阅读 | 过千率 |
|---|---|---|---|
| **数字 + 感叹** | 88 条 | **1,354** | **59%** |
| 数字 + 情绪词 | 30 条 | 1,124 | 53% |
| 感叹但无数字 | 10 条 | 236 | 20% |
| 数字但无感叹无情绪 | 39 条 | 172 | 23% |
| **书面语倾向** | 13 条 | **26** | 23% |
| 三者都没有 | 35 条 | 76 | 11% |

**我方对应数据**：
- 「无数字 + 无感叹 + 无情绪」：44 条（占 58%），**中位阅读 4**
- 「数字 + 感叹」：**1 条**

同一条规律，在头部是 1,354，在我方是 4。方向一致，程度差 300 倍。

### 发现三：真正的分界线不是「有没有数字」，是「有没有过程张力」

这是本次对标最有价值的发现。同一账号、同一赛事、同一天的两组标题：

**4 阅读**：
> 2026金球奖揭晓：凯恩凭73球夺魁，终结英格兰25年奖项荒

**11 阅读**：
> 德国杯：拜仁6-1大胜马格德堡，多点开花挺进1/8决赛

**18,000 阅读**：
> 让3追4！拜仁史诗级大逆转，30分钟连轰4球，凯恩替补完成绝杀！

**两组都有数字，都有感叹号候选位置。区别是：**
- 前者在**陈述结果**（谁赢了几分、终结了什么荒）—— 读者扫一眼就知道结论，没有点开的理由
- 后者在**描述过程的反常**（让3追4、30分钟4球、替补绝杀）—— 结果未知，必须点开

**这条可以量化**：标题里是否包含「过程锚点」——

```
让X追Y / 第N分钟 / N分钟N球 / 读秒 / 补时 / 绝杀 / 逆转 / 连丢N球 /
红牌罚下 / 伤退 / 替补建功 / N轮不胜 / 领先N分被追平
```

我方 76 篇里命中「过程锚点」的是 **0 篇**。全部是"…到底戳中了谁？""…他图个啥？""…还认得出吗？"这类**没有过程的空问**。

**同一件事发了 15 个切口**：赔率、排名、奖项汇总、叔叔炮轰、落泪、包机、皇马抵制、C罗减刑、凯恩创纪录……

**这才是"覆盖模式"真正的含义**——不是多发不同的事，是**同一件事多角度打透**。

注意最后那行：**凯恩夺冠那条只有 118 阅读，而亚马尔哭那条 7,227**。同一个奖、同一个账号、同一天。
→ 在这个赛道，**"输家的情绪细节"比"赢家的成就罗列"值钱**。但这条只在「我爱英超」内部成立（2.7 倍），在「西甲二人转」内部是 1.0 倍（见局限说明）。

### 发现五：粉丝数几乎不带来阅读

两个反常识样本：

| 账号 | 粉丝 | 单篇阅读 |
|---|---|---|
| 巴塞罗那足球俱乐部（官方认证） | **28.6 万** | **21 / 37 / 49 / 55 / 61** |
| 足球隽言（《体坛周报》全媒体记者认证） | 4.3 万 | 165 / 246 / 274 / 289 |
| 我爱英超（无认证） | 10.3 万 | 中位 **1,090** |

**28.6 万粉的巴萨官方号，单篇 21 人阅读。**

这说明头条是**纯算法推荐分发**：粉丝量对单篇阅读的贡献接近于 0，能不能进推荐池只取决于**标题 + 首图 + 前 3 行**。

**对我们的含义**：别再拿"涨粉"当北极星指标。粉丝 10 万但篇均 20 阅读的号，商业价值不如 1 万粉但篇均 5000 的号。**唯一该盯的指标是「单篇阅读中位数」。**

顺便：**"体坛周报记者"认证没有流量红利**。足球隽言篇均 244，比无认证的我爱英超低 4.5 倍。**专业资质不等于流量**——这直接打掉"内容要更专业才能起量"这个假设。

### 发现六：头部日更量比我们低

| 账号 | 产出节奏 |
|---|---|
| 英超那些事 | 抓到的 14 条覆盖约 7 天 → 约 2 篇/天，且 100% 过千 |
| 足球隽言 | 4 条/周 → 约 0.6 篇/天 |
| 西甲二人转 | 21 小时前一批 11 条、前天 8 条、3 天前 13 条 → 约 8~14 篇/天（抽奖模式） |
| 我方 10 月 | 成稿 7.8 篇/天，**实际发布 3.9 篇/天**，中位阅读 8 |

**"英超那些事"用 2 篇/天做到中位 5,526。我方用 3.9 篇/天做到中位 8。**

这条直接否掉上一份月度分析里"产能压回 6 篇/天"的思路——**问题从来不是数量，是每一篇的成色**。

### 发现七：视频号打破了这个规律（反过来限制了结论的适用范围）

「足球记忆FM」30.7 万粉，已经全面转视频：80 条里中位播放 **10,008**、98.8% 过千。
但它的**过程锚点覆盖率只有 2.5%**，比西甲二人转（7.2%）还低。

```
足球记忆FM  中位播放 10,008  ←  锚点 2.5%   ← 规律被打破
```

它的高播放内容长这样（标题里没有第几分钟、没有让X追Y）：

```
12万播放 皇马2-1巴萨，穆里尼奥重返国家德比 #国家德比 #皇马 #巴萨
1.6万播放 曾经他是悲情的"凯恩叔叔"，如今他加冕金球先生 #凯恩
```

**结论必须收窄**：过程锚点解释的是**图文推荐池**的行为。视频号靠封面 + 前 3 秒 + 时长留人，标题只是搜索标签。**我们的形态是图文，所以这条规律对我们有效，但不能说成"所有体育内容都适用"。**

顺便一条对选题有用的：视频号靠「国家德比」「金球先生」这种**大事件 + 人物符号**就能起量，不需要过程细节。如果哪天转视频，标题策略要重做，不能直接套图文这套。

## 四、GitHub 上的同类项目：他们已经踩过什么坑


搜到 4 个可直接对照的开源项目。**先说结论：在"事实校验"和"合规闸门"这两块，我们的实现已经领先；在"事件聚合"和"生成后自检"这两块，他们做得比我们细。**

### 1. `iRuperth/SynapseQuill`（F88tball）— 足球比赛视频自动化（LangGraph + 全免费层）

它最值得抄的是 **`agents/guardrail.py`**：

```
guardrail.py  anti-hallucination: facts check + LLM-as-judge,
              regenerate if wrong（校验不通过就重新生成）
```

**设计要点**：事实校验不是"检查完打个标记"，而是**作为生成流程的一个环**——不通过就回炉，而不是降级放行。

我们还差什么：我们的 `compliance_guard` / `fact_card` 是**闸门式**（过了就发，不过就打回 ≤2 次），但没有「**基于失败原因定向重写**」这一环——现在是整篇重写，而不是告诉模型"你上一版把比分写错了，只改这一处"。

### 2. `Adys23/football-news` — AI 新闻编辑室

它的核心流程（波兰语 README 直译）：

> 抓取信源 → **把报道聚合成事件** → 抽取结构化事实 → 验证 → 生成草稿 → 交编辑审核
> 明确原则："不做标题党，不无人审核就发布"

**最值得抄的是「事件聚合」**：多个源报道同一件事时，先聚成 `event`，再从事件生成文章。**而不是像我们这样一条一条选题。**

这正好对应发现四——我们要做到"一个事件 4 个切口"，前提是**先有"事件"这个概念**。我方现在最接近的是 `event_result.py` 的 `event_result_key`（只用于去重），没有事件级的角度池。

它的第二条原则（不无人审核发布）我们不适用——我们的定位就是全自动。但要接受代价：**全自动 = 不能靠人工兜底质量，只能靠闸门**。

### 3. `yAmineee/sports-scribe` — 多智能体体育写作

```
Data Collector → Researcher → Writer → Editor → Fact Checker
```

**Fact Checker 是独立 agent**，不是 Writer 内部的一个函数。这个职责切分比我们干净——我们的 `fact_card` 是数据、`compliance_guard` 是规则，但没有一个"专门挑刺"的角色。

### 4. `Cui-Owen/FootyAutoGen` — 外媒→中文社媒改写

ESPN/Football Italia → DeepSeek 翻译+风格化改写 → 微博/小红书发布。**形态和我们最像**（中文社媒化改写 + 多语言源）。

它 README 里自己写的风险点，逐条对照我们：

| 它列的风险 | 我们是否已解决 |
|---|---|
| 信源网站改版导致爬虫失效 | 部分（有 `source_watch` 巡检，但 10-26 才修过懂球帝被 EdgeOne 拦截的静默失效） |
| LLM 生成内容事实错误/幻觉 | 已解决（`fact_card` + `compliance_guard` + `event_result` 五道闸门，比它严格） |
| 多语种解析难度 | 已解决（`player_names.json` 做翻译映射） |
| 重复发布 | 已解决（`event_result_key` + slug 去重） |

## 五、我们 vs 头部：差距拆解

把差距拆成「可改」和「不可改」两栏，避免把不可改的部分当借口，也避免把不可改的部分当任务：

| 差距项 | 我方 | 头部 | 可改？ | 归属 |
|---|---|---|---|---|
| 疑问句收尾占比 | 85.5% | 13.3% | ✅ 可改 | 提示词 + 闸门 |
| 「过程锚点」覆盖率 | 0/76 | 大量 | ✅ 可改 | 选题 + 提示词 + 事实层 |
| 单事件切口数 | 1 | 15 | ✅ 可改 | 事件聚合 + 生成编排 |
| 时间锚点密度（第N分钟/N轮/N分） | 低 | 高 | ✅ 可改 | 事实层已有进球时间，未用于标题 |
| 账号权重/初始推荐量 | 低 | 高 | ⚠️ 需时间 | 无法直接改，只能靠内容质量累积 |
| 项目流量天花板（足球 < 国乒） | 足球 | 已迁走 | ❌ 不可改 | 接受现实，不为此改赛道 |
| 粉丝基数 | ~0 | 10~23 万 | ⚠️ 结果非原因 | 由单篇质量决定，不能直接追 |

**结论：三个可改项都指向同一个根因——我们的标题在"陈述"而不是在"制造点开理由"。**

## 六、综合改进计划

### P0-1 标题加「过程锚点」硬闸门（本周，最高优先）· ✅ 已落地 2026-11-01

**依据**：发现二 + 发现三。我方 58% 的标题无数字无感叹无情绪（中位 4 阅读），0 篇含过程锚点。

**做什么**：
1. `config/title_antipattern.yaml` 增加规则组 `process_anchor`：
   - 过程锚点词表已落地为 `title_features.PROCESS_ANCHOR_PATTERNS`（13 类，每类标了真实出处）
   - 事实层已有进球明细（`fixture_library` 的 goals 含时间/球员/是否点球），**必须从这里取**，不许模型编
2. **锚点按"加分"处理，不设"必须有"**。原因有两条硬证据：
   - 头部 4.2 万阅读的爆款「主场0-3大败！意甲劲旅彻底拉胯，11战仅2胜，头号球星带头反水！」**没有锚点**（"11战仅2胜"是战绩不是过程）
   - 视频号中位 10,008 播放，锚点覆盖率只有 2.5%
   → 设成硬必要条件会误杀大量合理的战绩型标题
3. 「疑问收尾」从"允许"改为**限额**：任意 14 天内 ≤2 篇（复用 `template_gate.py` 的 14 天窗口机制）
4. 打回策略：标题不过闸门 → **只重写标题**，不重写全文（省额度、提高通过率）

**验收**：
- `scripts/verify_title_anchor.py`（新增）四项硬项：锚点词表非空且自检通过 / 事实层可提供时间锚点 / 近 7 天成稿锚点覆盖率 **≥40%**（目标从 2.6% 提到 40%，对标英超那些事的 35.7%）/ 疑问收尾 14 天内 ≤2 篇
- 负向验证：把一篇标题改成"…他图个啥？"必须 FAIL；把锚点词表清空必须 FAIL
- 单测已落地 30 项（`tests/test_title_features.py` 16 项 + `tests/test_benchmark_peers.py` 14 项），全绿

**预期收益要打折**：西甲二人转内部「数字+感叹」中位 501 vs 该号中位 77，是 6.5 倍；但那是**已经进了推荐池**的样本。我方如果主要问题是"根本没进池"（账号权重低），改标题的收益会远低于 6.5 倍。见第七节局限第 6 条。

## 七、这份对标的局限（必须一起看）

1. **样本 181 条、4 个账号，且是滚动窗口**。够看量级差异，不够做回归。所有"倍数"只是中位数比值，不是统计显著性。
2. **「输家框架」不成立**。全样本「只写输家」中位 480 vs「只写赢家」500，几乎无差；同账号内「我爱英超」是 2.7 倍，「西甲二人转」是 1.0 倍。**所以我把这条从结论里降级成了观察，没写进 P0。**
3. **跨账号比较会骗人**。全样本「含顶流人名」显示 0.32x（负相关），控制账号后变 3.53x（正相关）。这是 Simpson 悖论。**任何"头部都这么做所以我们也做"的结论都不成立**，必须在本号数据上验证。
4. **我方 76 篇样本偏向有 platform_id 的批次**，存在选择偏差（上一份月度分析已标注）。
5. **阅读量口径不同**（主页累计 vs 后台统计窗口），倍数只能当方向。
6. **没有曝光量**，所以无法区分"标题不行"和"根本没进推荐池"。这是最大的盲区——**如果我们的问题主要是"没进推荐池"（账号权重低），那改标题的收益会远低于预期**。

第 6 条是这份计划最大的风险。**所以 P0-1 上线后必须做对照实验**：同一批次的稿子，一半用旧标题、一半用新标题，看 7 天后中位阅读是否真的分开。**如果分不开，说明瓶颈在账号权重而不是标题，那时候就该重新评估整条路。**
